## 零、根因（v1 已核对为行号准确，保留）

长录音必然失败是自放大闭环：转写文本长 → `splitChunks` 固定 3500 字硬切（`Generator.kt:177-213`，零重叠、切在句中）
→ 逐段串行调用且 `callWithRetry` 只认 `"HTTP 5"`（`Generator.kt:215-229`），429 直接抛（`LlmClient.kt:110`）

→ `max_tokens` 从不传（`Generator.kt:222`）、`finish_reason` 从不读（`LlmClient.kt:116-131`）→ 截断/超限 → 整篇 ERROR 且成果不落盘（`Generator.kt:54-57`）。

注意：`HomeScreen` 不会并发触发多篇生成（生成只从 `DetailScreen.kt:245/528` 起），真正的并发风险是**同一笔记上 revise/重新生成与进行中的流水线互相覆盖**（ViewModel 无 Job 管理）。

### T1 弹性 LLM 层（`llm/LlmClient.kt` + 新增 `llm/LlmPolicy.kt`）—— 治 P1/P2/P5/P6/P10
1. **接缝**：`interface Transport { fun post(url:String, headers:Map<String,String>, body:String): RawResp }`，
   `RawResp(code:Int, body:String, headers:Map<String,String>)`。默认 `OkHttpTransport`。单测注入 fake。
2. **错误分级**：`sealed class LlmError`：`RateLimited(code,retryAfterMs?)` / `ServerError` / `Network` / `Timeout` / `BadFormat` / `EmptyContent` / `Truncated`，都带原始 code 与 body 摘要；替换裸 `LlmException`（保留 `LlmException` 作外层兼容）。
3. **进程级节流闸**：`object LlmGate { fun <T> withGate(minIntervalMs, sleeper, block) }`——用进程单例的 `Mutex`/时间戳，**sleep 不持锁**（先取号→释放→delay→再发）；`chat`、`listModels`、设置页"测试连接"三条路径**全部经过同一个闸**。
   同时把 `LlmClient` 提为单例（挂在 `App` 上，`Generator`/`SettingsScreen` 复用），杜绝 `Generator.kt:23` 与 `SettingsScreen.kt:253` 各自 new 导致闸门形同虚设。
4. **退避**：`maxRetries=5`，`1s→2→4→8→16`，封顶 60s，±20% 抖动（抖动幅度由注入的 `rng` 决定，测试里可固定）；
   `Retry-After` 头优先（秒与 HTTP-date 两种），否则从 body 里正则找 `reset|retry_after|wait` 的秒数。只重试 `RateLimited/ServerError/Network/Timeout`；`BadFormat/EmptyContent/Truncated` 走上层降级而非盲重试。
5. **可取消 + 可测**：`interface Sleeper { suspend fun delay(ms:Long) }`（生产用 `kotlinx.coroutines.delay`，测试用记录型 fake）；`interface Clock`。退避期间 `CancellationException` 必须原样抛出。
6. **token 预算**：`estimateTokens(text)` = CJK 字符数 + `ceil(非CJK字符/4)`。预算 = `contextWindow - maxOut - inputReserve`；
   `maxOut` 默认 2048（生成/合并）或 1024（分段提炼）；请求体带上 `max_tokens`，并按你要求把 **system 提示词计入输入预算**。
   `contextWindow`/`minIntervalMs`/`conservative` 存 **DataStore**（`SettingsRepository.kt` 加 3 个键，默认 8192 / 1200ms / false）→ **不动 Room**。
7. **截断检测**：读 `choices[0].finish_reason`，`"length"` → 抛 `Truncated`，上层降级重试一次（提示改为"只输出导图、每节点≤12字、思路≤250字"）。
8. **错误文案**：`LlmError.userText()` 输出自然语言 + 下一步动作，绝不甩 body（body 只在设置页"调试信息"折叠里看）。

**T1 验收（可证伪，`LlmPolicyTest`，`runBlocking` + fake Transport + 记录型 Sleeper，真实 sleep 累计必须 = 0ms）**
- (a) fake 连续 429 两次再成功 → 返回值正确且 `calls == 3`，`sleeper.log == [1000±抖, 2000±抖]`（固定 rng 时精确等于 1000、2000）；
- (b) `Retry-After: 7` → 首次等待 == 7000；
- (c) `finish_reason=length` → 抛 `Truncated`，且上层降级重问恰 1 次；
- (d) content 为空 → `EmptyContent`；HTTP 401 → 不重试（`calls == 1`）；
- (e) `estimateTokens` 对"纯中文/纯英文/中英混排"三例断言在 ±15% 内；
- (f) 两次调用共享同一 `LlmGate` 时，第二次实际发送时刻 ≥ 第一次 + `minIntervalMs`；退避 sleep 期间闸可被另一请求取得（不死锁）；
- (g) `chat` 请求体 JSON 含 `max_tokens`，且 `estimateTokens(system+user) + max_tokens ≤ contextWindow`。

### T2 语义分段（新增 `llm/TextChunker.kt`，替换 `Generator.splitChunks`）—— 治 P3
- 断句：`。！？；!?;` + 换行；贪心装填到 `targetTokens`；**相邻块重叠最后 1 句**（首块不带重叠）；绝不切断句子；保留原始换行。
- 退级：无句末标点 → 按 `，,、` 退级 → 仍无边界 → 按字符硬切并返回 `noBoundary=true`（上层提示"转写缺少标点，分段质量受限"）。
- 收敛：`maxChunks`（默认 12；`conservative` 时 6）；超出则按比例上调 `targetTokens` 重算，保证请求数不失控。
- 纯函数：`data class Chunk(text:String, index:Int, overlap:Int)`；`fun planChunks(text:String, budget:TokenBudget, maxChunks:Int): ChunkPlan`，**零 Android 依赖**。

**T2 验收**（`TextChunkerTest`）：多句中文/中英混排/超长无标点/短文本（1 块）/恰好等于预算/切点恒在句末（断言每块以标点或结尾收束）/块序可还原（去掉重叠后按序拼接 == 原文归一化）/块数 ≤ `maxChunks`/重叠句不重复计入总量/`noBoundary` 标志正确 —— ≥10 例，全部无 Android 类。

### T3 长文流水线（新增 `llm/LongTextPipeline.kt` + `llm/SegmentStore.kt`，重写 `Generator.produceMapAndThinking`）—— 治 P4/P7
- 分段提炼返回**结构化中间结果**（`SegmentOutline(index, title, points:List<String>)`），不是自由文本大纲。
- **递归分组 reduce**：按 `mergeGroupTokens` 预算把相邻段分组（默认每组 ≤4 份大纲），逐组归并为中层大纲，逐层上收，直到落入一次最终生成调用的预算；**任何一次调用的输入都不超预算**。删除 `"——第 i 段——"` 机械拼接与 `mergeSystem` 里内嵌 `generateSystem` 造成的提示词翻倍。
- **零 schema 续跑**：`class SegmentStore(root: java.io.File)` 写 `segments-<noteId>.json`；记录已完成段与其结果；重跑时 `doneIndices()` 命中的段**不再发请求**；文件损坏/半截 JSON → 返回空集且不抛。目录由注入决定（生产 `context.filesDir/pipeline`，测试 `createTempDir`）。**`Entities.kt`/`AppDatabase.kt` 的 `version`、`@Entity`、`exportSchema`、`fallbackToDestructiveMigration` 必须零改动。**
- 单段永久失败 → 记录进 `PipelineResult.failedSegments`，整体仍可 READY，并在笔记上标注"第 X 段未纳入"。
- 真实进度：`onStage` 携带 `done/total`；`Transcriber` 把 `AudioDecode` 的真实进度透传（一行修，见 T4）。
- ViewModel 侧：同一笔记的 `generate/revise` 共用一个 `Job`，新操作先 `cancel` 旧的，避免互相覆盖（`DetailScreen.kt:245/528`）。
- **不做**：音频 VAD 重叠去重、`OfflineRecognizer` 缓存、跨段尾句传递（T2 重叠已覆盖）。

**T3 验收**（`LongTextPipelineTest`，无 Android 类型）：
