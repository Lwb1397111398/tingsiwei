### 第 1 轮必修项（全部已修并有测试）
1. `Retry-After: 0` 会绕过退避 → 退避与 Retry-After 取大；`≤0` 视为未提供。
2. `choice["message"]?.jsonObject` 对畸形响应抛英文异常 → 全部收敛为分级错误；数字型 content 判为 `EmptyContent`。
3. `LlmSession.requests/Recorded` 死代码 + 误导性注释 → 删除。
4. 错误子类里 8 个 `detail` 参数无人使用（且逼着调用点塞 body）→ 删除，响应体一律不进错误信息。
5. 限流文案承诺"正在自动等待"，实际是重试耗尽后才显示 → 改为"已自动重试多次仍未成功 + 怎么办"。
6. 空/非法接口地址绕过分类，英文异常直出界面 → `LlmEndpoint.normalize` 返回空即 `BadUrl`（不可重试）。
7. `TextChunker` 为压段数可以放大到超窗口 → 加 `maxTargetTokens` 硬上限，压不下就宁可多分几段。
8. `SegmentStore` 不失效 → 加 `sha1(内容)+分段参数` 指纹，不符即整体作废。
9. `pickCut` 每个解码缓冲全量重扫（平方级）+ 会切出 10ms 碎块 → 增量扫描 + `min` 下限 + 出块自动复位。
10. AudioDecode 用 `shortBuf.remaining()` 而非 `info.offset/size`（EOS 空包会重发旧样本）→ 修正，并把 PCM 累积/重采样/移位抽成可测的 `PcmBuffer`。
11. 归并两层仍超预算时被下游静默截断 → 流水线自己截并 `finalTrimmed` 上报。
12. 「补全」按钮实际是空操作（retry 只清提示）→ 走真正的断点续跑；同时「让 AI 改」失败不再重跑整篇（省额度），重新生成前自动存版本快照。

### 第 2 轮新增必修项（全部已修）
13. **快速失败在生产路径失效**：`LlmClient` 把 `LlmError` 包成 `LlmException`，导致流水线里 `catch (Reject)` 永远不命中，而测试因为假实现直接抛 `LlmError` 而"假绿" → 客户端不再包错误，测试改走真实 `LlmSession`。
14. 非 `LlmError` 的意外异常漏到界面（英文）→ 传输/解析两处兜底归类。
15. 非法地址被当成可重试的网络错误（白等 31 秒）→ 归为不可重试。
16. 默认值散落 4 处 → 统一 `LlmPolicy.DEFAULT_*`；`setLlmLimits` 输入 clamp。
17. `RateGate.lastSlotMs` 是生产类里的测试专用状态且有可见性问题 → 删除，测试改用可推进时钟断言"第几次请求发生在第几毫秒"。

### 终审采纳的 2 条风险修复
18. 额度型限流下最坏可打到 ~144 次请求才报错 → 连续 3 段提炼失败即收手，并提示可稍后「补全」。
19. 生成进行中打开版本列表并恢复 → 会被在飞的写库覆盖 → `restore()` 加互斥守卫。
