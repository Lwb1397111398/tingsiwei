# 用户实测清单 v1.1.0（本机无法自动验证，需你在手机上确认）

> 这次迭代修的是"长录音 → 接口 429 → 整篇失败"。逻辑层已有 68 个自动化单测覆盖（含注入 429 的端到端用例），
> 但**录音质量、界面手感、真机限流表现**必须你实测。下面每一项请勾一遍；有任何一条不对，把现象告诉我即可。

## A. 本次修复的核心（优先测）

| # | 项目 | 怎么测 | 期望 |
| --- | --- | --- | --- |
| A1 | 长录音不再炸 | 录 40 分钟以上的课（或导入一段长音频），走完转写→生成 | 不出现"接口返回错误（HTTP 429）"直接失败；状态条显示"正在提炼第 x/N 段…"并持续推进 |
| A2 | 限流自动等待 | 用你那个容易限流的渠道跑长录音 | 偶尔慢下来但**不报错**；全过程不需要你手动重试 |
| A3 | 断点续跑 | 生成中途杀掉 APP（或断网）再进来，点"重试/补全" | 从已完成的段继续，不从头再来；速度明显比第一次快 |
| A4 | 失败段提示 | 若某段始终失败 | 导图仍生成，顶部出现一条**灰色提示**（"第 x 段接口没响应成功…"）+「补全」按钮，而不是红色"出错" |
| A5 | 保守模式 | 设置→长录音与限流→打开"保守模式"再跑长录音 | 分段更少、节奏更慢，限流严重的渠道也能过 |
| A6 | 请求间隔/窗口 | 设置里改"请求间隔"和"上下文窗口" | 立即生效，不需要重启；调小窗口后长录音也能成功 |
| A7 | 转写真实进度 | 录音结束后看进度文案 | 显示"已完成 x%，已识别 N 字（第 m 段）"，百分比会动，不是停在 0% |
| A8 | 识别质量 | 同一段长录音，对比升级前后的转写文字 | 句子不被从中间切断（现在按静音点切块），错字/断句不明显变差 |

## C. 我这边已经自动验证过的（不用你重复确认）

- **98 个 JVM 单测全部通过**（原有 14 例一字未改仍通过）：
  - `LlmPolicyTest` 25 例：429 退避序列、`Retry-After`（含 0 秒不得绕过退避）、截断降级只重问一次、401/坏格式不重试、退避不占闸口、节流间隔、并发取号不重复、超大/纯英文/超长 system 输入的预算降级、保守模式、非法地址不重试、错误文案不泄漏 API KEY、地址规范化、**流水线接真实会话层的端到端用例**
  - `TextChunkerTest` 18 例：句末收束、重叠=上一块尾部、去重叠可还原、**每块严格不超预算（含"重叠放不下就放弃重叠"的构造用例）**、块数收敛到上限、无标点退级
  - `LongTextPipelineTest` 14 例：**4 万字 + 持续注入 429 仍能出图**、单段永久失败可跳过、断点只补失败段、内容改写后旧断点整体失效、归并层数 ≤2、不可重试错误连着两段停手 / 偶发一段只跳过那一段、窗口太小直接报错不浪费调用、归并两层仍装不下时如实报告截断
  - `SpeechCutTest` 13 例：静音中点切块、硬上限兜底、不产出碎块、**增量扫描与一次扫描结论一致**、流式排空不丢样不重复
  - `PcmBufferTest` 9 例：16k 直通、44.1k 下采样、8k 上采样、多声道下混、分批取用后长度与幅值正确、**灌 60 秒音频峰值不超过 2 秒（内存有界）**
- `assembleDebug` 出包成功；数据库 schema 未改动（version 仍为 1）。
- 行为变更：**「让 AI 改」失败时不再重跑整篇生成**（原导图保持不动，只清提示）；重新生成前会自动存一份版本快照，手动整理的导图可从时钟图标里回退。

## D. 已知仍需你判断的

- 真实渠道的限流是**外部因素**：如果你的渠道 RPM 极低（如每分钟 1 次），长录音仍可能很慢——把"请求间隔"调到"慢"+开保守模式。
- 识别质量取决于 SenseVoice 模型与录音环境，本次只改了切块边界（更不容易切坏句子），没有换模型。
