# 录音页模块总览

## 模块职责

录音页是 `RecordSession` 进程级单例的一层薄界面：负责麦克风/通知权限申请、开始-暂停-继续-完成-取消五个操作的发起，以及时长与实时识别文字的展示，页面自身不持有任何录音状态。

## 运作流程

**从哪来**：首页 FAB「开始录音」→ `onOpenRecord()` → `AppNav` navigate 到 `record` 路由（`AppNav.kt:24`、`AppNav.kt:29-36`）。

**怎么处理**：
1. 界面用 `viewModel(factory = recordVmFactory)` 拿 `RecordViewModel`（`RecordScreen.kt:56`、`181-184`），VM 的 8 个流全部是 `RecordSession` 单例字段的直接引用（`RecordScreen.kt:192-199`；`RecordSession.kt:28-37`），5 个方法也是纯转发（`RecordScreen.kt:207-211`）。这就是文件头注释说的「录音状态都在进程级 RecordSession 里，ViewModel 只是转发给界面」（`RecordScreen.kt:186-189`）。
2. 点 96dp 大按钮（`RecordScreen.kt:117-142`）：未录音 → 先 `ContextCompat.checkSelfPermission(RECORD_AUDIO)`（`RecordScreen.kt:120-122`），已授权直接 `vm.start()`，未授权拉起 `RequestMultiplePermissions`，Android 13+ 额外要 `POST_NOTIFICATIONS`（`RecordScreen.kt:126-130`、`70-73`）；录音中 → 在 pause / resume 之间切换（`RecordScreen.kt:132`）。
3. `RecordSession.start()` 在 `SupervisorJob + Dispatchers.Default` 的作用域里先占位 `isRecording = true` 防连点，再建 `Recorder` 并 `rec.start()`（`RecordSession.kt:59-70`；`Recorder.kt:32-60`，m4a/AAC 16kHz 单声道 32kbps），随后 `RecordService.start(App.get())` 起前台服务保活（`RecordSession.kt:75`；`RecordService.kt:77-79`），SYSTEM 模式下同时挂上 `SystemSpeechRecognizer`（`RecordSession.kt:76`、`153-158`），并起一个 250ms 的 ticker 把 `durationMs` 刷新出来（`RecordSession.kt:78-83`）。
4. 暂停/继续：`pause()` 调 `Recorder.pause()` 并停掉系统识别（`RecordSession.kt:93-98`）；`resume()` 反向恢复并按模式重启识别（`RecordSession.kt:100-105`）。

**产出什么**：点「完成」→ `RecordSession.stopAndSave()`（`RecordScreen.kt:147`；`RecordSession.kt:107-143`）：`recorder.stop()` 拿到 `(文件, 时长)`（`Recorder.kt:96-113`）→ `finishSession()` 收尾（`RecordSession.kt:160-167`）→ 先抓 `finalText`/`transcribeMode` 快照再在 `Dispatchers.IO` 落库（`RecordSession.kt:121-123`）：SYSTEM 模式且已有识别文字 → `content` 直接可用、`status = DRAFT`；否则 `status = TRANSCRIBING`；`source = RECORD`、标题为「录音 MM-dd HH:mm」（`RecordSession.kt:125-137`）→ `saved.emit(id)`（`RecordSession.kt:138`）。

**影响谁**：`RecordScreen` 的 `LaunchedEffect(Unit) { vm.saved.collect { onSaved(it) } }`（`RecordScreen.kt:66-68`）收到 id 后由 `AppNav` 跳详情并 `popUpTo(HOME)`（`AppNav.kt:31-33`）；详情页 `DetailViewModel.maybeRunPipeline()` 看到 `TRANSCRIBING + audioPath + 空 content` 就自动开跑离线转写（`DetailScreen.kt:479-480`）。点「取消」则 `cancelIfAny()` → `Recorder.cancel()` 删掉文件、不产生任何笔记（`RecordScreen.kt:153`；`RecordSession.kt:145-151`；`Recorder.kt:116-130`）。

## 入口文件清单

- `app/src/main/java/com/tingsiwei/app/ui/RecordScreen.kt` — 212 行 — 本模块唯一文件：`RecordScreen` Composable（`RecordScreen.kt:53-179`）、`recordVmFactory`（`RecordScreen.kt:181-184`）、`RecordViewModel`（`RecordScreen.kt:186-212`，转发层）。录音器本体、前台服务、系统识别分别属于 `record/Recorder.kt`、`record/RecordService.kt`、`transcribe/SystemSpeechRecognizer.kt`，不在本模块内。

## 对外接口 / 被谁调用

- `RecordScreen(onSaved: (Long) -> Unit, onBack: () -> Unit)`（`RecordScreen.kt:55`）：由 `AppNav` 的 `record` 路由挂载（`AppNav.kt:30-35`）。
- `RecordViewModel`（`RecordScreen.kt:190`）对外暴露：状态流 `isRecording / isPaused / durationMs / partialText / finalText / error / transcribeMode / saved`（`RecordScreen.kt:192-199`）+ 行为 `start / pause / resume / stopAndSave / cancelIfAny`（`RecordScreen.kt:207-211`）。构造需要 factory，因为文件里的 `recordVmFactory` 直接 `RecordViewModel() as T`（`RecordScreen.kt:181-184`）。
- `StatusChip` 等首页符号未被本页复用；本页除 `Formatters.duration`（`RecordScreen.kt:98`；`Formatters.kt:9-15`）外没有公共 UI 依赖。
- 第二条入口路径：常驻通知的「完成」action → `RecordService.onStartCommand` 判断 `ACTION_STOP` → `RecordSession.stopAndSave()`（`RecordService.kt:42-45`、`68`）——与页面按钮共用同一个出口，不经过本模块任何代码。

## 关键数据结构

无独立数据结构，复用 `RecordSession` 的一组进程级状态流与 `NoteEntity`：

- 状态流（`RecordSession.kt:28-34`）：`isRecording`、`isPaused`、`durationMs`、`partialText`、`finalText`、`error: String?`、`transcribeMode`，全部 `MutableStateFlow`。
- 一次性事件：`saved = MutableSharedFlow<Long>(extraBufferCapacity = 1)`（`RecordSession.kt:36-37`，注释明写「完成保存后发出新笔记 id（一次性事件）」）。
- 落库字段（`RecordSession.kt:127-136`）：`title`（时间戳模板）、`status`（DRAFT 或 TRANSCRIBING，取决于是否已有系统识别文字）、`source = RECORD`、`audioPath`、`durationMs`、`content`（可空）。
- 本文件自有结构：无。`RecordViewModel` 只是把上述引用换个名字暴露（`RecordScreen.kt:192-199`）。

## 已知坑与约束

1. **索引 README 没有本页面**：README 第 17 行「录音」只指向 `record/Recorder.kt`，`ui/RecordScreen.kt`（212 行）与 `RecordSession`/`RecordService` 都未列入索引；「RecordViewModel 只是展示层」这一层分工只存在于代码注释（`RecordScreen.kt:186-189`）和 `RecordSession.kt:21-25` 的 KDoc 里。
2. **`saved` 无 replay，事件会丢**：`MutableSharedFlow`（`RecordSession.kt:37`）只在有收集者时投递；收集者是 `LaunchedEffect(Unit)` 起的一次订阅（`RecordScreen.kt:66-68`）。若用户已经离开录音页却在通知栏点「完成」（`RecordService.kt:42-45`），笔记照常入库，但不会自动跳详情，需要回首页列表手找。
3. **`error` 是全局单例字段，不是页面临时态**：`RecordViewModel.error` 直指 `RecordSession.error`（`RecordScreen.kt:197`）。「没有麦克风权限，无法录音」这类页面级提示也被写进全局流（`RecordScreen.kt:72`），只有下次 `start()` 开头才清（`RecordSession.kt:60`）→ 重进录音页仍会看到上次的报错。
4. **单个大按钮三态复用**：未录 → start、录制中 → pause、已暂停 → resume（`RecordScreen.kt:118-133`），图标只在「录制中且未暂停」时换成 Pause（`RecordScreen.kt:136-141`）。
5. **暂停在某些机型是假的**：`Recorder.pause()` 捕获异常后「不崩也不改状态，录音和计时照常继续」（`Recorder.kt:62-73` 及其注释），但 `RecordSession.pause()` 无条件把 `isPaused = true`（`RecordSession.kt:93-98`）→ 界面显示已暂停、实际仍在录，且 `resume()` 因为 `paused == false` 直接 return（`Recorder.kt:75-77`）。
6. **取消无二次确认**：`vm.cancelIfAny(); onBack()` 同一行里连做（`RecordScreen.kt:153`），`cancelIfAny` → `recorder.cancel()` → `outFile?.delete()`（`RecordSession.kt:145-151`；`Recorder.kt:116-130`），录音不可找回。
7. **实时文字只在 SYSTEM 模式显示**：`if (mode == TranscribeMode.SYSTEM)`（`RecordScreen.kt:165`），OFFLINE 模式录完前界面只有时长（`RecordScreen.kt:91-113`）；SYSTEM 的展示是 `finalText + "\n" + partialText` 的简单拼接（`RecordScreen.kt:167`），且 `onSegment` 每收到一段就整体覆盖并清空 partial（`RecordSession.kt:45-48`）。
8. **过短录音会静默失败**：`Recorder.stop()` 抛异常时删文件并上抛（`Recorder.kt:96-113`），`stopAndSave` 捕获后置 `error`、调 `finishSession()` 后 return（`RecordSession.kt:112-118`）→ 不产生笔记、不跳转，用户停在原地只看到一行红字（`RecordScreen.kt:159-162`）。
9. **`transcribeMode` 有两条写入源**：VM `init` 里读一次 DataStore（`RecordScreen.kt:201-205`），`RecordSession.start()` 里又读一次（`RecordSession.kt:66`）。以 start 时的值为准，界面上显示的模式可能与实际起的作用不同（若在录音途中去设置页改）。
10. **factory 忽略 `modelClass`**：`recordVmFactory.create` 直接 `RecordViewModel() as T`（`RecordScreen.kt:181-184`），只服务这一个 VM，照抄到多类型场景会 CCE。
11. **界面提示依赖前台服务链路**：「锁屏或离开本页录音都会继续，从通知栏可回到本页或结束录音」（`RecordScreen.kt:106-113`）成立的前提是 `FOREGROUND_SERVICE_MICROPHONE` 权限与服务类型都对上（`AndroidManifest.xml:7`、`33`），通知本身是 `IMPORTANCE_LOW` + `setUsesChronometer` + 「完成」action（`RecordService.kt:27-31`、`59-69`），点通知正文回 `MainActivity`（`RecordService.kt:50-53`）——回到的是起始路由，不是录音页。
12. **`durationMs` 计时口径**：来自 `Recorder.currentDurationMs()`，用 `SystemClock.elapsedRealtime` 扣除暂停累计（`Recorder.kt:88-93`），250ms 轮询刷新（`RecordSession.kt:78-83`），与 `MediaRecorder` 自身无关；落库时长是停止瞬间的快照（`Recorder.kt:97-99`）。
