# 入口与导航模块总览

## 模块职责

负责应用进程与界面的启动骨架：`App` 提供全局数据层单例，`MainActivity` 挂载 Compose，`AppNav` 注册并路由 5 个页面，`Theme.kt` 决定配色，`AndroidManifest.xml` 声明权限、前台服务与 FileProvider。

## 运作流程

**从哪来**：系统按 `AndroidManifest.xml:11` 的 `android:name=".App"` 实例化 `App`，`App.kt:16-19` 在 `onCreate` 里把自己写进 `companion` 的 `instance`；数据库与设置仓库都是 `by lazy`（`App.kt:8-9`），启动瞬间不发生任何磁盘 IO。LAUNCHER 意图（`AndroidManifest.xml:24-27`）拉起 `MainActivity`（`AndroidManifest.xml:20`）。

**怎么处理**：`MainActivity.kt:13` 先 `enableEdgeToEdge()`，再 `setContent { TingsiweiTheme { AppNav() } }`（`MainActivity.kt:14-18`）。`TingsiweiTheme`（`Theme.kt:14-25`）按 `Build.VERSION.SDK_INT >= S` 选动态取色或内置明暗方案（`Theme.kt:19-23`），最后交给 `MaterialTheme`（`Theme.kt:24`）。`AppNav`（`AppNav.kt:18-53`）建一个 `rememberNavController()`（`AppNav.kt:19`），以 `Routes.HOME` 为起点声明 `NavHost`（`AppNav.kt:20`），5 个 `composable` 分支把跳转闭包作为参数注入页面（`AppNav.kt:21-51`）——页面本身不认识 NavController，全部靠回调。`detail/{noteId}` 的参数从字符串解析，失败退化成 `0L`（`AppNav.kt:46`）。

**产出什么**：产出「路由字符串 → 页面 composable」的映射表和两个进程级单例（`App.database`、`App.settings`），不产出任何持久化数据。

**影响谁**：所有页面与 ViewModel 都通过 `App.get()` 拿数据层（`SettingsScreen.kt:296`、`DetailScreen.kt:439-440`、`HomeScreen.kt:253`、`RecordSession.kt:66`、`TextInputScreen.kt:97`），一旦 `App` 没注册或没跑到 `onCreate`，`App.kt:13` 的 `instance!!` 直接 NPE，ViewModel 构造即崩（与索引 README「坑」清单第 2 条一致）。反向引用也有：`RecordService` 的通知点击意图指向 `MainActivity`（`RecordService.kt:14`、`RecordService.kt:50-52`），录音通知的「完成」按钮指向 `.record.RecordService`（`AndroidManifest.xml:30-33`、`RecordService.kt:54-58`）。

### Manifest 三件事逐条

- **权限**（`AndroidManifest.xml:4-8`）：`INTERNET`（LLM 接口与模型下载）、`RECORD_AUDIO`、`FOREGROUND_SERVICE`、`FOREGROUND_SERVICE_MICROPHONE`、`POST_NOTIFICATIONS`。运行时只主动申请两个：录音按钮里申请 `RECORD_AUDIO`，Android 13+ 追加 `POST_NOTIFICATIONS`（`app/src/main/java/com/tingsiwei/app/ui/RecordScreen.kt:120-131`）。另有 `android:usesCleartextTraffic="true"`（`AndroidManifest.xml:16`）放开明文 HTTP，供自建/内网 LLM 地址使用。
- **前台服务**（`AndroidManifest.xml:30-33`）：`.record.RecordService`，`exported="false"`，`foregroundServiceType="microphone"`。`RecordService.kt:35-47` 在 `onStartCommand` 里 `startForeground`，Android 11+ 显式传 `FOREGROUND_SERVICE_TYPE_MICROPHONE`（`RecordService.kt:37-41`），返回 `START_NOT_STICKY`（`RecordService.kt:46`）；启动/停止由 `RecordService.start/stop` 封装（`RecordService.kt:77-83`），调用点在 `RecordSession.kt:75` 与 `RecordSession.kt:166`。
- **FileProvider**（`AndroidManifest.xml:35-43`）：用 androidx 内置 `FileProvider`，authority 为 `${applicationId}.fileprovider`，`exported="false"` + `grantUriPermissions="true"`，路径表 `@xml/file_paths` 只开放 `cache/shared/`（`file_paths.xml:3`）与 `files/exports/`（`file_paths.xml:4`）。唯一使用方是导出模块：`Exporter.kt:73` 以 `"${context.packageName}.fileprovider"` 拼出同一个 authority 分享 Markdown/PNG。

## 依赖的上游模块

本模块是最顶层，没有业务上游依赖；它依赖的是**下游**：

- 数据层：`App.kt:4-5` 直接 import `data.db.AppDatabase` 与 `data.SettingsRepository`。
- UI 五个页面：`AppNav.kt:22,30,38,47,50` 分别调 `HomeScreen`、`RecordScreen`、`TextInputScreen`、`DetailScreen`、`SettingsScreen`。
- 资源：`androidx.compose.material3`、`androidx.navigation:navigation-compose:2.8.5`、`androidx.activity:activity-compose:1.9.3`（`app/build.gradle.kts:51-54`）。
- 其他组件由 Manifest 侧挂：`RecordService`（录音）、`FileProvider`（导出）。

## 关键数据结构

- `object Routes`（`AppNav.kt:8-15`）：`HOME="home"`、`RECORD="record"`、`TEXT_INPUT="textinput"`、`SETTINGS="settings"`、`DETAIL="detail/{noteId}"`（模板）+ `detail(noteId: Long)` 构造器（`AppNav.kt:14`）。模板与实际参数都用字符串，`noteId` 类型是 `Long`，出参时再 `toLongOrNull()`（`AppNav.kt:46`）。
- `App.companion.instance`（`App.kt:12`，可空私有）＋ `get()`（`App.kt:13`，`!!` 断言）：进程内手工单例，没有 DI 框架。
- `TingsiweiTheme(darkTheme, content)`（`Theme.kt:14-17`）：`darkTheme` 默认取 `isSystemInDarkTheme()`。
- 除此之外无独立数据结构——导航状态全部封装在 `rememberNavController()`（`AppNav.kt:19`）内部。

## 已知坑与约束

1. `App.get()` 是 `instance!!`（`App.kt:13`），删掉 Manifest 的 `android:name=".App"`（`AndroidManifest.xml:11`）会在任何 ViewModel 构造时抛 NPE，与索引 README「坑」清单一致。
2. 双主题轨道：Compose 用 `TingsiweiTheme`，窗口层用 `res/values/themes.xml` 里 parent 为 `android:Theme.Material.Light.NoActionBar` 的 `Theme.Tingsiwei`（`AndroidManifest.xml:17`）——它是**固定 Light**，深色模式下冷启动瞬间仍是浅色底。
3. `Theme.kt` 只有 `TingsiweiTheme` 一个文件（`ui/theme/` 目录下无 Color/Type/Shape 定义），`Theme.kt:19-23` 在非 Android 12+ 设备上直接用 Material3 默认 `darkColorScheme()`/`lightColorScheme()`，项目没有自定义色板；minSdk=26（`app/build.gradle.kts:15`）意味着 8.0~11 一律走默认色。
4. `noteId` 解析失败静默降级为 `0L`（`AppNav.kt:46`），`DetailViewModel` 对 `noteId <= 0L` 返回 `flowOf(null)`/`flowOf(emptyList())`（`DetailScreen.kt:443,445`）：页面不崩但呈现空白，没有兜底回首页。
5. `MainActivity` 用 `configChanges` 吞掉旋转/键盘/尺寸变化（`AndroidManifest.xml:23`）以避免重建，窗口输入靠 `windowSoftInputMode="adjustResize"`（`AndroidManifest.xml:22`）；副作用是 Activity 级状态长期存活。
6. 导航里 `popUpTo(Routes.HOME)` 只用在录音/文字保存后的跳详情（`AppNav.kt:32,40`），`RECORD`/`TEXT_INPUT` 自身没有 `launchSingleTop`，重复点击入口理论上可叠栈。
7. `allowBackup="true"`（`AndroidManifest.xml:12`）且未提供 `fullBackupContent`/`dataExtractionRules`（`app/src/main/res/xml/` 下只有 `file_paths.xml`），意味着 DataStore 里的设置项（含 `llm_key`，见数据层模块总览）会被系统自动备份带走。本文档只描述这一事实，不涉及任何取值。
8. `usesCleartextTraffic="true"`（`AndroidManifest.xml:16`）是**应用级**放开明文，不只作用于 LLM 地址，WebView 与模型下载同样受影响（模型下载实际走 https，`app/src/main/java/com/tingsiwei/app/transcribe/ModelManager.kt:19-22`）。
9. `POST_NOTIFICATIONS` 只在点录音按钮时才申请（`RecordScreen.kt:127-128`），没有启动时申请；Android 13+ 用户若不授权，前台服务能起但通知不可见。
10. `FileProvider` 的 authority 在两侧手工拼：Manifest 用 `${applicationId}`（`AndroidManifest.xml:37`），代码用 `context.packageName`（`Exporter.kt:73`）。当前 `namespace` 与 `applicationId` 同为 `com.tingsiwei.app`（`app/build.gradle.kts:10,14`）所以一致；一旦加 `applicationIdSuffix`（如 debug）就会两边不一致导致分享崩溃。
11. **索引 README 与本模块的差异**：README「入口/导航」行（`docs/模块总览/README.md` 第 9 行）位置只写 `MainActivity.kt`、`ui/AppNav.kt`，实际入口还包括 `App.kt`（全局单例，缺了它整包不能用）与 `ui/theme/Theme.kt`；该行说「5 个路由：home / record / textinput / detail/{noteId} / settings」，与 `AppNav.kt:8-15` 完全一致（此条无误）。另一处：README「录音」行（第 17 行）只列 `record/Recorder.kt`，但 Manifest 注册的是 `.record.RecordService`（`AndroidManifest.xml:31`），且录音生命周期实际在 `record/RecordSession.kt`，二者都没进索引。
