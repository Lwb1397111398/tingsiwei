# 导图画布模块总览

## 模块职责

用 WebView 加载本地打包的 mind-elixir v5 页面来渲染/编辑思维导图，并通过 JS↔Kotlin 双向桥与 Room 里的 `mapJson` 同步（`MindMapPanel.kt:75`、`index.html:103`）。

## 运作流程

**从哪来**：`DetailScreen` 的 `MapTab` 把 Room `notes.mapJson`（由 `TreeText.toMapData` 产出，`Generator.kt:70`、`TextInputScreen.kt:136`）作为 `mapJson` 参数传进来（`DetailScreen.kt:273-280`）。`mapJson == null` 时不建 WebView，只显示「生成导图」按钮（`DetailScreen.kt:257-268`）。

**怎么处理（原生侧）**：`AndroidView(factory=…)` 造 `WebView`，开 JS/DOM Storage、关 file/content access，模拟器上加 `LAYER_TYPE_SOFTWARE`，挂 `WebChromeClient`（把 JS console 转成 logcat tag `MindMapJS`，`MindMapPanel.kt:111-116`）与 `WebViewClient`，注册 `AndroidBridge` 接口，再 `loadUrl("file:///android_asset/mindmap/index.html")`（`MindMapPanel.kt:96-136`）。**页面未就绪前 `update` 直接 return**（`MindMapPanel.kt:141`）。

**怎么处理（页面侧）**：`index.html` 引 `<script src="MindElixirFull.iife.js">`（`index.html:45`），取 `MECore.default` 为 `ME`（`index.html:47`），把 html/body/#map 三层高度用 `window.innerHeight` 像素钉死（`index.html:52-64`），`window.appInit(jsonText, darkMode)` 内 `JSON.parse` → `new ME(opts)` → `mind.init(data)`（`index.html:103-143`），并 `bus.addListener('operation', …)` 挂 500ms 防抖回传（`index.html:136-138`）。

**产出什么**：一次编辑操作后 500ms，页面把 `JSON.stringify(mind.getData())` 通过 `AndroidBridge.onMapChanged` 推回（`index.html:86-94`）→ `localJson` 记账 + 回调上层 → `vm.saveMap(it)` 写 Room（`DetailScreen.kt:276`、`DetailScreen.kt:564-572`）。另外可产出 base64 PNG（`index.html:194-208`，当前无人接收，见坑 12）。

**影响谁**：Room → `note` Flow 回灌 → `update` 块判断是否外部变更 → `appSetData` 刷画布（`MindMapPanel.kt:144-153`）；导出模块 `TreeText.fromMapData` 依赖这里存回的数据形状（`Exporter.kt:29`）；TTS/思路页读同一行的 `thinking`。

## 关键数据结构

- `MapBridge(onReadyCb, onMapChangedCb, onLogCb, onPngCb)`（`MindMapPanel.kt:21-26`）：**回调属性一律 `Cb` 后缀**，`@JavascriptInterface` 方法与之同名不同体。
- `MapController(webView)`（`:49`）：无状态薄壳，每次调用现造；`DetailScreen` 用 `remember { mutableStateOf<MapController?>(null) }` 持有首次回调给的那一个（`DetailScreen.kt:270`、`MindMapPanel.kt:149`）。
- 面板内的 5 个记忆状态（`:89-94`）：`pageLoaded`、`localJson`（最近一次本地产出的数据，防回环用）、`initedJson`（已推给画布的数据）、`lastEditable`、`lastDark`（后两个初值 `null` → 首帧必定各发一次）。
- 页内全局（`index.html:48-50`）：`mind` 实例、`dark` 布尔、`saveTimer` 防抖句柄。
- `mind.getData()` 的返回形状：`{ nodeData, arrows, summaries, direction, theme, compact, meta }`（`MindElixirFull.iife.js:11` 的 `si`），经 `JSON.stringify` 落库——**比 `TreeText.toMapData` 的初始产物多出 `theme` 等字段**（`MindElixirFull.iife.js:11`，序列化时剔除 `parent` 循环引用）。
- 手势状态机 `ptState`：`Idle/Pinch/DragWait/Drag/Pan/BoxSelect`（`MindElixirFull.iife.js:11`，双击阈值 300ms），仅在 `overflowHidden === false` 时注册（`MindElixirFull.iife.js:16`）。

## 已知坑与约束

**桥与初始化**

1. `MapBridge` 的方法名不能与属性同名，否则 `fun onReady() { onReady() }` 无限递归栈溢出——属性统一 `Cb` 后缀（`MindMapPanel.kt:21-30`；索引 README:48 的实测教训）。
2. **初始化不用 JS→原生的 ready 信号**：`AndroidBridge.onReady()` 只在 `load` 后 50ms 打个 log（`index.html:228-232` + `MindMapPanel.kt:125`），真正的门闩是 `WebViewClient.onPageFinished` 置 `pageLoaded=true`（`MindMapPanel.kt:117-121`，主线程回调，写 Compose state 触发重组）→ `update` 块才允许下发 `appInit`（`MindMapPanel.kt:141-150`）。原因：页面加载完成前 `evaluateJavascript` 调不到 `window.appInit`，而等 JS 回报又会出现「先有蛋还是先有鸡」的死锁（索引 README:49）。
3. `onMapChangedCb` 由 `@JavascriptInterface` 在 WebView 的 JavaBridge 线程回调，代码里**没有切主线程**就直接写 `localJson` 并转 `saveMap`（`MindMapPanel.kt:126-129`）；`saveMap` 自身走 `Dispatchers.IO`（`DetailScreen.kt:566`）故写库安全，Compose 状态跨线程写属未实测的潜在风险（见「疑点」）。
4. `allowFileAccess=false`、`allowContentAccess=false` 下仍用 `file:///android_asset/...` 加载（`MindMapPanel.kt:103-104,134`），实测可用；但改 URL 方案时要记得这条。

**防回环与写库**

5. 回推条件：`isInit || (localJson != null && mapJson != localJson && mapJson != initedJson)`，命中后同步 `initedJson`/`localJson`（`MindMapPanel.kt:144-146`）。自己拖动产生的数据永远先落进 `localJson`，所以不会被回推（索引 README:31 的第 4 条设计决策）。
6. 第二重保险：`appSetData` 走 `mind.refresh`，而 `refresh` **不 `fire('operation')`**（`MindElixirFull.iife.js:11` 的 `Li`；防抖只挂在 `'operation'` 上，`index.html:137`）→ 外部刷新不会再回声一次 `onMapChanged`。
7. `saveMap` 只在 `status == READY` 且内容变化时写库（`DetailScreen.kt:568`）；非 READY 态（AI 正在生成）拖动不会落库，于是 `localJson` 与库值分叉，一旦外部 `mapJson` 变化就会被 `setData` 覆盖掉本地编辑（`MindMapPanel.kt:151-153`）。可编辑性也由 READY 决定（`DetailScreen.kt:275`）。
8. **撤销/重做不落库**：`undo`/`redo` 内部是 `refresh(快照)`（`MindElixirFull.iife.js:15` 的 `Re`），不触发 `'operation'` → 不 `onMapChanged` → 不写 Room。撤销后必须再随便编辑一次才会保存，否则杀进程即丢（`index.html:137,174-175`）。
9. `index.html:131-132` 手工 `mind.install(ME.nodeDraggable)` / `install(ME.operationHistory)`，但核心在 `init()` 里已经自动装过（`MindElixirFull.iife.js:16` 的 init；上游 `src/methods.ts:98-102`）：`nodeDraggable` 在 v5.15.1 已是**空实现**（`MindElixirFull.iife.js:1` 的 `function Oe(e){return()=>{}}`；上游 `src/plugin/nodeDraggable.ts:330-334` 注释「拖拽已改由 mouse.ts 的指针事件处理，保留仅为兼容」，实际拖拽逻辑在 `MindElixirFull.iife.js:11` 的 `qe/Tt/St/Ze`），而 `operationHistory` 因此被装了两份（各自监听 `'operation'`、各自 `getData()`，最后安装的才是生效的那份）。两次 `install` 属冗余，且都被 `destroy()` 回收（`index.html:106`、`MindElixirFull.iife.js:16`）。

**渲染与手势**

10. 高度链：WebView 上 `body{height:100%}` 百分比链可能失效（html 正常、body 为 0，且 `overflow:hidden` 会把 `#map` 全裁成空白），所以 CSS 里 `html,body{height:100%}` 只是兜底（`index.html:9-10`），真正靠 JS `fixSize()` 用 `window.innerHeight/innerWidth` 像素钉死 html/body/#map 三层，并监听 `resize`（`index.html:52-64`；索引 README:50）。
11. `overflowHidden` 必须保持默认 `false`：该构建只在 `overflowHidden===false` 时注册指针手势（双指捏合缩放、单指平移、拖节点、框选），传 `true` 会导致导图完全不能缩放拖动（`index.html:120-122` 的原注 + `MindElixirFull.iife.js:16` 的 `this.overflowHidden?…:this.disposable.push(Gt(this))`）。
12. 缩放上下限被显式放宽：opts `scaleMax:3 / scaleMin:0.15 / scaleSensitivity:0.2`（`index.html:125-127`）覆盖库默认 `1.4/0.2/0.1`（`MindElixirFull.iife.js:16` 构造函数）。但 `scale()` 是「同向越界才拦」的软夹紧（`MindElixirFull.iife.js:11` 的 `gi`），而 `scaleFit()` 直接写 `scaleVal` 不查下限（`:11` 的 `bi`）→ 点「适应」可以把图缩到 `0.15` 以下。原生侧只暴露 `toCenter`，缩放/平移/增删改全在页内工具栏（`index.html:176-192`、`DetailScreen.kt:282-287`）。
13. 暗色切换：`darkTheme` 参数默认 `isSystemInDarkTheme()`（`MindMapPanel.kt:82`），只有变化才下发（`:159-162`）；页内 `applyDark` 用 `mind.changeTheme(dark?ME.DARK_THEME:ME.THEME, true)`（`index.html:96-101`），第二参 `true` 会顺带 `refresh()` 重排（`MindElixirFull.iife.js:15` 的 `En`）。连锁坑：`getData()` 会把整个 `theme` 对象写进 `mapJson`（`MindElixirFull.iife.js:11`），而 `init` 用 `data.theme` 覆盖 opts 主题（`MindElixirFull.iife.js:16`；上游 `src/methods.ts:83`），页面只在 `dark` 为真时 `applyDark()`（`index.html:135`）——亮色态下靠同一帧 `update` 里紧随其后的 `appSetDark(false)` 纠偏（`MindMapPanel.kt:149-162`，`lastDark` 初值 `null` 保证首帧必发一次），改动这段顺序会让暗/亮主题错乱。
14. 导出 PNG 链路（通但休眠）：`MapController.exportPng()`（`MindMapPanel.kt:62`）→ `appExportPng`（`index.html:194-208`）→ `mind.exportPng()`（内部 `exportSvg` → `Image` → `canvas.toBlob`，`MindElixirFull.iife.js:16` 的 `Po`，声明在 `:15`）→ `FileReader.readAsDataURL` → 剥 `base64,` 前缀 → `AndroidBridge.onPngReady`。但**全仓没有任何 Kotlin 调用 `exportPng()`**（仅定义处 `MindMapPanel.kt:62`），页内工具栏也没有导出按钮，且 `onPngCb` 未传（`:124-131` + 默认值 `:25`）→ base64 落地即丢；`Exporter.savePng` 已备好落盘（`Exporter.kt:66-70`）却无人调用。索引 README:24 只写「Markdown + FileProvider 分享」，与实况一致。
15. WebView 销毁：`onRelease { it.destroy() }`（`MindMapPanel.kt:137-139`）；`DetailScreen` 因此把导图层**常驻组合**、其他两个 tab 用不透明背景盖在上面，避免切页销毁重建丢缩放/平移位置（`DetailScreen.kt:187-203`）。
16. 模拟器（swiftshader 软件渲染）下硬件合成丢内容 → 命中 `FINGERPRINT~generic`/`PRODUCT~sdk_gphone`/`MODEL~Emulator` 时 `setLayerType(LAYER_TYPE_SOFTWARE)`，真机保持硬件加速（`MindMapPanel.kt:105-109`；索引 README:52）。背景色用 `android.graphics.Color.WHITE`（`MindMapPanel.kt:110`），与 Compose `Color` 类型不同（索引 README:57），而页面 CSS 是 `background:transparent`（`index.html:9`）→ 实际底色由 WebView 决定。
17. CSS 必须用 esbuild `--minify --target=chrome80` 处理后**内联**进 `index.html:6`（源码含 CSS 嵌套，旧 WebView 整块丢弃会让节点变透明背景+白字隐形；索引 README:51）。
18. `addChild` 无选中节点时不会默认用根，需手动兜底 `document.querySelector('#map me-root me-tpc')`（`index.html:162-168`；索引 README:53），因为 v5 用自定义元素 `<me-tpc>` 等。
19. 回传数据自带 `theme/arrows/summaries/meta`（`MindElixirFull.iife.js:11`）：首次任何一次操作就会把库里那份「精简 JSON」换成全量 JSON，`notes.mapJson` 随之变大；`TreeText.fromMapData` 靠 `ignoreUnknownKeys` 只取 `nodeData`（`TreeText.kt:25,102-103`）所以仍兼容，但别拿 `mapJson.length` 估节点数。
20. 页内 JS 的 console 全部转 logcat tag `MindMapJS`（`MindMapPanel.kt:111-116`），`appInit` 的 `init result: …`/异常栈也走 console（`index.html:134,141`）→ 排障先看这两个 tag。

**与索引 README 不一致的点**

21. README:29 说打包产物是 `MindElixirFull.iife.js/.css` 两个文件，**实际 `app/src/main/assets/mindmap/` 下只有 `MindElixirFull.iife.js` 与 `index.html`，没有 `.css`**——CSS 已按 README:51 的做法内联进 `index.html:6`。
22. README:16 把桥描述成「`onMapChanged`(500ms 防抖) 回传数据、`appInit/appSetData/appSetDark/appExportPng` 等」——方向与实现一致，但漏了 `appSetEditable`（`MindMapPanel.kt:58` ↔ `index.html:155`）以及 `onLog`/`onPngReady` 两个 JS→Kotlin 方法（`MindMapPanel.kt:37-45`），并且 `appExportPng` 在原生侧其实无人调用（坑 14）。
23. README:16 说打包「含 nodeDraggable/operationHistory/contextMenu 插件」——三个都在包里（`MindElixirFull.iife.js:16` 的 `z.nodeDraggable/z.operationHistory/z.contextMenu`），但 `nodeDraggable` 在 v5.15.1 是空壳（坑 9），真正管拖拽的是核心 `mouse.ts` 的指针事件；README 的说法容易让人误以为「拖拽靠 install」。
