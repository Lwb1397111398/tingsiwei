# 转写模式选择模块总览

## 模块职责

一个全局二选一开关 `TranscribeMode`（`OFFLINE` / `SYSTEM`），决定录音的文字是靠"手机自带识别边录边转"还是"录完后用内置离线模型转写"。

## 运作流程

**从哪来（用户在哪切）**：设置页 →「语音转文字」卡片里的两个 `RadioButton`（`ui/SettingsScreen.kt:166-179`，"离线模型（推荐，免费、录音完转写）"与"手机自带识别（边录边转，各手机效果不一）"）→ `SettingsViewModel.setMode(mode)`（`ui/SettingsScreen.kt:386-389`）→ `SettingsRepository.setTranscribeMode`（`data/SettingsRepository.kt:85-87`）→ DataStore 键 `transcribe_mode`（`data/SettingsRepository.kt:45`）。除设置页外没有第二个入口（首页/录音页只读不写）。

**怎么处理（读取与快照）**：`AppSettings.transcribeMode` 随 `settings` 流读出，缺省 `OFFLINE`（`data/SettingsRepository.kt:28`、`:58`）。只有两个时点会读它：① `RecordSession.start()` 里读一次并缓存进 `RecordSession.transcribeMode`（`record/RecordSession.kt:66`）；② 录音页 `RecordViewModel.init` 读一次用于显示（`ui/RecordScreen.kt:201-205`）。

**分流在哪一行**（结论：**不在 `Transcriber.kt`**，那里没有模式分支）：
- `record/RecordSession.kt:76` —— 开录时 `if (transcribeMode.value == TranscribeMode.SYSTEM) startRecognition()`，SYSTEM 才边录边转。
- `record/RecordSession.kt:103` —— `resume()` 时同样按 SYSTEM 重启识别会话。
- `record/RecordSession.kt:125` —— 保存时 `val content = if (mode == TranscribeMode.SYSTEM && systemText.isNotBlank()) systemText else null`，紧接着 `:131` 据此决定 `status = DRAFT`（有文字，直接进生成）或 `TRANSCRIBING`（没文字）。
- OFFLINE 一侧是**隐式回落**：`status = TRANSCRIBING` 的笔记进详情页即自动调 `transcribe()`（`ui/DetailScreen.kt:479` → `:511-537`），其中 `Transcriber.transcribeOffline(...)` 在 `ui/DetailScreen.kt:518`，全程不再看模式。

**影响谁**：录音页文案与是否显示实时字幕（`ui/RecordScreen.kt:102`、`:165-176`）、是否创建 `SystemSpeechRecognizer`（`record/RecordSession.kt:153-158`）、笔记落库的 `content`/`status`（`record/RecordSession.kt:125-136`）、是否触发模型下载需求（`OFFLINE` 需模型就绪，`transcribe/Transcriber.kt:21-23`）、下游 LLM 生成入口（`ui/DetailScreen.kt:481-482`）。

## 对外接口 / 被谁调用

- `TranscribeMode.OFFLINE = "offline"`、`TranscribeMode.SYSTEM = "system"`（`data/SettingsRepository.kt:19-22`）——纯常量容器，无函数、无校验、无解析辅助。
- `AppSettings.transcribeMode: String`（`data/SettingsRepository.kt:28`）与 `SettingsRepository.setTranscribeMode(mode: String)`（`:85-87`）。
- `RecordSession.transcribeMode: MutableStateFlow<String>`（`record/RecordSession.kt:34`）——进程内的"本次录音按哪种模式"快照，UI 直接读它。
- 全仓引用点（grep `TranscribeMode` 的完整结果，无遗漏）：`data/SettingsRepository.kt:19/58/85`、`record/RecordSession.kt:4/34/76/103/125`、`ui/RecordScreen.kt:48/102/165`、`ui/SettingsScreen.kt:51/168/169/175/176/304/388`。`transcribe/` 包与 `llm/` 包一次都不引用它。

## 关键数据结构

- 定义形态：`object TranscribeMode { const val OFFLINE = "offline"; const val SYSTEM = "system" }`（`data/SettingsRepository.kt:19-22`）——**不是 `enum class`**，是字符串常量组；比较一律用 `==`。
- 持久化：DataStore preferences 键名 `"transcribe_mode"`，值是原始字符串，写入不做白名单校验（`data/SettingsRepository.kt:45`、`:85-87`）。
- 默认值：`TranscribeMode.OFFLINE`，三处独立写死——读设置时的兜底（`data/SettingsRepository.kt:58`）、`RecordSession.transcribeMode` 初值（`record/RecordSession.kt:34`）、`SettingsViewModel.transcribeMode` 初值（`ui/SettingsScreen.kt:304`）。
- 与笔记状态的耦合：`content != null → NoteStatus.DRAFT`，否则 `NoteStatus.TRANSCRIBING`（`record/RecordSession.kt:131`；状态常量见 `data/db/Entities.kt:9-15`）。
- 语义分工：`OFFLINE` = 录完再转、需要模型文件；`SYSTEM` = 边录边转、依赖厂商识别服务（注释 `data/SettingsRepository.kt:20-21`）。

## 已知坑与约束

- **索引 README 的说法与代码不符**：README 模块索引第 22 行写「文字转写（**备用**） | 设置里切换 `TranscribeMode` | OFFLINE / SYSTEM 双模式」。① OFFLINE 不是"备用"，它是**默认模式**（`data/SettingsRepository.kt:58`、`record/RecordSession.kt:34`），UI 文案也标"推荐"（`ui/SettingsScreen.kt:171`）；② 该行"位置"列没给文件，实际定义在 `app/src/main/java/com/tingsiwei/app/data/SettingsRepository.kt:19-22`（不在 `transcribe/` 包里，容易找不到）；③ 这一行还写在小节"文字转写"下，容易误以为存在一个文字转写模块，实际没有独立文件。
- **分流点不在转写门面**：`transcribe/Transcriber.kt` 只有 `transcribeOffline` 一条路（`:16-52`），没有 `if (mode)`；真正的分叉在 `record/RecordSession.kt:76`、`:103`、`:125` 三行，加上 `ui/DetailScreen.kt:479` 的隐式回落。想加第三种模式必须同时动这 4 处 + 3 处 UI。
- **录音途中改设置对本次无效**：模式在 `start()` 时快照（`record/RecordSession.kt:66`），正在录的这一段不会切换识别方式；但录音页文案读的是同一个快照（`ui/RecordScreen.kt:102`），而设置页的 `transcribeMode` 是另一份状态（`ui/SettingsScreen.kt:304`）——两份状态在用户切页后可能显示不一致。
- **字符串无校验，未知值退化成 OFFLINE**：`setTranscribeMode` 不校验入参（`data/SettingsRepository.kt:85-87`），任何脏值都会使 `== TranscribeMode.SYSTEM` 为 false（`record/RecordSession.kt:76`、`:125`）从而按离线走，且没有任何日志。
- **两条链路可能同时不可用**：`SYSTEM` 模式下一句话都没识别出来 → `content = null`、`status = TRANSCRIBING`（`record/RecordSession.kt:125-131`）→ 详情页仍会去跑离线转写（`ui/DetailScreen.kt:479`、`:518`），此时若模型没下载就直接报"离线识别模型还没下载，请到设置页下载"（`transcribe/Transcriber.kt:21-23`），用户会以为"我明明选了手机识别"。
- **模式不随笔记记录**：`NoteEntity` 没有存转写方式的字段（`data/db/Entities.kt:25-43`）→ 事后无法区分某条正文来自系统识别还是离线模型；详情页"重试"也是按 `content` 是否为空来决定重跑转写还是生成（`ui/DetailScreen.kt:505`），同样不看模式，所以**改了模式不会让已有笔记重新转写**。
- **`SYSTEM` 不额外省空间**：两种模式都会保留 m4a 并写 `audioPath`（`record/RecordSession.kt:133`），系统识别只是少了后处理，不减少磁盘占用。
