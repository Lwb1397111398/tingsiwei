# 文字录入页模块总览

## 模块职责

文字录入页让用户不录音也能建笔记：粘贴学习内容交给 AI 生成导图与思路，或直接把电脑上整理好的 TAB 缩进导图粘贴进来、跳过 LLM 立刻得到可拖拽的导图。

## 运作流程

**从哪来**：首页 FAB 菜单第三项「输入文字 / 粘贴导图」→ `onOpenTextInput()` → `AppNav` navigate 到 `textinput`（`AppNav.kt:25`、`AppNav.kt:37-44`）；用户填两个输入框：标题（可留空，`TextInputScreen.kt:62-68`）与正文（`TextInputScreen.kt:70-76`）。

**怎么处理**：两条互斥的提交路径，都跑在 `rememberCoroutineScope()` + `Dispatchers.IO` 里（`TextInputScreen.kt:47`、`92`、`133`）。
- 路径 A「生成导图 + 思路」（`TextInputScreen.kt:83-117`）：只校验 `content.isBlank()`（`TextInputScreen.kt:86-89`）→ 标题留空时取正文首行前 20 字（`TextInputScreen.kt:94-96`）→ 插一条 `status = DRAFT`、`source = TEXT`、`content = 原文` 的笔记（`TextInputScreen.kt:97-106`）。
- 路径 B「导入为导图」（`TextInputScreen.kt:119-159`）：先 `TreeText.parse(content)` 做格式校验（`TextInputScreen.kt:126-130`），解析不出树就报「没有解析到有效内容」；标题留空时取首棵树 topic 前 30 字（`TextInputScreen.kt:135`）→ `TreeText.toMapData(forest, t)` 得到 `(mapJson, virtualRoot)`（`TextInputScreen.kt:136`；`TreeText.kt:83-98`，多棵顶层树会包虚拟根）→ 插一条 **直接 `status = READY`** 的笔记，带上 `mapJson` 与 `virtualRoot`（`TextInputScreen.kt:137-148`）。

**产出什么**：一条 `notes` 记录 + 新行 id；成功即 `withContext(Dispatchers.Main) { onSaved(id) }`（`TextInputScreen.kt:107`、`149`），失败回到主线程写 `error` 并复位 `submitting`（`TextInputScreen.kt:108-113`、`150-155`）。

**影响谁**：`AppNav` 收到 `onSaved` 后 `navigate("detail/$id") { popUpTo(HOME) }`（`AppNav.kt:39-41`），录音页被留在栈外。路径 A 进详情后由 `DetailViewModel.maybeRunPipeline()` 的 `DRAFT` 分支自动开跑生成（`DetailScreen.kt:481-482`）；路径 B 进详情即 `READY`，画布可拖拽（`DetailScreen.kt:276`）、AI 建议按钮可用（`DetailScreen.kt:233`），全程不产生 LLM 调用。

## 入口文件清单

- `app/src/main/java/com/tingsiwei/app/ui/TextInputScreen.kt` — 169 行 — 整个模块只有一个 Composable `TextInputScreen(onSaved, onBack)`（`TextInputScreen.kt:40-169`），内含两个按钮的完整校验与落库逻辑，**没有 ViewModel**。本模块仅此一个文件。

## 对外接口 / 被谁调用

- 唯一对外符号：`fun TextInputScreen(onSaved: (Long) -> Unit, onBack: () -> Unit)`（`TextInputScreen.kt:42`）。
- 被谁调用：`AppNav` 的 `textinput` 路由（`AppNav.kt:38`），`onSaved` → 详情页、`onBack` → `popBackStack()`（`AppNav.kt:42`）。
- 对上游的写接口：`App.get().database.noteDao().insert(NoteEntity(...))`（`TextInputScreen.kt:97`、`137`）——本页面直接触达数据层，不经过任何仓库/服务层。
- 没有暴露任何状态流、没有事件总线、没有对外回调注册点。

## 依赖的上游模块

- 导图格式引擎：`TreeText.parse`（`TextInputScreen.kt:126`；`TreeText.kt:28-49`，TAB 优先、纯空格按每 4 个算一层）、`TreeText.toMapData`（`TextInputScreen.kt:136`；`TreeText.kt:83-98`）。这是本页最实的依赖，「用户粘贴的文本」和「LLM 输出的文本」走的是同一个解析器（对应 README 关键设计决策 1，README 第 28 行）。
- 数据层：`App` 单例 + `noteDao().insert`（`TextInputScreen.kt:32`、`97`、`137`；`AppDatabase.kt:29-30`，`OnConflictStrategy.REPLACE`）。
- 实体：`NoteEntity` / `NoteStatus` / `NoteSource`（`TextInputScreen.kt:33-35`；`Entities.kt:9-22`、`24-43`）。
- 协程：`Dispatchers.IO` + `withContext(Dispatchers.Main)`（`TextInputScreen.kt:37`、`92`、`107`），未引入 `viewModelScope`。
- 导航：`AppNav.kt`（回调上抛，`AppNav.kt:37-44`）。
- 不依赖：LLM 客户端、提示词、生成流水线、录音/转写模块（本页一行都不碰）。

## 关键数据结构

无独立数据结构，复用 `NoteEntity`（`Entities.kt:24-43`）。两条路径写入的字段集合不同：

| 字段 | 路径 A 生成（`TextInputScreen.kt:97-106`） | 路径 B 导入（`TextInputScreen.kt:137-148`） |
| --- | --- | --- |
| `title` | 用户输入或首行前 20 字 | 用户输入或首棵树 topic 前 30 字 |
| `status` | `DRAFT` | `READY` |
| `source` | `TEXT` | `TEXT` |
| `content` | 原文 | 原文（同一段粘贴文本） |
| `mapJson` / `virtualRoot` | 不写（留 null / false） | `toMapData` 的返回值 |
| `audioPath` / `durationMs` | 不写 | 不写 |

页内 UI 状态是 4 个 `remember`：`title`、`content`、`error: String?`、`submitting: Boolean`（`TextInputScreen.kt:43-46`）。

## 已知坑与约束

1. **索引 README 无本模块条目**：README 第 22 行有一条「文字转写（备用） | 设置里切换 `TranscribeMode` | OFFLINE / SYSTEM 双模式」——那说的是语音转写的实现方式切换，跟本页（手动录入文字/粘贴导图）不是一回事；本页在索引里完全不存在，`ui/` 下的界面文件只有 `ui/AppNav.kt` 被列进 README 第 9 行。
2. **没有 ViewModel，落库写在 Composable 里**：`scope.launch(Dispatchers.IO)`（`TextInputScreen.kt:92`、`133`）用的是 `rememberCoroutineScope()`（`TextInputScreen.kt:47`），绑定组合生命周期。落库途中用户按返回，协程随组合取消 → 笔记可能不落地（或只写了一半前置校验），页面也没有 `onCleared` 兜底。
3. **`submitting` 是共享闸门**：两个按钮共用同一个 `submitting` 且都用 `enabled = !submitting`（`TextInputScreen.kt:116`、`158`），一条路径在飞会连带禁掉另一条；成功路径不复位标志（直接导航走了，`TextInputScreen.kt:107`、`149`），只有异常分支复位（`TextInputScreen.kt:111`、`153`）。
4. **路径 B 跳过 LLM 也跳过版本快照**：直接写 `status = READY`（`TextInputScreen.kt:142`），而 `versions` 表只在 `Generator.generate`/`revise` 覆盖前和 `restoreVersion` 回退前写入（`Generator.kt:59-69`、`96-104`、`151-161`）→ 粘贴导入的初版导图没有对应快照，除非之后跑过一次 AI 操作，否则时钟抽屉里是空的（`DetailScreen.kt:396-397` 的空态文案正是这个情形）。
5. **`toMapData` 会抛**：空 forest 触发 `require(forest.isNotEmpty()) { "空导图" }`（`TreeText.kt:84`）。现在被 `TextInputScreen.kt:127-130` 提前挡住，删掉那段校验就会变成运行时异常。
6. **同一段文本两条路径的默认标题不同**：A 取 `content.trim().lines().firstOrNull()?.take(20)`（`TextInputScreen.kt:95`），B 取 `forest.first().topic.take(30)`（`TextInputScreen.kt:135`）。因为 `parse` 会剥掉 markdown 记号（`TreeText.kt:52-65`），标题可能和粘贴的第一行不完全一致。
7. **「导入为导图」对普通散文不设防**：只要求 `parse` 出至少一棵树（`TextInputScreen.kt:126-130`）。没有缩进的整段文字会被解析成一堆 depth=0 的顶层节点（`TreeText.kt:36-40`），`toMapData` 于是包虚拟根、把笔记标题塞成根节点（`TreeText.kt:85-89`），层级完全不对但界面不报错。
8. **正文框高度写死**：`Modifier.fillMaxWidth().height(320.dp)`（`TextInputScreen.kt:74`），外层 Column 又整体 `verticalScroll`（`TextInputScreen.kt:60`）。长文本没有行号/无自适应，软键盘弹起依赖 `windowSoftInputMode="adjustResize"`（`AndroidManifest.xml:22`）。
9. **`error` 不会在成功后清空**：只在每次点击开头 `error = null`（`TextInputScreen.kt:85`、`121`）与失败时赋值；离开页面再进来才会重置（`remember`）。
10. **两条路径的提示语不同**：A 是「请先输入内容」（`TextInputScreen.kt:87`），B 是「请先粘贴导图文本」（`TextInputScreen.kt:123`），别当成同一条。
11. **`insert` 冲突策略是 REPLACE**（`AppDatabase.kt:29-30`）：本页传入的 `NoteEntity` 未带 id（默认 0，`Entities.kt:26`）走自增，正常不冲突；但这也意味着本页面若被误改成带 id 复用对象写库，会静默覆盖既有行。
12. **说明文案与行为一致**：页面底部「导入为导图会把文本按 TAB 缩进层级直接变成可拖拽的导图，之后可以在导图页让 AI 修改拓展」（`TextInputScreen.kt:162-166`）—— 与 `DetailScreen.kt:276`（`editable = status == READY`）、`DetailScreen.kt:553-562`（`sendSuggestion`）的实际行为相符。
