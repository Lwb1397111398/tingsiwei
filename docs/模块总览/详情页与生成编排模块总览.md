# 详情页与生成编排模块总览

## 模块职责

详情页是单条笔记的唯一工作台（导图 / 原文 / 思路三页 + 版本回退 + 播放 + 朗读 + 分享 + AI 修改）。v1.5.0 起，转写/生成/改写的**真正执行**已从本页挪进 App 级宿主 `pipeline/NoteProcessor`（离开页面、退到后台都不中断，见「笔记处理宿主模块总览.md」）；本模块负责三件事：把界面按钮**接线**到宿主与生成器、把宿主的阶段进度**渲染**成状态条与首页角标、以及宿主管不到的部分（播放、朗读、分享、版本恢复界面）在本页兜底。

## 运作流程

**从哪来**：路由 `detail/{noteId}`（`Routes.DETAIL`，`ui/AppNav.kt:13`；带参构造 `Routes.detail(noteId)`，`:14`）。四条路汇到这里：首页卡片点击（`AppNav.kt:23` 的 `onOpenNote` 回调）、录音保存后跳转（`AppNav.kt:32`，`popUpTo(HOME)` 清栈）、文字录入保存后跳转（`AppNav.kt:40`）、音频导入后进列表再手点（`HomeScreen.kt:316-331` 导入落库，`:324` 置 `TRANSCRIBING`）。

**怎么装配**：`DetailScreen(noteId, onBack)`（`ui/DetailScreen.kt:89`，本文件 665 行、UI 与 ViewModel 同文件）里 `viewModel(key = "note$noteId", factory = detailVmFactory(noteId))`（`:90`）——`key` 保证每条笔记一个实例，`detailVmFactory`（`:444-447`）是为了把 `noteId` 灌进构造函数。状态源是 Room 的两条 Flow：`noteDao().observeById`（`:454-455`，`noteId <= 0L` 时短路 `flowOf(null)`）与 `versionDao().observeForNote`（`:456-457`），`collectAsState` 后驱动整个界面重渲染。

**状态条怎么渲染（:133-188）**：顶部一条 `when(note.status)`——`TRANSCRIBING/GENERATING` 显示进度文案（`:138-146`，文案来自 `busyStage`）；`ERROR` 显示错误 + 「重试」按钮（`:150-168`）；`READY` 且 `errorMsg` 非空显示「补全」按钮（`:169-187`）——此时 `errorMsg` 的语义是「部分失败的分段提示」而非错误（写入方在 `Generator.kt:77`）。

**`busyStage` 的两个来源（:462）**：`combine(NoteProcessor.stageFlow(noteId), localStage) { p, l -> l ?: p }`——主来源是宿主的 `stages` 表（转写/生成/改写的阶段文案，`NoteProcessor.kt:147-149`），本地补一个「正在恢复版本…」（`restore()` 里 `:552` 设、`finally :556` 清）。首页角标也读同一张 `stages` 表（`HomeScreen.kt:168` 的 `stage = stages[note.id]`），两边看到的是同一份进度。

**三个标签怎么分工**：`TabRow`（`:190-194`）+ 叠放 Box（`:196-212`，注释写明：导图 WebView 常驻组合不销毁，另两页用不透明背景盖上去，切页不丢缩放/平移状态）。

- **导图 `MapTab`（:261-297）**：`mapJson` 为空时显示「还没有思维导图」+「生成导图」按钮（`:271`，点击 `vm.generate()`）；有图则挂 `MindMapPanel`（`:280-287`，`editable = status == READY`，`:282`；`onMapChanged` 回调 `vm.saveMap`），右上角浮层只剩「导出图片」一颗按钮经 `MapController` 调画布——撤销/居中在画布底部工具条里，不再原生转发（2026-10-31 可读性重做）。
- **原文 `TranscriptTab`（2026-10-31 起三路分支）**：先按笔记解析时间轴 `Timeline.decode(n.timings)`（`remember(n.id, n.timings)` 只解一次）；有 `audioPath` 先渲染播放条 `AudioPlayerCard`。正文三分支——`content` 空 → 空状态；**`timings` 非空 → `SyncedTranscript`（播放跟随：逐句渲染、当前句主色容器高亮、播放时自动滚动把当前句拉到视口中部）**；否则按旧逻辑按段落拆项渲染。`SyncedTranscript` 的跟随规则：进度流（300ms 一跳）只认「当前句变化」（`Timeline.activeIndex` 二分）滚动，用户手指拖列表期间不抢（`DragInteraction` 探测），松手后下一次句变化立刻拉回；点任意一句 = `vm.onSentenceTap(句起点)` 从那句起播（在播就跳过去，没播就起播）。复制全文按钮两分支都有。旧笔记（无 timings）保持原样无高亮。
- **思路 `ThinkingTab`（2026-11-14 起双视图）**：顶部「图示卡片 / 文字版」药丸切换（`ViewModeToggle`/`TogglePill`，默认图示卡片=现状形态）。**图示卡片形态**：有分段图示 → `ThinkingSections` 小节卡片流——卡片点击**展开/收起详细讲解**（`DetailParser.decode(n.detailJson)` 按标题对齐；chevron 随展开翻转 + `AnimatedVisibility` expand/shrink；`extra=true` 的补充小节排在尾部、带「补」徽章、默认收起）；**跳原声改为标题行右侧 ▶ 圆钮**（2026-11-14(三) 是整卡点击，(四) 让位给展开详解；文字笔记/旧笔记无录音自动隐藏）；尾部「生成详细讲解 / 重新生成讲解」按钮（`regenDetail`，失败给 Snackbar 人话提示）。无分段图示 → 回退整段显示 + 手动生成按钮（2026-11-14(二) 布局坑见 图示功能总览 坑 8）。**文字版形态**（`TextVersionView`）：`composeFullText(detailDoc)` 拼接全文（中文序号「一、二、」+ 标题行 + 节间空行；没详解回退 `thinking` 原文），`SelectionContainer` 可长按选字 + 尾部「复制全文」按钮（写系统剪贴板）。**听书读文字版**：`toggleTts()` 读 `DetailParser.decode(n.detailJson)?.let(::composeFullText) ?: n.thinking`——有详读书拼接全文（课堂细节完整），没详解回退思路原文。朗读条（▶/朗读中/语速滑杆）与 AI 建议输入条沿用原布局。点击跳原声（(三)）的定位链（`TimelineLocator` + `jump` 闭包 + `pendingCenterIdx` 对准）原样保留，仅触发点改 ▶。

**AI 建议输入（:214-245）**：底部输入框 + 「让 AI 改」按钮（`:234-243`，可用条件 `mapJson != null && busyStage == null`，`:240`）。**点击后不清空输入框**（`:237` 注释）——改图成功后由 ViewModel 清，失败则建议留在框里可直接改字重发。这条「谁负责清空」的约定由 `reviseAwaitingResult` 状态机实现（`:480`、`:490-504`）：ViewModel 收集 `note` 流，观察到 `READY` 才清空 `suggestion`（`:495-498`），观察到 `ERROR` 只解除等待（`:500`）。

**版本抽屉 `VersionsSheet`（:249-258、`:397-442`）**：顶栏时钟图标打开（`:119`，`enabled = note?.mapJson != null`）。每行显示时间 + 首行预览（`TreeText.fromMapData` 反解快照取第一行，`:422-426`）+ 「恢复」；点击走 `vm.restore(v.id)`。抽屉文案说明快照是「每次 AI 改动前的快照」。

### DetailViewModel 逐个方法（:449-665）

| 方法 | 位置 | 做什么 |
| --- | --- | --- |
| `maybeRunPipeline()` | `:507-510` | 打开笔记时的常驻钩子：`LaunchedEffect(note?.id, note?.status)`（`:101`）触发，转调 `NoteProcessor.maybeRun(noteId)`——续跑/纠偏的四种情形判定全在宿主侧（`NoteProcessor.kt:70-86`），本页只负责在状态变化时触发它。 |
| `retry()` | `:512-527` | 状态条「重试」的共用出口，三分支：① `ERROR` 且 `errorMsg` 以「修改失败」开头 → 只把行清成 `READY`，**绝不重跑整篇生成**（省额度，`:516-520`；判据来自 `Generator.revise` 失败写的前缀，两边字面量成对，改动任一侧都会破坏约定）；② `content` 空但有 `audioPath` → `NoteProcessor.start(TRANSCRIBE)`（`:522-523`）；③ 其余 → `NoteProcessor.start(GENERATE)`（`:524`，重生成前 `Generator.generate` 自动存快照，不丢手动整理的导图）。 |
| `generate()` | `:529-531` | 一行委托：`NoteProcessor.start(noteId, Kind.GENERATE)`。幂等：同笔记已有任务在跑时宿主直接返回 false 忽略。 |
| `sendSuggestion(text)` | `:533-536` | `if (NoteProcessor.start(noteId, Kind.REVISE, text)) reviseAwaitingResult = true`——**只有真正起跑才算等待结果**（`:534` 注释：渠道忙导致没起跑时输入框原样保留）。 |
| `saveMap(json)` | `:538-546` | 画布回传的唯一落库口。`Dispatchers.IO` 重新读行（`:540`，不信任内存旧对象）→ 只有 `status == READY` **且** `mapJson != json` 才写（`:542-544`）。与画布侧闸门 `editable = READY`（`:282`）构成双保险（README 设计决策 5）。 |
| `restore(versionId)` | `:548-559` | 唯一还留在页面里的流水线动作：先 `NoteProcessor.isBusy(noteId)` 守卫——**在飞的那次写库用的是开跑前的快照，会把恢复结果覆盖掉**（`:549` 注释），在跑就静默拒绝；然后本地 `localStage = "正在恢复版本…"`，`Generator(db, settingsRepo).restoreVersion(noteId, versionId)`（`:554`），`finally` 清 stage。 |
| `shareMarkdown()` | `:561-568` | `Exporter.exportMarkdown(ctx, n)` 生成临时 md → `Exporter.shareFile`（`export/Exporter.kt`，见「导出模块总览.md」）。 |
| `togglePlay/seekTo/startTicker` | 播放：懒建 `MediaPlayer` 抽成 `ensurePlayer()`（IO 线程 prepare，失败报 Snackbar 返回 null，2026-10-31 重构）——`togglePlay()` 与新加的 `onSentenceTap(startMs)`（点句子从那句起播）共用；`seekTo(fraction)` 服务滑杆；300ms ticker 刷进度；导入时已知时长先预填。 |
| `toggleTts/toggleTtsText/setTtsRate` | 朗读：`toggleTts` 先取朗读文本——`DetailParser.decode(n.detailJson)?.let(::composeFullText) ?: n.thinking`（2026-11-14 起读详解拼接的文字版，回退思路原文），再 `toggleTtsText(text)`：`settingsRepo.current()` 取引擎，CLOUD 时用 `CloudTtsConfig.fromSettings(s)` 按服务档位组装配置 → `tts.speak(text, rate, engine, cloud)`（正文回落默认开）；朗读中拖语速条 `updateRate` 即时生效并持久化。 |
| `regenDetail()`（2026-11-14 新增） | 前置检查（`detailsEnabled` 关 / 无思路 / 无 diagramJson → Snackbar 人话提示）→ `NoteProcessor.start(noteId, Kind.DETAIL, "manual")` → 轮询 `while (NoteProcessor.isBusy(noteId)) delay(300)` → 结束后比对 detailJson 没变则提示「详细讲解没生成出来（接口没返回可用内容）…」——软失败静默的唯一人话出口。 |
| `onCleared`（:658-664） | 释放播放器与 TTS 资源。 |

**自动接力的例子**：录音页保存后跳进详情页时，笔记可能还是 `TRANSCRIBING`——`LaunchedEffect(note?.id, note?.status) { vm.maybeRunPipeline() }`（`:101`）触发宿主 `maybeRun`，宿主发现该转写就启动 `TRANSCRIBE`，转写完**同栈自动接 `runGenerate`**（`NoteProcessor.kt:112`/`125`），用户全程不用再点。进程被杀的情形由 `NoteProcessor.resumeStuck()`（App 启动时批量）兜底。

**产出什么**：全部落在 `notes` 行（状态、content、mapJson、thinking、virtualRoot、errorMsg、updatedAt）与 `versions` 快照上；分享产生 `cache/` 下一个导出临时文件（`export/Exporter.kt`，见「导出模块总览.md」）。本页不持有跨页状态——连「改图建议输入框内容」都放 ViewModel（`:478-479`）就是为了改图失败后不丢。

**影响谁**：写库后 `observeById` 再发一格 → 画布 `setData` 刷新（外部变化才回推，拖动防回环见「导图画布模块总览.md」）、首页列表顺序变化（按 `updatedAt DESC`）。

## 已知坑与约束

1. **「重试」对「修改失败」只清提示、绝不重跑**：判据是 `errorMsg.startsWith("修改失败")`（`:517-520`），与 `Generator.revise` 失败分支写入的前缀字面量成对（`Generator.kt` 的失败分支）——改任一侧的字面量都会让重试语义失效（多打一次整篇生成、白烧额度）。详见「生成流水线模块总览.md」改写链路。
2. **版本恢复有 `isBusy` 闸门**（`:550`）：转写/生成进行中直接拒改版本，理由见 `:549` 注释（在飞写库用开跑前快照，会覆盖恢复结果）。抽屉侧不再单独拦，恢复请求静默失效。
3. **`toggleTtsText` 的 KDoc 说「思路/原文共用一个播放器」，实际调用点只有思路**（`:631`）——原文页没有朗读按钮。注释是超前/残留描述，改动前先确认产品意图。
4. **建议输入框的清空时机在三方手里**：按钮不清（`:237`）、成功由 ViewModel 清（`:497`）、失败留在框里。改 `reviseAwaitingResult` 收集逻辑时三处要一起看。
5. **`saveMap` 双闸门**：UI 侧 `editable = READY`（`:282`）+ VM 侧 `status == READY && mapJson != json`（`:542`）——旧值相同也不写，避免无意义地刷 `updatedAt` 挤掉首页排序。
6. **恢复版本走 `Generator.restoreVersion` 而不通知宿主**（`:548-559`）：`restore` 是本地协程 + `localStage` 文案，宿主 `stages` 表里没有这条任务；`isBusy` 守卫防的就是「宿主在飞时恢复被覆盖」。
7. **播放器资源必须回收**：`MediaPlayer` 持有、`onCleared` 统一释放（`:658-664`）；`prepare()` 在 IO 线程（`:579-584`），失败只置 `playing = false` 不打扰用户（`:594-596`）。
8. **`noteId <= 0` 的兜底与守卫分两路**：路由解析失败给 `0L`（`AppNav.kt:46` `toLongOrNull() ?: 0L`）；ViewModel 侧两条 Flow 直接 `flowOf(null/emptyList())`（`:454-457`）；宿主 `start` 与 `maybeRun` 也各有 `noteId <= 0` 守卫（`NoteProcessor.kt:45`、`71`）——`DetailScreen.maybeRunPipeline` 本身不拦（`:508-510`），靠宿主侧拦，不会写库。
