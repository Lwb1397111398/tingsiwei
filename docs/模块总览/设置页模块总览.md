# 设置页模块总览

## 模块职责

`ui/SettingsScreen.kt` 是唯一的应用配置界面：录入并保存 LLM 接口三要素（地址 / API KEY / 模型）、拉取模型列表、测试连接、切换转写方式、下载或删除离线识别模型、开关「允许 AI 拓展知识」与「思路精修（更慢）」、选择朗读引擎（系统 TTS / 本地 kokoro 离线模型 / 在线大模型）、下载或删除 TTS 模型、配置在线朗读（2026-10-24 起分两档：**官方 ElevenLabs** 只填 API Key + 获取音色点选 + 模型 chips，**自定义 OpenAI 兼容**填地址/Key/模型/音色，均改动即存）、试听朗读效果、调节限流节奏（请求间隔 / 上下文窗口 / 保守模式）与朗读语速；2026-10-05 起还有「应用更新」卡（检查/下载/安装新版本、GitHub 令牌配置，逻辑在《应用自更新模块总览》）。

## 关键数据结构

- `enum class ModelState { UNKNOWN, READY, DOWNLOADING, NOT_DOWNLOADED }`（`SettingsScreen.kt:369`）——识别模型在界面上的四态。
- `data class ModelStateUi(state, bytes, downloaded, total, progress)`（`SettingsScreen.kt:371-377`）：`total` 默认取 `ModelManager.MODEL_BYTES = 237_115_547`（`375`），`bytes` 是目录内所有文件大小之和，`progress = downloaded/total`。
- `enum class TtsModelState { UNKNOWN, READY, DOWNLOADING, NOT_DOWNLOADED }`（`SettingsScreen.kt:379`）与 `data class TtsModelStateUi(...)`（`381-387`）：TTS 侧镜像四态，`total` 默认取 `ModelManager.TTS_TOTAL_BYTES`（`385`）。注意 TTS 的 DOWNLOADING 判定与 ASR **不同源且方向相反**：`refreshTtsModelState()`（`513-526`）在「有残缺字节但未就绪」时返回的是 `NOT_DOWNLOADED` 并带上残缺进度（`519-521`，注释原话「不算'下载中'，按钮可点续传」；UI 此时显示「已下载 X，点下载继续」`:332-334`）——即 TTS 侧**不存在** ASR 那种假「下载中」，下载中状态只由 `downloadTtsModel()` 自己写入。

## 已知坑与约束

1. **「测试连接」不保存，正式生成用的是库里的旧值**：`test()` 直接把界面上的 `url/key/model` 传给 `client.chat(...)`（`SettingsScreen.kt:473-482`），全程没有 `repo.setLlm`；而生成链路读的是已持久化的值（`LlmClient.kt:59`）。测到「连接正常」却不点保存 → 下次生成仍用旧配置。
2. **「获取模型列表」会顺带写库**：`fetchModels()` 先 `repo.setLlm(url.value, key.value, model.value)` 再拉取（`SettingsScreen.kt:456-468`，写库在 `461`，注释也写明「先保存当前填写内容再拉取」），用户点一个只读的按钮实际产生了写操作，无法「先看看有哪些模型再决定保存」。
3. **API KEY 明文显示、明文存储**：`key` 字段是普通 `OutlinedTextField`，无 `visualTransformation`（`SettingsScreen.kt:127-132`），底层是 DataStore 首选项明文键 `llm_key`（`data/SettingsRepository.kt:55`），再叠加 `allowBackup="true"`（`AndroidManifest.xml`）。本文档只描述存放位置与读写方式，不记录任何具体取值。（2026-10-05 注：全项目 `ui/*.kt` 的首个 `PasswordVisualTransformation` 现已存在——本文件应用更新卡的令牌框 `:402`；旧句「全项目无」就此作废，`key` 字段本身仍是明文显示。）
4. **三个输入框都没设 `keyboardOptions`**（`SettingsScreen.kt:119-140`），网址与 KEY 都弹普通键盘，`singleLine = true` 是唯一的输入约束（`124`、`132`、`140`）。
5. **当前选中的档位渲染成 `Button(onClick = {})`**：限流卡的间隔/窗口档位用空回调的实心按钮表示「已选」（间隔档在 `SettingsScreen.kt:260` 的 `forEach` 内渲染，窗口档在 `268` 的 `forEach` 内渲染），点击无反馈、无障碍上也读不出选中态；未选档才是 `TextButton`。
6. **档位是硬编码枚举，无法自定义**：间隔只有 `600/1200/2500`（`SettingsScreen.kt:260`，标签「快/中/慢」），窗口只有 `8192/16384/32768/65536/131072/262144` 六档（`268`，v1.3 起去掉 4096、上限抬到 262144，见 `SettingsRepository.kt:67-68` 的迁移标记）。而数据层允许 `2048..1_000_000`，窗口小于 8k 或大于 262144 的渠道在界面上无法配置。默认值 `LlmPolicy.DEFAULT_CONTEXT_WINDOW = 131072` 与 `DEFAULT_MIN_INTERVAL_MS = 1200` 都在候选里，所以初始渲染不会出现「无选中项」。
7. **ASR 下载中断后再进设置页会卡在假的「下载中」**：`refreshModelState()` 把「`model.int8.onnx` 已有部分字节」判成 `DOWNLOADING`（`SettingsScreen.kt:430-441`，`downloadedBytes(..., "model.int8.onnx") > 0` 即 DOWNLOADING），此时按钮 `enabled = state != DOWNLOADING`（`206`）为假，并且 `downloadModel()` 首行对 `DOWNLOADING` 直接 `return`（`608`）——实际没有任何协程在跑，页面永远点不动。可自救路径只有「删除模型」（`210` → `633-636` → `ModelManager.deleteModel` 删掉目录里包括半成品在内的全部文件）后重下。**TTS 侧已修掉这个假态**：`refreshTtsModelState()` 对同样情形返回 `NOT_DOWNLOADED`+残缺进度（`519-521`），按钮保持可点续传；`downloadTtsModel()` 的早退分支（`529`）只挡真在跑的情形。
8. **模型状态只在进入页面时刷新一次**（`SettingsScreen.kt:95-98` 的 `LaunchedEffect(Unit)` 同时拉 ASR 与 TTS 两套状态），无轮询无事件；`DOWNLOADING` 期间的进度只由下载回调驱动（ASR `609-628`，TTS 的进度回写在 `onProgress`（`547-553`）；`downloadTtsModel()` 开头的 `531-535` 只是把状态置成 DOWNLOADING 的初始写入）。ASR 侧 `tokens.txt` 的回调被丢弃（`613` 传 `{ _, _ -> }`），所以「正在下载 tokens…」阶段进度显示为 0%。
9. **体积口径不一致**：ASR 文案硬编码「约 230MB」（`SettingsScreen.kt:195`、`614`），而按 `Formatters.fileSize` 的 1024 进制是 `226.1 MB`（`ModelManager.MODEL_BYTES = 237_115_547`）；TTS 侧同理，下载清单实算 `TTS_TOTAL_BYTES = 215,308,902` 字节（205.3 MiB / 215MB 十进制），详见模型下载模块总览。
10. **拖动语速滑块会每帧写库**：`Slider(onValueChange = { vm.setTtsRate(it) })`（`SettingsScreen.kt:307`）直接落 DataStore（`502-506`），没有 debounce；且 `tts_rate` 有第二个写入口——详情页的语速控件同样调 `setTtsRate`（`ui/DetailScreen.kt:651-656`），两处状态不互通（详情页只在 VM 创建时读一次）。唯一联动：本页试听进行中拖滑块会即时改速（`setTtsRate` 里 `previewTts.updateRate(rate)`，`504`），详情页的朗读中调速则由 TtsPlayer 自己处理。
11. **限流三项共享一次写入**：`persistLimits()` 把 `contextWindow/minIntervalMs/conservative` 三个值整体 `setLlmLimits`（`SettingsScreen.kt:601-605`），所以任一项变动都会重写另两项的当前值；配合 `data/SettingsRepository.kt:127-128` 的 `coerceIn`，越界值会被静默夹取而不是报错。
12. **AI 拓展 / 思路精修 / 转写方式 / 朗读引擎均无二次确认**：`Switch`（`221`、`233`）与 `RadioButton`（`178`、`185`、`316`、`323`）改完即生效，正在进行的生成不会回滚（`Generator` 只在任务开始时读一次 `cfg`）。
13. **`vm.message` 由 UI 直接改写**：`LaunchedEffect` 消费完提示后执行 `vm.message.value = null`（`SettingsScreen.kt:92`），提示的清空逻辑泄漏到组合函数里；同一条消息在重组期间被再次触发时可能被吞。
