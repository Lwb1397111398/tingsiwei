# 设置页模块总览

## 模块职责

`ui/SettingsScreen.kt` 是唯一的应用配置界面：录入并保存 LLM 接口三要素（地址 / API KEY / 模型）、拉取模型列表、测试连接、切换转写方式、下载或删除离线识别模型、开关「允许 AI 拓展知识」与「思路精修（更慢）」、调节限流节奏（请求间隔 / 上下文窗口 / 保守模式）与朗读语速。

## 运作流程

**从哪来**：`AppNav` 的 `composable(Routes.SETTINGS)` 调 `SettingsScreen(onBack = { nav.popBackStack() })`（`app/src/main/java/com/tingsiwei/app/ui/AppNav.kt:49-51`）。ViewModel 用默认工厂在导航条目作用域创建（`SettingsScreen.kt:63`），构造时抓两样东西：`App.get().settings` 作为仓库（`SettingsScreen.kt:296`）和 `LlmClient(repo)`（`SettingsScreen.kt:297`），`context` 直接取 `App.get()`（`SettingsScreen.kt:298`）。`init` 块里一次性 `repo.current()`，把 9 个值灌进 13 个 `MutableStateFlow`（`SettingsScreen.kt:314-327`，字段声明在 `SettingsScreen.kt:300-312`）。

**怎么处理**：界面是 `Scaffold + TopAppBar + verticalScroll(Column)`（`SettingsScreen.kt:89-101`），五张 `Card`：

| 卡片 | 位置 | 控件 | 落库方式 |
| --- | --- | --- | --- |
| LLM 接口（OpenAI 兼容） | `SettingsScreen.kt:105-160` | 3 个 `OutlinedTextField`（`108-123`、模型字段包在 `ExposedDropdownMenuBox` + `menuAnchor()` 里 `124-132`）、`获取模型列表`/`测试连接`/`保存` 三按钮（`147-151`）、`busy` 转圈（`152-158`） | **必须点按钮**：`save()`→`repo.setLlm(...)`（`347`）；`fetchModels()` 也先写库（`360`）；`test()` **不写库** |
| 语音转文字 | `SettingsScreen.kt:163-203` | 2 个 `RadioButton`（`167-179`）、模型状态文本（`181-186`）、`LinearProgressIndicator`（`187-192`）、`下载模型`/`删除模型`（`193-201`） | `setMode()` 即改即存（`386-389`） |
| 生成偏好 | `SettingsScreen.kt:206-232` | `Switch` 绑 `allowExpand` 与 `stagedThinking`（思路精修，默认关） | `setAllowExpand()`/`setStagedThinking()` 即改即存 |
| 长录音与限流 | `SettingsScreen.kt:225-262` | 间隔 3 档（`236-239`）、窗口 4 档（`243-247`）、保守模式 `Switch`（`250`） | `persistLimits()` 三项一起写（`416-420`） |

**产出什么**：全部落到 `SettingsRepository` → DataStore `settings`（`app/src/main/java/com/tingsiwei/app/data/SettingsRepository.kt:16`），键位 `llm_url`/`llm_key`/`llm_model`（`SettingsRepository.kt:42-44`，写入前 `trim()` `71-73`）、`transcribe_mode`（`45`）、`allow_expand`（`46`）、`llm_context_window`/`llm_min_interval_ms`/`llm_conservative`（`48-50`，写入前夹在 `2048..1_000_000` 与 `0..60_000` 之间，`79-80`）、`tts_rate`（`47`）。另一条产出是磁盘上的离线模型文件（`files/asr/sensevoice/model.int8.onnx` + `tokens.txt`，目录见 `app/src/main/java/com/tingsiwei/app/transcribe/SherpaTranscriber.kt:49-50`），由 `ModelManager.downloadFile` 断点续传写入（`SettingsScreen.kt:428`、`430-438` → `transcribe/ModelManager.kt:47-98`）。此外 `message` 走 `SnackbarHost` 一次性提示并手动置空（`SettingsScreen.kt:79`、`81-86`）。

**影响谁**：`LlmClient` 每次建会话都读 `settings.current()` 组装重试/限流/预算策略（`app/src/main/java/com/tingsiwei/app/llm/LlmClient.kt:59-75`）；`Generator` 用 `allowExpand` 决定 system 提示词、用 `llmUrl/llmKey/llmModel` 发请求、用 `llmContextWindow`/`llmConservative` 配长文流水线（`app/src/main/java/com/tingsiwei/app/llm/Generator.kt:39-47`、`108`）；录音链路读 `transcribeMode`（`app/src/main/java/com/tingsiwei/app/record/RecordSession.kt:66`、`ui/RecordScreen.kt:203`）；详情页朗读读 `ttsRate`（`ui/DetailScreen.kt:461`、`464`、`658`）。保守模式不改库里存的窗口/间隔原值，而在读取侧折算：`LlmPolicy.windowFor` 减半、`intervalFor` 翻倍（`app/src/main/java/com/tingsiwei/app/llm/LlmPolicy.kt:134-138`）。

## 关键数据结构

- `enum class ModelState { UNKNOWN, READY, DOWNLOADING, NOT_DOWNLOADED }`（`SettingsScreen.kt:284`）——模型文件在界面上的四态。
- `data class ModelStateUi(state, bytes, downloaded, total, progress)`（`SettingsScreen.kt:286-292`）：`total` 默认取 `ModelManager.MODEL_BYTES`（`290`），`bytes` 是目录内所有文件大小之和（`ModelManager.kt:130-131`），`progress = downloaded/total`（`336`、`436`）。
- 13 个 `MutableStateFlow` 构成 VM 的全部状态（`SettingsScreen.kt:300-312`）：`url`、`key`、`model`、`models`、`transcribeMode`、`allowExpand`、`ttsRate`、`contextWindow`、`minIntervalMs`、`conservative`、`modelState`、`message`、`busy`。初值与 `AppSettings` 默认值保持一致（`SettingsScreen.kt:305-309` ↔ `data/SettingsRepository.kt:59-63`）。
- 复用数据层的 `AppSettings`（`data/SettingsRepository.kt:24-37`）作为读快照类型，本文件不新增持久化模型。

## 已知坑与约束

1. **「测试连接」不保存，正式生成用的是库里的旧值**：`test()` 直接把界面上的 `url/key/model` 传给 `client.chat(...)`（`SettingsScreen.kt:376`），全程没有 `repo.setLlm`；而生成链路读的是已持久化的值（`llm/Generator.kt:42`、`llm/LlmClient.kt:60`）。测到「连接正常」却不点保存 → 下次生成仍用旧配置。
2. **「获取模型列表」会顺带写库**：`fetchModels()` 先 `repo.setLlm(url, key, model)` 再拉取（`SettingsScreen.kt:360-361`，注释也这么写），用户点一个只读的按钮实际产生了写操作，无法「先看看有哪些模型再决定保存」。
3. **API KEY 明文显示、明文存储**：`key` 字段是普通 `OutlinedTextField`，无 `visualTransformation`（`SettingsScreen.kt:116-123`；全项目 `ui/*.kt` 无 `PasswordVisualTransformation`），底层是 DataStore 首选项明文键 `llm_key`（`data/SettingsRepository.kt:43`），再叠加 `allowBackup="true"`（`AndroidManifest.xml:12`）。本文档只描述存放位置与读写方式，不记录任何具体取值。
4. **三个输入框都没设 `keyboardOptions`**（`SettingsScreen.kt:108-131`），网址与 KEY 都弹普通键盘，`singleLine = true` 是唯一的输入约束（`113`、`121`、`130`）。
5. **当前选中的档位渲染成 `Button(onClick = {})`**：`SettingsScreen.kt:237`、`245` 用空回调的实心按钮表示「已选」，点击无反馈、无障碍上也读不出选中态；未选档才是 `TextButton`。
6. **档位是硬编码枚举，无法自定义**：间隔只有 `600/1200/2500`（`SettingsScreen.kt:236`，标签「快/中/慢」），窗口只有 `4096/8192/16384/32768`（`243`）。而数据层允许 `2048..1_000_000`（`data/SettingsRepository.kt:98-99`），窗口小于 4k 或大于 32k 的渠道在界面上无法配置。默认值 `16384`（`llm/LlmPolicy.kt:111`）与 `1200`（`112`）恰好都在候选里，所以初始渲染不会出现「无选中项」。
7. **下载中断后再进设置页会卡在假的「下载中」**：`refreshModelState()` 把「存在 `.part` 半成品」判成 `DOWNLOADING`（`SettingsScreen.kt:334-337`），此时按钮 `enabled = modelState.state != ModelState.DOWNLOADING`（`195`）为假、文案变「下载中…」（`196`），并且 `downloadModel()` 首行对 `DOWNLOADING` 直接 `return`（`423`）——实际没有任何协程在跑，页面永远点不动。可自救路径只有「删除模型」（`448-452` → `ModelManager.deleteModel` 会删掉目录里包括 `.part` 在内的全部文件，`transcribe/ModelManager.kt:125-128`）后重下。
8. **模型状态只在进入页面时刷新一次**（`SettingsScreen.kt:87` 的 `LaunchedEffect(Unit)`），无轮询无事件；`DOWNLOADING` 期间的进度只由下载回调驱动（`433-437`）。`tokens.txt` 的回调被丢弃（`428` 传 `{ _, _ -> }`），所以「正在下载 tokens…」阶段进度显示为 0%。
9. **体积口径不一致**：界面文案硬编码「约 230MB」（`SettingsScreen.kt:184`、`429`），而同一文件按 `Formatters.fileSize` 的 1024 进制显示为 `226.1 MB`（`util/Formatters.kt:21-24` + `transcribe/ModelManager.kt:23` 的 `237_115_547L`），`transcribe/SherpaTranscriber.kt:13` 注释与索引 README 第 20 行都写「~226MB」。
10. **拖动语速滑块会每帧写库**：`Slider(onValueChange = { vm.setTtsRate(it) })`（`SettingsScreen.kt:271`）直接落 DataStore（`396-399`），没有 debounce；且 `tts_rate` 还有第二个写入口——详情页的语速控件同样调 `setTtsRate`（`ui/DetailScreen.kt:667-668`），两处状态不互通（详情页只在 VM 创建时读一次，`DetailScreen.kt:464`）。
11. **限流三项共享一次写入**：`persistLimits()` 把 `contextWindow/minIntervalMs/conservative` 三个值整体 `setLlmLimits`（`SettingsScreen.kt:416-420`），所以任一项变动都会重写另两项的当前值；配合 `data/SettingsRepository.kt:79-80` 的 `coerceIn`，越界值会被静默夹取而不是报错。
12. **AI 拓展与转写方式无二次确认**：`Switch`（`SettingsScreen.kt:210`）与 `RadioButton`（`167-178`）改完即生效，正在进行的生成不会回滚（`llm/Generator.kt:39` 只在任务开始时读一次 `cfg`）。
13. **`vm.message` 由 UI 直接改写**：`LaunchedEffect` 消费完提示后执行 `vm.message.value = null`（`SettingsScreen.kt:84`），提示的清空逻辑泄漏到组合函数里；同一条消息在重组期间被再次触发时可能被吞。
14. **离线模型大小阈值与实际下载校验不同源**：界面判断「已就绪」用 `SherpaTranscriber.isModelReady`（`SettingsScreen.kt:330` → `SherpaTranscriber.kt:52-56`：模型 > 200_000_000 且 tokens > 100_000），而 `downloadFile` 完成校验用的是调用方传入的 `minBytes`（`430-431` 的 `200_000_000`、`428` 的 `100_000`）。两处阈值重复硬编码，改一处容易漏另一处；`ModelStateUi.total` 用的又是第三个常量 `MODEL_BYTES`（`290`），所以「100%」不等于阈值满足。
15. **索引 README 相关**：README 索引表（第 21、22 行）用「`tts/TtsPlayer.kt` 语速 0.5~2.0x」「文字转写（备用）设置里切换 `TranscribeMode`」来描述本页面能做的事，行为与代码相符（`SettingsScreen.kt:272` 的区间、`386-389` 的切换），但索引**没有为设置页单独列一行**，`ui/SettingsScreen.kt` 只作为其它条目的隐含入口出现；README 第 10 行列举的设置项名称「LLM 地址/KEY/模型、转写方式、AI 拓展开关、语速、上下文窗口/请求间隔/保守模式」在代码里对应 `llmUrl/llmKey/llmModel/transcribeMode/allowExpand/ttsRate/llmContextWindow/llmMinIntervalMs/llmConservative`（`data/SettingsRepository.kt:25-36`），其中「AI 拓展开关」的实际字段名是 `allowExpand`、界面标题是「允许 AI 拓展知识」（`SettingsScreen.kt:213`）。
