# 数据层模块总览

## 模块职责

全应用唯一的持久化出入口：`SettingsRepository` 用 DataStore Preferences 存应用设置（基础 9 项，含 LLM 接口配置，API KEY 只存在 `llm_key` 键；2026-10-05 起另有应用自更新 4 个键；2026-10-31 起再增 LLM 配置方案 2 键 `llm_profiles`/`llm_active_profile`——多套命名的接口配置，JSON 存单键，见键位表；K 对象现共 27 键），`AppDatabase` + `Entities` 用 Room 存两张表 `notes`（笔记）与 `versions`（导图版本快照）。配置方案的模型与 JSON 编解码在独立文件 `data/LlmProfiles.kt`（纯函数，带 JVM 单测）。

## 运作流程

**从哪来**：`App` 用 `by lazy` 各建一个实例——`database = AppDatabase.create(this)`（`app/src/main/java/com/tingsiwei/app/App.kt:8` → `data/db/AppDatabase.kt:66-70`）、`settings = SettingsRepository(this)`（`App.kt:9`），全局只有这一份，靠 `App.get()` 分发。

**怎么处理（写）**：
- 设置项：设置页每个动作对应一个 setter——`setLlm`（`app/src/main/java/com/tingsiwei/app/ui/SettingsScreen.kt:347`、`360`）、`setTranscribeMode`（`SettingsScreen.kt:388`）、`setAllowExpand`（`393`）、`setTtsRate`（`398`，详情页另有一处 `ui/DetailScreen.kt:668`）、`setLlmLimits`（`SettingsScreen.kt:418`）；写库前做 `trim()`（`data/SettingsRepository.kt:71-73`）与 `coerceIn` 夹取（`SettingsRepository.kt:79-80`）。
- 笔记插入：录音保存（`record/RecordSession.kt:126-136`）、首页导入音频（`ui/HomeScreen.kt:305-315`）、文字录入两条分支（`ui/TextInputScreen.kt:97-106` 生成路径 / `137-148` 粘贴导图路径）。
- 笔记更新：生成链路集中改状态（`llm/Generator.kt:34`、`37`、`76`、`83`、`105`、`128`、`138`、`167`），详情页改转写/导图/原文（`ui/DetailScreen.kt:488`、`501`、`515`、`524`、`529`、`569`）。
- 版本快照：只有 `Generator` 写——统一走 `saveSnapshot()`（2026-10-31 起，`llm/Generator.kt`）：重新生成前存旧导图、`revise` 前存、恢复版本前再存当前，**插完即把本篇裁到最近 20 份**（`VersionDao.pruneTo`，此前只进不出 versions 表会无限膨胀）。
- 删除：`noteDao().delete(note)`（`ui/HomeScreen.kt:275`），删前先手动清音频文件（`HomeScreen.kt:264-266`）与分段落盘缓存（`HomeScreen.kt:272`）。

**产出什么**：`files/../databases/tingsiwei.db`（库名见 `AppDatabase.kt:61`）与 DataStore 文件 `settings`（store 名见 `SettingsRepository.kt:16`）。读侧全部是响应式：`settings: Flow<AppSettings>` + 一次性 `current()`、首页轻量列表 `noteDao().observeList()` 与搜索 `searchList(q)`（2026-10-31 起，只取卡片展示列 + SQL 截 120 字预览，整篇原文/导图 JSON 不进内存）、`observeById()`、`versionDao().observeForNote()`，另有 `byId` 同步快照读。

**影响谁**：首页列表与搜索（`ui/HomeScreen.kt:257-260`）、详情页三块内容（`ui/DetailScreen.kt:443-445`）、LLM 请求参数与限流策略（`llm/LlmClient.kt:60-74`、`llm/Generator.kt:39-47`）、转写方式选择（`record/RecordSession.kt:66`、`ui/RecordScreen.kt:203`）、TTS 语速（`ui/DetailScreen.kt:464`、`658`）。

## 已知坑与约束

1. **Room 升版本必须配迁移（2026-10-25 已堵死破坏性回退）**：`version = 1`（`AppDatabase.kt:60`）；当日移除 `fallbackToDestructiveMigration()`（原 `:62`），现在漏写迁移会在启动时直接抛异常（崩在明处）而不是静默清空用户笔记；`exportSchema = true` + `app/schemas/…/1.json` 入库（`AppDatabase.kt:57-59` 注释即铁律）。**当前仍是 version=1、没有任何 Migration 对象**——首次升版本（如加字段）必须同步写 `MIGRATION_1_2` 挂进 `addMigrations`（`AppDatabase.kt:66-70` 处），并提交新的 schema JSON；迁移测试尚未建立（207 例单测不含 Room 迁移用例），首升版本时建议补。
2. `NoteDao.insert` 用 `OnConflictStrategy.REPLACE`（`AppDatabase.kt:29-30`）：传入带非 0 `id` 的实体时是整行替换而不是报错，未列出的字段会丢；现有调用点都靠 `id` 默认 0 走自增（`record/RecordSession.kt:126`、`ui/HomeScreen.kt:305`、`ui/TextInputScreen.kt:97`、`137`），改成「就地编辑」时有踩雷风险。`VersionDao.insert` 则没有冲突策略（`47-48`）。
3. ~~`NoteDao.search(q)` 是死代码、首页内存过滤~~ **已修（2026-10-31）**：新增轻量投影 `observeList()`/`searchList(q)`（`AppDatabase.kt`，SQL 截 120 字预览，不拉整篇原文/导图 JSON），首页改用 `flatMapLatest` 在两个查询间切换（`ui/HomeScreen.kt` HomeViewModel），整实体 `search()` 已删除。
4. `notes` 表没有任何索引与外键（`Entities.kt:24-43` 只有 `@Entity(tableName = "notes")`），`ORDER BY updatedAt DESC`（`AppDatabase.kt:17`）是全表排序；`versions` 才有 `Index("noteId")`（`Entities.kt:55`）。
5. ~~版本快照只增不减~~ **已修（2026-10-31）**：`Generator` 的三处插快照统一走 `saveSnapshot()`，插完调 `VersionDao.pruneTo(noteId, 20)` 只留每篇最近 20 份（上限常量 `Generator.VERSION_KEEP`）；老用户的历史积压在下次改图/重生成/恢复时被惰性裁剪。删整条笔记仍靠外键 `CASCADE`（`Entities.kt:52`）连带删除。
6. `versions` 的删除依赖数据库级联，但 `mapJson` 的父行删除走的是 `noteDao().delete(note)`（`ui/HomeScreen.kt:275`）；音频文件与分段缓存是**手工**删的（`HomeScreen.kt:264-272`），不走数据库——任何新增的删除入口若忘记这两步，就会留下孤儿文件（缓存清理包在 `try/catch (_: Exception)` 里，失败会静默）。
