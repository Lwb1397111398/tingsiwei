# 图示功能模块总览

## 模块职责

把已生成的「思路」二次加工成两层衍生内容（2026-11-14 起详解层入列，本模块实为「图示 + 详解」）：

1. **分段图示**（diagram 层）：AI 把思路拆成 3~8 个小节，给讲流程、对比、时间线、层级、判断的小节各配一张精炼图，复习时「一眼看懂关系」。
2. **详细讲解**（detail 层）：AI 对照录音转写原文，为每个小节补回被总结压缩掉的细节（定义/例子/法条/数字/老师强调点，200~600 字/节），录音里有、总结整个漏掉的话题以「补充小节」追加——解老板反馈的「概况不全面、遗漏多」。

两层都独立于生成主流程——失败不影响导图与思路，`diagramJson` 为空时思路页回退整段显示，`detailJson` 为空时卡片不可展开、听书回退读思路原文。

## 运作流程

**从哪来**：图示层两个触发口——①`runGenerate` 尾部自动接（`pipeline/NoteProcessor.kt`：生成成功且 READY 且有思路且开关开着才跑）；②思路页按钮手动触发（`DetailViewModel.regenDiagrams()` → `NoteProcessor.start(noteId, Kind.DIAGRAM)`，与生成/改写共用同笔记互斥锁）。详解层三个触发口——①`runGenerate` 尾部接力（生成 → 图示 → 详解串行，图示成功才接）；②`runDiagram` 成功后接力（`runDiagramIfEnabled` → 图示成功 → `runDetailIfEnabled`）；③AI 修改（`runRevise`）后 **thinking 真被改动才**自动重跑图示+详解（2026-11-14 起，顺带修复「AI 修改后图示过期」的既有脱节——改的只是导图结构时不动，省两次请求）；④思路页尾部「生成详细讲解 / 重新生成讲解」按钮手动触发（`DetailViewModel.regenDetail()` → `NoteProcessor.start(noteId, Kind.DETAIL, "manual")`）。两层都**有意不在 maybeRun/resumeStuck 里自动补**：那会让升级后打开每篇老笔记都烧 API。

**怎么处理（图示层）**：`llm/DiagramFlow.generate()`——输入 `notes.thinking` 全文，一次 LLM 调用（`LlmClient.chat` → `chatWithDegrade` 自带截断降级，输出预算 4096），system prompt 是 `Prompts.diagramSystem()`（图表选择规则改编自 feishu-visual-notes 的关系→图表映射；「宁缺毋滥」纪律改编自 diagram-design 的反图表清单：简单罗列不配图）。输出 JSON → `diagram/DiagramParser.parse()` 容错解析（剥代码围栏 → 花括号配对抽 JSON → 截断时逐段抢救完整段 → 逐段「最小可画」校验，不够画的 diagram 置 null）→ 格式不对时带 `diagramReminder` 重问一次 → 仍失败返回 false 静默结束。

**怎么处理（详解层，2026-11-14 新增）**：`llm/DetailFlow.generate()`——输入 = `notes.content` 转写原文全文 + 现有小节清单（`buildSectionsText`：「〔N〕标题 + 正文」逐节排列），一次 LLM 调用（输出预算 8192，`Prompts.detailSystem(allowExpand)` 纪律：忠实原文补回遗漏不编造、连贯自然段适合朗读、title 一字不差、补充小节 ≤3 个、拓展句标「（拓展）」；「允许 AI 拓展」开关与主生成共用）→ `DetailParser.parse()` 容错解析（与 DiagramParser 同一门派：剥围栏 → `extractJsonObject` 抽对象 → 截断抢救 `salvageArray(text,"items")` 丢最后半个条目救前面完整的）→ `markExtras(doc, sectionTitles)` 标题对齐（trim 匹配；对不上的标 extra=true；**一条都对不上返回 null**——模型重写整套标题时按补充全收会大量重复，宁失败不乱收）→ 格式不对带 `detailReminder` 重问一次 → 仍失败返回 false 静默结束。**输入超窗纪律**：自动链路（allowTruncate=false）装不下窗口（`Tokens.estimate(content)+system+sectionsText+8192 > LlmPolicy.windowFor`）直接跳过——截断的原文会让录音后半段整段漏讲，宁缺毋滥；手动按钮传 allowTruncate=true 硬来（`Tokens.fit` 截断，覆盖能覆盖的）。

**产出什么**：两层各落一列——①标准化图示 JSON 存 `notes.diagramJson`（Room v3→v4 新列，`MIGRATION_3_4`）；②详解 JSON 存 `notes.detailJson`（Room v4→v5 新列，`MIGRATION_4_5`，2026-11-14 起）。两层写库都只覆盖各自一列，**不动 updatedAt**（不把首页排序挤动，同 `setCategory`）。UI 侧 `DiagramParser.decode()` 读回 → `ThinkingSections` 渲染小节卡片（序号圆徽 + 标题 + 正文），卡片点击展开 `DetailParser.decode(n.detailJson)` 对齐标题的详解（`AnimatedVisibility` expand/shrink；2026-11-14 起整卡点击 = 展开详解，跳原声改为标题行右侧 ▶ 按钮，文字笔记/旧笔记无录音时 ▶ 自动不显示），`s.diagram` 非空时正文下面挂 `ui/components/DiagramViews.kt` 的 `DiagramView`，按 type 分发到 5 个渲染器（flow 纵向步骤块 / timeline 左轴圆点竖排 / matrix 列宽固定+横滚 / hierarchy 根块+分支 chips / decision 顶问题+左右两路径），全部 MaterialTheme 语义色自动适配深浅色。标记 `extra=true` 的补充小节（总结漏掉的整个话题）排在现有小节后，卡片带「补」徽章。思路页另有「图示卡片 / 文字版」双视图切换：文字版 = `composeFullText(doc)` 本地把各节「中文序号、标题、详解正文」拼成整篇（不额外调 AI），供听书与「复制全文」按钮；没详解时回退 `thinking` 原文。

**影响谁**：详情页思路标签的展示形态与交互（`ui/DetailScreen.kt`）；**听书与复制改读文字版**——`DetailViewModel.toggleTts()` 读 `DetailParser.decode(n.detailJson)?.let(::composeFullText) ?: n.thinking`（有详解读拼接全文，没详解回退思路原文），「复制全文」按钮复制同一份文本，两者同源同文；导出、AI 修改、版本快照仍用 `thinking`/`mapJson` 原文，零感知。

## 对外接口 / 被谁调用

- `DiagramFlow.generate(noteId, db, settings, onStage)`：仅 `pipeline/NoteProcessor` 调用（`runDiagram`，`Kind.DIAGRAM` 任务与 `runDiagramIfEnabled` 自动接力）。
- `DetailFlow.generate(noteId, db, settings, allowTruncate, onStage)`：仅 `pipeline/NoteProcessor` 调用（`runDetail`，自动链 `allowTruncate=false`、手动按钮 `allowTruncate=true`；`Kind.DETAIL` 任务）。
- `DiagramParser.parse/decode/encode`：`DiagramFlow`（LLM 原文）、`DetailScreen.ThinkingTab`（`remember(n.id, n.diagramJson)` 读库解析）、`DetailFlow`（取小节清单作详解骨架）。
- `DetailParser.parse/decode/encode`、`markExtras`、`composeFullText`：`DetailFlow`（解析+落库）、`DetailScreen.ThinkingTab`（读库解析 + 图标对齐 + 文字版拼接）、`DetailViewModel.toggleTts`/`regenDetail`（朗读文本、重生成比对）。
- `DiagramView(diagram)`：仅 `DetailScreen.ThinkingSections` 调用。
- `Prompts.diagramSystem/diagramUser/diagramTrimRule/diagramReminder`：仅 `DiagramFlow` 用；`Prompts.detailSystem/detailUser/detailTrimRule/detailReminder`：仅 `DetailFlow` 用。
- `NoteProcessor.Kind.DIAGRAM`：`DetailViewModel.regenDiagrams()` 发起；`Kind.DETAIL`：`DetailViewModel.regenDetail()` 发起（arg="manual"）；`start()` 的同笔记互斥对两者同样生效。
- 设置键 `diagrams_enabled`（`SettingsRepository`，默认开）：读侧 `DiagramFlow.generate` 与 `runDiagramIfEnabled`；写侧 `SettingsScreen.setDiagramsEnabled`。`details_enabled`（默认开）：读侧 `DetailFlow.generate` 与 `runDetailIfEnabled`；写侧 `SettingsScreen.setDetailsEnabled`。

- **数据层**：`notes.diagramJson` 列（Room v4）、`notes.detailJson` 列（Room v5）、`SettingsRepository.diagramsEnabled`/`detailsEnabled` 键。

## 关键数据结构

| 结构 | 位置 | 说明 |
| --- | --- | --- |
| `Diagram` | `diagram/DiagramData.kt` | 单一扁平结构：`type`（flow/timeline/matrix/hierarchy/decision，常量在 `DiagramType`）+ 各类型字段全带默认值；故意不用 sealed class 多态——LLM 输出 type 拼错/缺字段时扁平结构救回概率更高 |
| `DiagramSection` | 同上 | `title`（≤12 字）+ `text`（正文）+ `diagram?`（null = 不配图） |
| `DiagramDoc` | 同上 | `sections` 列表，落库编码 `{"sections":[…]}` |
| `notes.diagramJson` | Room v4 列 | null = 未生成/关闭/损坏；解析路径 `decode → parse` 同一条容错链 |
| `DetailItem` | `diagram/DetailData.kt` | `title`（与现有小节一字不差，供对齐与朗读段落提示）+ `detail`（200~600 字连贯自然段）+ `extra`（true = 总结漏掉的整个话题，界面挂「补」徽章；markExtras 以程序比对结果重算，不信任 LLM 自带值） |
| `DetailDoc` | 同上 | `items` 列表，落库编码 `{"items":[…]}` |
| `notes.detailJson` | Room v5 列 | null = 未生成/关闭/损坏/全对不上作废；解析路径 `decode → parse` 同一条容错链；**听书/复制的文字版由它拼出，与卡片展开的详解同源同文** |
| 最小可画条件 | `DiagramParser.usable` | flow/timeline/hierarchy ≥2 实质节点、hierarchy 另需 root 非空、decision 需 question + 至少一条路径、matrix ≥2 列 + ≥1 行；不满足 → diagram 置 null |

## 已知坑与约束

1. **截断抢救的括号配对必须跳过字符串内字符**：`extractJsonObject`/`salvageTruncated` 的 when 分支顺序是「转义 → 串内反斜杠 → 串内闭引号 → 串内其他字符跳过 → 开引号 → 括号」。曾两次踩坑：①少了「串内其他字符跳过」——字符串里的 `}` 被误计数，截断文本尾部的 `]}` 破坏配对导致 salvage 不触发；②把「串内其他字符跳过」放在闭引号分支前——闭引号被吞，字符串永不闭合，9 个测试全崩。**动这个 when 前先跑 `DiagramParserTest`**（20 例，含两个专守此坑的截断用例）。
2. **图示任务进行中详情页状态条不显示**（顶部横幅只在 TRANSCRIBING/GENERATING 出现）：进度文案走 `stages` 表，思路页在分段列表顶部用 `InlineNotice` 显示它；READY 态下 `busyStage` 只会来自图示化/版本恢复这类本地任务。
3. **重试按钮不进图示链路**：`DetailViewModel.retry()` 的三分支只管转写/生成；图示失败后用户走思路页「生成分段图示」按钮手动重画。
4. **设置开关关闭时的行为**：自动接力直接跳过（`runDiagramIfEnabled`）；手动按钮点了会弹提示「先到设置页打开」——宁可提示也不静默开跑烧 API。
5. **老笔记不自动补图**：升级安装后全部旧笔记 `diagramJson=null`，思路页保持整段显示 + 手动生成按钮；这是额度保护设计，不是缺陷。
6. **矩阵图列宽固定 dp + 横向滚动**：手机竖屏硬挤 3 列中文必出「每字竖排」，角列固定 72dp、数据列固定 100dp，外层 `horizontalScroll`。不能用 `weight` 分列宽——`horizontalScroll` 给 Row 无限主轴约束，`weight` 会算出 0 宽（实测踩过）。
7. LLM 输出 JSON 的质量因渠道而异：解析失败 → `diagramReminder` 重问一次 → 仍失败静默放弃，思路页回退整段——三道保险，最坏体验是「没图」而不是「坏图」。
8. **回退分支的布局结构是 Box(weight) 外包 + Text(fillMaxSize) 内填**（`ThinkingSections` 回退分支）：`weight` 是 ParentDataModifier，Column 只认**直接 child** 上的——写在被 `SelectionContainer` 包着的 Text 上会被 wrapper 挡住，weight 失效后 Text 的 `fillMaxSize` 占满整列，把「生成分段图示」按钮挤成 21dp 高贴在底部（实测踩过）；把 weight 移到 SelectionContainer 上仍然不行（wrapper 语义节点行为不可靠），最终用与 ThinkingTab 顶层同构的 `Box(Modifier.weight(1f))` 外包结构解决。改这段布局先在模拟器看按钮是否完整显示。
9. **详解依赖图示小节骨架**：`DetailFlow` 要求 `DiagramParser.decode(diagramJson)?.sections` 非空才跑——设置里关掉「思路分段图示」后详解自然不可用（两层开关独立，但详解实际以图示产出为输入）；手动重生成图示后旧 detailJson 仍对得上新小节标题则继续可用，对不上则卡片静默不可展开（extra 判定按标题 trim 匹配）。
10. **详解输出慢是常态不是卡死**：输出预算 8192 tokens（每节 200~600 字 × 最多 11 节），模拟器实测一轮 2 分钟以上才落库——别把「detailJson 迟迟不落」当失败诊断，先看 ProcessingService 是否还活着（活着 = 还在飞）。
11. **软失败完全静默**：`DetailFlow.ask` 两层 catch（`catch(_: Exception){return null}`）+ `markExtras` 返 null + 格式重问失败，全部只返回 false 不留痕——失败原因不可观测是既定取舍（不拖累主成果）；需要排查时用思路页手动按钮重试，其失败提示由 `DetailViewModel.regenDetail` 比对 detailJson 变化给出（人话：「详细讲解没生成出来…」）。
12. **`composeFullText` 的中文序号**：TTS 读「1、」会读成「一点」，所以序号用中文数字「一、二、…」；超过 20 节退回阿拉伯数字（`CnIndex` 表 + `cnIndex` 越界回退，差一 bug 曾被单测抓出——`CnIndex[n-1]` 不是 `CnIndex[n]`）。
