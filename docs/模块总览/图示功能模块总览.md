# 图示功能模块总览

## 模块职责

把已生成的「思路」二次加工成**分段卡片 + 解释性小图**：AI 把思路拆成 3~8 个小节，给讲流程、对比、时间线、层级、判断的小节各配一张精炼图，复习时「一眼看懂关系」。独立于生成主流程——图示失败不影响导图与思路，`diagramJson` 为空时思路页回退整段显示。

## 运作流程

**从哪来**：两个触发口——①`runGenerate` 尾部自动接（`pipeline/NoteProcessor.kt`：生成成功且 READY 且有思路且开关开着才跑）；②思路页按钮手动触发（`DetailViewModel.regenDiagrams()` → `NoteProcessor.start(noteId, Kind.DIAGRAM)`，与生成/改写共用同笔记互斥锁）。**有意不在 maybeRun/resumeStuck 里自动补图示**：那会让升级后打开每篇老笔记都烧一次 API。

**怎么处理**：`llm/DiagramFlow.generate()`——输入 `notes.thinking` 全文，一次 LLM 调用（`LlmClient.chat` → `chatWithDegrade` 自带截断降级，输出预算 4096），system prompt 是 `Prompts.diagramSystem()`（图表选择规则改编自 feishu-visual-notes 的关系→图表映射；「宁缺毋滥」纪律改编自 diagram-design 的反图表清单：简单罗列不配图）。输出 JSON → `diagram/DiagramParser.parse()` 容错解析（剥代码围栏 → 花括号配对抽 JSON → 截断时逐段抢救完整段 → 逐段「最小可画」校验，不够画的 diagram 置 null）→ 格式不对时带 `diagramReminder` 重问一次 → 仍失败返回 false 静默结束。

**产出什么**：标准化 JSON 存 `notes.diagramJson`（Room v3→v4 新列，`MIGRATION_3_4`）；写库只覆盖这一列，**不动 updatedAt**（不把首页排序挤动，同 `setCategory`）。UI 侧 `DiagramParser.decode()` 读回 → `ThinkingSections` 渲染小节卡片（序号圆徽 + 标题 + 正文；2026-11-14 起整卡可点 → `TimelineLocator.locate` 定位 → 跳录音对应位置听原声，标题行右侧淡色 PlayArrow 作提示，详见「详情页与生成编排模块总览.md」），`s.diagram` 非空时正文下面挂 `ui/components/DiagramViews.kt` 的 `DiagramView`，按 type 分发到 5 个渲染器（flow 纵向步骤块 / timeline 左轴圆点竖排 / matrix 列宽固定+横滚 / hierarchy 根块+分支 chips / decision 顶问题+左右两路径），全部 MaterialTheme 语义色自动适配深浅色。

**影响谁**：详情页思路标签的展示形态（`ui/DetailScreen.kt`）；首页排序不受影响；TTS 朗读、导出、AI 修改、版本快照全部继续用 `thinking` 原文，零感知。

## 对外接口 / 被谁调用

- `DiagramFlow.generate(noteId, db, settings, onStage)`：仅 `pipeline/NoteProcessor` 调用（`runDiagram`，`Kind.DIAGRAM` 任务与 `runDiagramIfEnabled` 自动接力）。
- `DiagramParser.parse/decode/encode`：`DiagramFlow`（LLM 原文）、`DetailScreen.ThinkingTab`（`remember(n.id, n.diagramJson)` 读库解析）。
- `DiagramView(diagram)`：仅 `DetailScreen.ThinkingSections` 调用。
- `Prompts.diagramSystem/diagramUser/diagramTrimRule/diagramReminder`：仅 `DiagramFlow` 用。
- `NoteProcessor.Kind.DIAGRAM`：`DetailViewModel.regenDiagrams()` 发起；`start()` 的同笔记互斥对 DIAGRAM 同样生效。
- 设置键 `diagrams_enabled`（`SettingsRepository`，默认开）：读侧 `DiagramFlow.generate` 与 `runDiagramIfEnabled`；写侧 `SettingsScreen.setDiagramsEnabled`。

## 依赖的上游模块

- **LLM 客户端与弹性层**（`LlmClient.chat` 的截断降级、`LlmError.Truncated.partialContent` 抢救）与**提示词**（`Prompts`）。
- **数据层**：`notes.diagramJson` 列（Room v4）、`SettingsRepository.diagramsEnabled` 键。
- **笔记处理宿主**：`Kind.DIAGRAM` 任务宿主与 `stages` 进度文案。
- **入口与导航**：`Spacing`/主题令牌、`ui/components/Common.kt` 的 `InlineNotice`（图示进行中提示条）。
- kotlinx-serialization（插件 + json 1.7.3，项目已有）。

## 关键数据结构

| 结构 | 位置 | 说明 |
| --- | --- | --- |
| `Diagram` | `diagram/DiagramData.kt` | 单一扁平结构：`type`（flow/timeline/matrix/hierarchy/decision，常量在 `DiagramType`）+ 各类型字段全带默认值；故意不用 sealed class 多态——LLM 输出 type 拼错/缺字段时扁平结构救回概率更高 |
| `DiagramSection` | 同上 | `title`（≤12 字）+ `text`（正文）+ `diagram?`（null = 不配图） |
| `DiagramDoc` | 同上 | `sections` 列表，落库编码 `{"sections":[…]}` |
| `notes.diagramJson` | Room v4 列 | null = 未生成/关闭/损坏；解析路径 `decode → parse` 同一条容错链 |
| 最小可画条件 | `DiagramParser.usable` | flow/timeline/hierarchy ≥2 实质节点、hierarchy 另需 root 非空、decision 需 question + 至少一条路径、matrix ≥2 列 + ≥1 行；不满足 → diagram 置 null |

## 已知坑与约束

1. **截断抢救的括号配对必须跳过字符串内字符**：`extractJsonObject`/`salvageTruncated` 的 when 分支顺序是「转义 → 串内反斜杠 → 串内闭引号 → 串内其他字符跳过 → 开引号 → 括号」。曾两次踩坑：①少了「串内其他字符跳过」——字符串里的 `}` 被误计数，截断文本尾部的 `]}` 破坏配对导致 salvage 不触发；②把「串内其他字符跳过」放在闭引号分支前——闭引号被吞，字符串永不闭合，9 个测试全崩。**动这个 when 前先跑 `DiagramParserTest`**（20 例，含两个专守此坑的截断用例）。
2. **图示任务进行中详情页状态条不显示**（顶部横幅只在 TRANSCRIBING/GENERATING 出现）：进度文案走 `stages` 表，思路页在分段列表顶部用 `InlineNotice` 显示它；READY 态下 `busyStage` 只会来自图示化/版本恢复这类本地任务。
3. **重试按钮不进图示链路**：`DetailViewModel.retry()` 的三分支只管转写/生成；图示失败后用户走思路页「生成分段图示」按钮手动重画。
4. **设置开关关闭时的行为**：自动接力直接跳过（`runDiagramIfEnabled`）；手动按钮点了会弹提示「先到设置页打开」——宁可提示也不静默开跑烧 API。
5. **老笔记不自动补图**：升级安装后全部旧笔记 `diagramJson=null`，思路页保持整段显示 + 手动生成按钮；这是额度保护设计，不是缺陷。
6. **矩阵图列宽固定 dp + 横向滚动**：手机竖屏硬挤 3 列中文必出「每字竖排」，角列固定 72dp、数据列固定 100dp，外层 `horizontalScroll`。不能用 `weight` 分列宽——`horizontalScroll` 给 Row 无限主轴约束，`weight` 会算出 0 宽（实测踩过）。
7. LLM 输出 JSON 的质量因渠道而异：解析失败 → `diagramReminder` 重问一次 → 仍失败静默放弃，思路页回退整段——三道保险，最坏体验是「没图」而不是「坏图」。
8. **回退分支的布局结构是 Box(weight) 外包 + Text(fillMaxSize) 内填**（`ThinkingSections` 回退分支）：`weight` 是 ParentDataModifier，Column 只认**直接 child** 上的——写在被 `SelectionContainer` 包着的 Text 上会被 wrapper 挡住，weight 失效后 Text 的 `fillMaxSize` 占满整列，把「生成分段图示」按钮挤成 21dp 高贴在底部（实测踩过）；把 weight 移到 SelectionContainer 上仍然不行（wrapper 语义节点行为不可靠），最终用与 ThinkingTab 顶层同构的 `Box(Modifier.weight(1f))` 外包结构解决。改这段布局先在模拟器看按钮是否完整显示。
