# 导出模块总览

## 模块职责

把一条笔记渲染成 Markdown 文档（标题 + 导图列表 + 思路 + 原文），写进应用缓存目录，再通过 `FileProvider` 授予一次性读权限并调起系统分享面板。

## 运作流程

**从哪来**：详情页顶栏「分享」按钮（`DetailScreen.kt:113-116`，可用条件是 `note?.mapJson != null`）→ `DetailViewModel.shareMarkdown()`（`DetailScreen.kt:584-591`）→ 先从 `noteDao().byId(noteId)` 读一条权威的 `NoteEntity`（`DetailScreen.kt:586`），上下文用 Application 级 `App.get()`（`DetailScreen.kt:587`）。

**怎么处理**：
1. 渲染 `buildMarkdown(note)`（`Exporter.kt:28-52`）：`note.mapJson` 非空时先用 `TreeText.fromMapData(it, note.virtualRoot)` 转成 TAB 缩进树文本（`Exporter.kt:29`；`TreeText.kt:101-107`，`virtualRoot` 为真时展开虚拟根，所以笔记标题不会和根节点重复），再 `TreeText.parse` 解析成 forest（`Exporter.kt:30`），交给 `forestToMarkdown` 递归输出 `- ` 无序列表、每层 2 个空格（`Exporter.kt:18-26`）。
2. 落盘 `exportMarkdown`（`Exporter.kt:60-64`）：`withContext(Dispatchers.IO)` 里 `File(cacheDir/shared, "<safeName(title)>.md").writeText(md, UTF_8)`，目录由 `exportsDir` 顺手 `mkdirs()`（`Exporter.kt:54-55`），文件名经 `safeName` 过滤非法字符并截到 40 字符（`Exporter.kt:57-58`）。
3. 分享 `shareFile`（`Exporter.kt:72-82`）：`FileProvider.getUriForFile(context, "${context.packageName}.fileprovider", file)` 换 `content://` URI（`Exporter.kt:73`）→ `ACTION_SEND` + `type = mime` + `EXTRA_STREAM` + `FLAG_GRANT_READ_URI_PERMISSION`（`Exporter.kt:74-77`）→ `Intent.createChooser(..., "分享")` 再补 `FLAG_ACTIVITY_NEW_TASK`（`Exporter.kt:79-81`，因为起点不是 Activity）。详情页传的 mime 是 `"text/markdown"`（`DetailScreen.kt:589`）。

**产出什么**：`cache/shared/<标题>.md` 一个临时文件 + 一次系统分享选择器；返回 `File` 供调用方链式使用（`Exporter.kt:60`、`66`）。

**影响谁**：只有接收方 App 读到的一份只读副本。导出对库内数据零改动，也不影响 `notes`/`versions`/`cache` 之外的任何位置；唯一的副作用是缓存里多出一个 md 文件且不会自动清理。

## 入口文件清单

- `app/src/main/java/com/tingsiwei/app/export/Exporter.kt` — 93 行 — 本模块唯一文件，单个 `object Exporter`（`Exporter.kt:15`）：`forestToMarkdown`（`Exporter.kt:17-26`）、`buildMarkdown`（`Exporter.kt:28-52`）、`exportsDir`（`Exporter.kt:54-55`）、`safeName`（`Exporter.kt:57-58`）、`exportMarkdown`（`Exporter.kt:60-64`）、`savePng`（`Exporter.kt:66-70`，当前无调用者）、`shareFile`（`Exporter.kt:72-82`）、`shareText`（`Exporter.kt:84-92`，当前无调用者）。
- `app/src/main/AndroidManifest.xml` — 与本模块相关的部分是 FileProvider 声明（`AndroidManifest.xml:35-43`），不是本模块的文件，但缺了就分享不出去。
- `app/src/main/res/xml/file_paths.xml` — 6 行 — 共享路径白名单（`file_paths.xml:3` 的 `cache-path name="shared" path="shared/"` 正是 `exportsDir` 的落点）。

## 对外接口 / 被谁调用

- `suspend exportMarkdown(context, note): File`（`Exporter.kt:60`）← `DetailScreen.kt:588`。
- `shareFile(context, file, mime)`（`Exporter.kt:72`）← `DetailScreen.kt:589`。
- `buildMarkdown(note): String`（`Exporter.kt:28`）：public，但当前只有同文件 `exportMarkdown` 调（`Exporter.kt:61`）。
- `forestToMarkdown(forest): String`（`Exporter.kt:18`）：public，当前只有 `buildMarkdown` 调（`Exporter.kt:37`）。

- 没有任何模块注册/订阅本模块；它不暴露 Flow，纯函数式工具对象。

## 依赖的上游模块

- 导图格式引擎：`TreeText.fromMapData`（`Exporter.kt:29`；`TreeText.kt:101-107`）、`TreeText.parse`（`Exporter.kt:30`；`TreeText.kt:28-49`）、类型 `TreeNote`（`Exporter.kt:8`；`TreeText.kt:14-17`）。本模块对导图的理解完全走这条引擎，不自己解析 mind-elixir JSON。
- 数据层实体：`NoteEntity`（`Exporter.kt:7`；`Entities.kt:24-43`），消费 `title`（`Exporter.kt:32`、`57-58`）、`mapJson` + `virtualRoot`（`Exporter.kt:29`）、`thinking`（`Exporter.kt:40-43`）、`content`（`Exporter.kt:46-49`）。
- AndroidX/框架：`FileProvider`（`Exporter.kt:6`）、`Intent`/`Uri`（`Exporter.kt:4-5`）、`Context.cacheDir`/`filesDir`、`kotlinx.coroutines` 的 `Dispatchers.IO` + `withContext`（`Exporter.kt:10-11`）。
- Manifest 侧契约：provider `androidx.core.content.FileProvider`、`android:authorities="${applicationId}.fileprovider"`、`exported="false"`、`grantUriPermissions="true"`、`meta-data android.support.FILE_PROVIDER_PATHS = @xml/file_paths`（`AndroidManifest.xml:35-43`）。
- 上游调用方（唯一）：`ui/DetailScreen.kt` 的 `DetailViewModel.shareMarkdown`（`DetailScreen.kt:584-591`）。不依赖 LLM、转写、录音、Room DAO 本身（传入的是已经查好的实体）。

## 关键数据结构

无独立数据结构，复用 `NoteEntity`（`Entities.kt:24-43`）。本模块真正「定义」的是输出文档的形状（`Exporter.kt:28-52`），按出现顺序：

- `# <note.title>` —— 恒有（`Exporter.kt:32`），后跟一个空行（`Exporter.kt:33`）。
- `## 思维导图` 段 —— 仅当 forest 非空时整段出现（`Exporter.kt:34-39`），正文是 `forestToMarkdown` 的 `- ` 无序列表，每层缩进 2 个空格（`Exporter.kt:20-21`）。
- `## 思路` 段 —— 仅当 `thinking` 非空白（`Exporter.kt:40-45`），正文原样插入。
- `## 原文` 段 —— 仅当 `content` 非空白（`Exporter.kt:46-50`），正文原样插入。

上面两个 `##` 级小节标题在代码里是 `appendLine("## 思维导图")` 这样的字面量（`Exporter.kt:35`、`41`、`47`），不满足条件时整节消失，不会留下空标题。收尾固定 `trimEnd() + "\n"`（`Exporter.kt:51`）。文件名形状 `<safeName(title)>.md`（`Exporter.kt:61`）与 `<safeName(title)>_<时间戳>.png`（`Exporter.kt:67`）；`safeName` 的替换集是 `\ / : * ? " < > | \n \r`（`Exporter.kt:58`）。URI 形状依赖 authority 约定 `${packageName}.fileprovider`（`Exporter.kt:73`）↔ `${applicationId}.fileprovider`（`AndroidManifest.xml:37`）。

## 已知坑与约束

1. **图片导出是空架子**：`Exporter` 的 KDoc 写着「导出 Markdown / 导图图片」（`Exporter.kt:14`），但 `savePng`（`Exporter.kt:66`）无任何调用者；上游整条链路也没接线——JS 侧有 `appExportPng`（`app/src/main/assets/mindmap/index.html:194-203`）、控制器有 `exportPng()`（`MindMapPanel.kt:62`），而 `MapBridge` 构造时没传 `onPngCb`（`MindMapPanel.kt:123-133`，默认空实现见 `MindMapPanel.kt:25`），详情页也只用了 `toCenter`/`undo`（`DetailScreen.kt:282-287`）。索引 README 第 24 行反倒只说「Markdown（导图+思路+原文）、FileProvider 分享」，与代码相符——不符的是文件内注释。
2. **`shareText` 也是死代码**（`Exporter.kt:84-92`），全工程无调用点。它走 `EXTRA_TEXT` 不经过 FileProvider，所以是另一条独立分享路径的预留口。
3. **坏 `mapJson` 会让分享直接抛**：`TreeText.fromMapData` 里 `json.parseToJsonElement(mapJson)` 不做容错（`TreeText.kt:102`），`buildMarkdown` 也没包 `runCatching`（`Exporter.kt:29`），调用点 `DetailScreen.kt:588` 同样没有 try/catch → 一条被写坏的导图会让「分享」崩掉。（`null` 是安全的，`Exporter.kt:29` 有 `.orEmpty()`。）
4. **`no activity can handle` 风险未处理**：`shareFile` 直接 `startActivity(chooser)`（`Exporter.kt:79-81`），既不 `resolveActivity` 也不捕获 `ActivityNotFoundException`；mime 传的是 `text/markdown`（`DetailScreen.kt:589`），接收方声明不认这个类型时就没有可选项。
5. **authority 靠字符串拼接对齐**：代码用 `"${context.packageName}.fileprovider"`（`Exporter.kt:73`），Manifest 用 `${applicationId}.fileprovider`（`AndroidManifest.xml:37`）。当前 `namespace` 与 `applicationId` 都是 `com.tingsiwei.app`（`app/build.gradle.kts:10`、`14`）且没有 `applicationIdSuffix`，所以相等；一旦加了 flavor/suffix，`packageName` 与 `applicationId` 就会分叉，`getUriForFile` 抛 `IllegalArgumentException`。
6. **`file_paths.xml` 有一条空挂规则**：`<files-path name="exports" path="exports/"/>`（`file_paths.xml:4`）在本工程没有任何生产者——全工程 grep 无 `filesDir/exports` 写入点，导出实际落在 `cacheDir/shared`（`Exporter.kt:55`）。留着会误导后来人往 `files/exports` 写文件（那条路径虽可分享，但没人清）。
7. **同标题笔记互相覆盖**：md 文件名只用标题（`Exporter.kt:61`），`safeName` 又截到 40 字符（`Exporter.kt:58`）→ 两条标题前 40 字符相同的笔记导出会写同一个文件；后一次分享拿到的是覆盖后的内容。png 因为带 `System.currentTimeMillis()` 不会（`Exporter.kt:67`）。
8. **缓存语义 = 文件不保证活到对方读完**：落在 `cacheDir`（`Exporter.kt:54-55`），系统清理或「清除缓存」会删掉它，且本模块从不主动清理（会一直堆积 md）。分享是即时读的，但接收方延迟加载（如某些云盘的后台上传）可能读空。
9. **只给读权限，不给保存路径**：链路是 `FLAG_GRANT_READ_URI_PERMISSION`（`Exporter.kt:77`）+ provider `exported=false, grantUriPermissions=true`（`AndroidManifest.xml:38-39`），Manifest 里没有 `WRITE_EXTERNAL_STORAGE`（`AndroidManifest.xml:4-8`），也没有任何 `CREATE_DOCUMENT`/MediaStore 写入。也就是说用户点「分享」只能送给别的 App，**无法直接保存到 Downloads/云盘以外的公共位置**（首页的 `OpenDocument` 是导入方向，`HomeScreen.kt:92`，不是导出）。
10. **导出的 Markdown 粘不回本 App**：导图段用 2 空格/层（`Exporter.kt:20-21`），而 `TreeText.parse` 对纯空格是按**每 4 个一层**算 depth 的（`TreeText.kt:36-40`），`- ` 列表符还会被 `cleanTopic` 剥掉（`TreeText.kt:41` → `TreeText.kt:54`）。所以把导出的 md 贴进「输入文字 / 粘贴导图」的「导入为导图」路径（`TextInputScreen.kt:126`）时，第 1、2 层会被压平成同一层，层级只保住一半。要可往返应导出 `TreeText.serialize` 的 TAB 缩进原文（`TreeText.kt:68-76`），本模块没有提供这条出口。
11. **导出前 topic 会被二次清洗**：`buildMarkdown` 的 forest 来自 `TreeText.parse(mapText)`（`Exporter.kt:30`），`parse` 对每行跑 `cleanTopic`——剥开头的 `-`/`•`/`#`/成对 `**`、`*`（`TreeText.kt:52-65`）。用户手输成「*重点」这类开头的节点，在 md 里会与 App 内画布显示不一致。
12. **`thinking` / `content` 原样插入，不做 Markdown 转义**（`Exporter.kt:43`、`49`）：正文里若本身有 `# `、`- `、表格或代码块，会破坏导出文档结构（导图段是工具生成的，正文段不是）。
13. **编码与换行**：`Charsets.UTF_8` 显式指定（`Exporter.kt:62`），换行由 `appendLine` 给 `\n`（`Exporter.kt:32` 等），无 BOM；`savePng` 用 `writeBytes`（`Exporter.kt:68`）。
14. **线程约定靠调用方遵守**：只有 `exportMarkdown`/`savePng` 自己切了 `Dispatchers.IO`（`Exporter.kt:60`、`66`），`buildMarkdown`（`Exporter.kt:28`）和 `shareFile`（`Exporter.kt:72`）是普通函数——`buildMarkdown` 对长原文是纯 CPU 字符串拼接，`shareFile` 是主线程 `startActivity`，目前调用方都在协程里（`DetailScreen.kt:585-590`，`viewModelScope.launch` 默认主线程调度 + `exportMarkdown` 内部转 IO），换调用点时别把 `buildMarkdown` 直接扔主线程。
