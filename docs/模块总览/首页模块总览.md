# 首页模块总览

## 模块职责

首页是应用启动后的落地页：列出全部笔记、按关键词过滤、在卡片上显示转写/生成的实时进度小字、长按删除，并用右下角 FAB 提供三个新建入口（现场录音 / 导入音频文件 / 输入文字），把用户送进对应页面或详情页。

## 运作流程

**从哪来**：`HomeViewModel` 订阅 Room 的 `notes` 表流 `db.noteDao().observeAll()`（`HomeScreen.kt:269`，DAO 定义在 `AppDatabase.kt:17-18`，按 `updatedAt DESC` 排序），与本地搜索词 `query`（`HomeScreen.kt:266`）做 `combine`。

**怎么处理**：搜索在内存里做——`query` 非空时对全表结果按 `title` 或 `content` 做忽略大小写 `contains` 过滤（`HomeScreen.kt:270-271`），再 `stateIn(viewModelScope, WhileSubscribed(5000))` 共享（`HomeScreen.kt:272`）。列表项渲染成 `NoteCard`（`HomeScreen.kt:166-171` → `HomeScreen.kt:194-243`），预览文案取 `thinking ?: content ?: "（还没有内容）"`（`HomeScreen.kt:209`），状态角标由 `StatusChip` 按 `NoteStatus` 字符串映射中文与色板（`HomeScreen.kt:246-262`）。**v1.5.0 起卡片多一行实时进度小字**：`HomeScreen` 顶层 `collectAsState()` 订阅 `NoteProcessor.stages`（`HomeScreen.kt:88`），把 `stages[note.id]` 传进 `NoteCard`（`:168`），当笔记处于 `TRANSCRIBING` 或 `GENERATING` 且有阶段文案时，在卡片底部渲染一行主题色小字（`HomeScreen.kt:232-240`）——文案来自笔记处理宿主模块的进度流（「正在解码音频…」「正在识别…已完成 X%…」「正在汇总生成导图…」等），转写/生成在后台跑、离开详情页也不中断。

**产出什么**：三类写库动作。
1. 点卡片 → `onOpenNote(note.id)`（`HomeScreen.kt:169`）。
2. 导入音频：`OpenDocument` 选 `audio/*`（`HomeScreen.kt:94-96`、`:133`）→ `HomeViewModel.importAudio` 把流拷进 `files/recordings/IMP_<时间戳>.m4a`（`HomeScreen.kt:297-302`）、从 `OpenableColumns.DISPLAY_NAME` 取标题（`HomeScreen.kt:305-308`）、用 `MediaMetadataRetriever` 取时长（`HomeScreen.kt:310-317`）、插入一条 `status=TRANSCRIBING, source=IMPORT` 的笔记（`HomeScreen.kt:319-329`，状态在 `:324`），**随即 `NoteProcessor.start(id, Kind.TRANSCRIBE)` 导入即开跑（`HomeScreen.kt:331`，v1.5.0 起，App 级协程离开页面不断）**，Snackbar 提示「导入成功！已开始转写并生成导图，点开笔记可看进度」（`HomeScreen.kt:332`）。
3. 长按卡片 → 弹确认框（`HomeScreen.kt:170`、`:179-191`）→ `HomeViewModel.delete` 四步清理（`HomeScreen.kt:274-291`）：先 `NoteProcessor.cancel(note.id)` 停掉还在跑的转写/生成任务（`:277`，避免它继续往已删除的笔记上写）、删录音文件（`:278-283`）、删该笔记的**分段落盘断点文件**——`SegmentStore(File(App.get().filesDir, "pipeline")).clear(note.id)`（`:286`，删的是 `files/pipeline/segments-<noteId>.json`，生成流水线的段成果断点，不清会留孤儿文件）、最后删库（`:289`）。

**影响谁**：`HomeScreen` 不 navigate，四个导航回调全部由 `AppNav` 注入（`AppNav.kt:22-27`：home → detail/{noteId}、record、textinput、settings）。导入/录音产生的笔记由笔记处理宿主模块在后台转写并自动接生成，详情页 `maybeRunPipeline()`（`ui/DetailScreen.kt:101`、`:507-510`）只是打开笔记时的兜底续跑入口之一。删除则会影响 `versions` 表（外键级联，`Entities.kt:47-54`）、`files/pipeline/segments-*.json` 断点文件（`SegmentStore.kt:91-96` 的 `clear`）与在跑的 `NoteProcessor` 任务。

## 关键数据结构

无独立数据结构，复用数据层 `NoteEntity`（`Entities.kt:24-43`）。本模块自有的运行时结构只有三个流和两个局部状态：

- `notes: StateFlow<List<NoteEntity>>`（`HomeScreen.kt:269-272`）：`combine(observeAll(), query)` 的产物，初始值 `emptyList()`。
- `query: MutableStateFlow<String>`（`HomeScreen.kt:266`）：直接由 `OutlinedTextField` 双向绑读写入（`HomeScreen.kt:147-148`）。
- `message: MutableStateFlow<String?>`（`HomeScreen.kt:267`）：一次性提示，`LaunchedEffect(message)` 弹出后立即手工置 null（`HomeScreen.kt:98-103`）。
- 局部 UI 状态：`fabOpen`（`HomeScreen.kt:91`）、`pendingDelete: NoteEntity?`（`HomeScreen.kt:92`，驱动删除确认框）。
- 进度徽章不是本模块的状态：`stages` 由 `NoteProcessor.stages`（`Map<Long, String>`，noteId → 文案）通过 `collectAsState()` 借进来（`HomeScreen.kt:88`），显示条件额外要求 `note.status` 为 `TRANSCRIBING/GENERATING`（`HomeScreen.kt:232`）。
- 导入落库的关键字段：`title`（文件名去扩展名截 40 字，`HomeScreen.kt:318`）、`status = TRANSCRIBING`、`source = IMPORT`、`audioPath`（绝对路径）、`durationMs`（`HomeScreen.kt:319-329`）。

## 已知坑与约束

1. **README 索引缺首页行的坑已解决**：2026-09-20 README 重写后「首页」已有独立索引行（现行 README 第 12 行），本条仅留档。`ui/` 下其余页面也全部入索引。
2. **搜索不是 SQL**：DAO 里备好了带 LIKE 的 `NoteDao.search(q)`（`AppDatabase.kt:29-30`），全工程 grep 无任何调用点；首页是在内存里过滤全表（`HomeScreen.kt:269-272`）。后果：笔记多时每次组合都拉全表；且只搜 `title` 与 `content`，搜不到 `thinking` 与导图节点文字。
3. **导入即开跑（v1.5.0 起，旧坑「导入 ≠ 转写」已消失）**：`importAudio` 落库后立即 `NoteProcessor.start(id, Kind.TRANSCRIBE)`（`HomeScreen.kt:331`），提示文案也明说「已开始转写并生成导图」（`:332`）；进度在首页卡片可见（`:232-240`），不必打开详情页。剩余的边角：若导入后 App 立刻被杀，重启时由 `resumeStuck()` 按 Room 状态拉起（`App.kt:22`；`pipeline/NoteProcessor.kt:89-104`）。
4. **同秒导入会撞文件名**：目标文件名固定 `IMP_yyyyMMdd_HHmmss.m4a`（`HomeScreen.kt:298-299`），一秒内两次导入会覆盖同一文件，两条笔记的 `audioPath` 指向同一路径，删除其中一条会把另一条的录音一起删（删除逻辑 `HomeScreen.kt:278-283` 不判断引用计数）。
5. **删除的失败被吞**：录音文件删除和断点清理都包在 `try/catch (_: Exception)` 里（`HomeScreen.kt:278-283`、`:285-288`），随后无条件 `db.noteDao().delete(note)`（`HomeScreen.kt:289`）→ 可能留下孤儿录音/孤儿断点文件，界面无任何反馈。`versions` 靠外键 CASCADE 清理（`Entities.kt:47-54`），前提是 Room 外键生效。
6. **删除与在飞任务的竞态窗口（静态推断，未实测）**：`delete` 先 `NoteProcessor.cancel`（`HomeScreen.kt:277`）再删库，但 cancel 只是发起取消，若此刻任务里恰有一次 `dao.update` 已经飞出，可能在已删除的笔记上多一次无效写（详见笔记处理宿主总览「已知坑」第 3 条）。
7. **导入结果不跳转**：插入拿到的 `id` 现在用于启动转写任务（`HomeScreen.kt:319`、`:331`），但导入成功仍只弹 Snackbar（`HomeScreen.kt:332`）、不跳详情页，用户得自己在列表里找那条新笔记。
8. **时长/标题是尽力而为**：`MediaMetadataRetriever` 异常整段被吞（`HomeScreen.kt:310-317`）→ `durationMs` 可能为 0，此时卡片不显示时长（`HomeScreen.kt:223-230`）；取不到 `DISPLAY_NAME` 时标题兜底为「导入的音频」（`HomeScreen.kt:304-307`）。
9. **`vm.message.value = null` 写在组合里**：`LaunchedEffect` 直接改 ViewModel 的流（`HomeScreen.kt:101`），属于「UI 反写状态」的写法，`message` 不是事件流而是可空状态流，重复值会被 `StateFlow` 去重（连续两次同样的提示文案不会二次弹出）。
10. **ViewModel 归属页面作用域**：`viewModel()` 未指定 store owner（`HomeScreen.kt:84`），落在 Navigation 回退栈条目上；`notes` 用 `WhileSubscribed(5000)`（`HomeScreen.kt:272`），离开首页 5 秒后停止收集，回到首页重新拉全表。
11. **`import` 顺序小瑕疵**：`com.tingsiwei.app.llm.SegmentStore` 被插在 `data.db` 的 import 之间（`HomeScreen.kt:58-61`），不影响编译，只是风格。
12. **空状态与文案硬编码**：空列表提示（`HomeScreen.kt:154-161`）、删除确认文案（`HomeScreen.kt:183`）、三个 FAB 菜单项（`HomeScreen.kt:119-142`）全部中文字面量内联，未走 `res/values/strings.xml`。
13. **长按即删除**：`onLongClick = { pendingDelete = note }`（`HomeScreen.kt:170`）是唯一的长按行为，没有多选、没有归档，误触风险靠确认框兜底（`HomeScreen.kt:179-191`）。
14. **`StatusChip` 的未知状态**：`else -> status to surfaceVariant`（`HomeScreen.kt:253`）会把原始英文枚举字面量直接显示出来，若上游新增状态而这里没跟上就会露馅。
15. **`DRAFT` 状态不显示进度小字**：显示条件钉死在 `TRANSCRIBING || GENERATING`（`HomeScreen.kt:232`）；SYSTEM 模式保存的 `DRAFT` 笔记由宿主直接进生成，等 `status` 变成 `GENERATING` 后徽章才出现，中间有一小段无进度的空窗。
