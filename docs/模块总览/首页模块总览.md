# 首页模块总览

## 模块职责

首页是应用启动后的落地页：列出全部笔记、按关键词过滤、长按删除，并用右下角 FAB 提供三个新建入口（现场录音 / 导入音频文件 / 输入文字），把用户送进对应页面或详情页。

## 运作流程

**从哪来**：`HomeViewModel` 订阅 Room 的 `notes` 表流 `db.noteDao().observeAll()`（`HomeScreen.kt:257`，DAO 定义在 `AppDatabase.kt:17-18`，按 `updatedAt DESC` 排序），与本地搜索词 `query`（`HomeScreen.kt:254`）做 `combine`。

**怎么处理**：搜索在内存里做——`query` 非空时对全表结果按 `title` 或 `content` 做忽略大小写 `contains` 过滤（`HomeScreen.kt:258-260`），再 `stateIn(viewModelScope, WhileSubscribed(5000))` 共享（`HomeScreen.kt:260`）。列表项渲染成 `NoteCard`（`HomeScreen.kt:164-168` → `HomeScreen.kt:193-231`），预览文案取 `thinking ?: content ?: "（还没有内容）"`（`HomeScreen.kt:206`），状态角标由 `StatusChip` 按 `NoteStatus` 字符串映射中文与色板（`HomeScreen.kt:234-242`）。

**产出什么**：三类写库动作。
1. 点卡片 → `onOpenNote(note.id)`（`HomeScreen.kt:166`）。
2. 导入音频：`OpenDocument` 选 `audio/*`（`HomeScreen.kt:92-94`、`131`）→ `HomeViewModel.importAudio` 把流拷进 `files/recordings/IMP_<时间戳>.m4a`（`HomeScreen.kt:283-288`）、从 `OpenableColumns.DISPLAY_NAME` 取标题（`HomeScreen.kt:290-294`）、用 `MediaMetadataRetriever` 取时长（`HomeScreen.kt:296-303`）、插入一条 `status=TRANSCRIBING, source=IMPORT` 的笔记（`HomeScreen.kt:305-315`），只在 Snackbar 提示结果（`HomeScreen.kt:316-318`）。
3. 长按卡片 → 弹确认框（`HomeScreen.kt:167`、`176-188`）→ `HomeViewModel.delete` 依次删录音文件、删该笔记的分段落盘成果 `SegmentStore.clear(note.id)`、删库（`HomeScreen.kt:262-277`）。

**影响谁**：`HomeScreen` 不 navigate，四个导航回调全部由 `AppNav` 注入（`AppNav.kt:22-27`：home → detail/{noteId}、record、textinput、settings）。导入的笔记不会被本页转写，转写与生成要等用户点开详情、由 `DetailViewModel.maybeRunPipeline()` 看到 `TRANSCRIBING + audioPath` 才续跑（`DetailScreen.kt:473-493`）。删除则会影响 `versions` 表（外键级联，`Entities.kt:47-54`）与 `files/pipeline/segments-*.json`（`SegmentStore.kt:69-74`）。

- `app/src/main/java/com/tingsiwei/app/ui/HomeScreen.kt` — 322 行 — 首页的全部内容：`HomeScreen` 组合函数（`HomeScreen.kt:77-189`）、`NoteCard` 列表卡片（`HomeScreen.kt:191-231`）、`StatusChip` 状态角标（`HomeScreen.kt:233-250`）、`HomeViewModel` 列表流 + 删除 + 音频导入（`HomeScreen.kt:252-322`）。本模块仅此一个文件。

## 关键数据结构

无独立数据结构，复用数据层 `NoteEntity`（`Entities.kt:24-43`）。本模块自有的运行时结构只有三个流和两个局部状态：

- `notes: StateFlow<List<NoteEntity>>`（`HomeScreen.kt:257-260`）：`combine(observeAll(), query)` 的产物，初始值 `emptyList()`。
- `query: MutableStateFlow<String>`（`HomeScreen.kt:254`）：直接由 `OutlinedTextField` 双向绑读写入（`HomeScreen.kt:145-146`）。
- `message: MutableStateFlow<String?>`（`HomeScreen.kt:255`）：一次性提示，`LaunchedEffect(message)` 弹出后立即手工置 null（`HomeScreen.kt:96-101`）。
- 局部 UI 状态：`fabOpen`（`HomeScreen.kt:89`）、`pendingDelete: NoteEntity?`（`HomeScreen.kt:90`，驱动删除确认框）。
- 导入落库的关键字段：`title`（文件名去扩展名截 40 字，`HomeScreen.kt:304`）、`status = TRANSCRIBING`、`source = IMPORT`、`audioPath`（绝对路径）、`durationMs`（`HomeScreen.kt:305-315`）。

## 已知坑与约束

1. **索引 README 没有「首页」这一条**：README 模块索引只到 `入口/导航 | MainActivity.kt、ui/AppNav.kt`（README 第 9 行），实际 `ui/` 下另有 4 个界面文件 1381 行（`HomeScreen.kt` 322 + `TextInputScreen.kt` 169 + `RecordScreen.kt` 212 + `DetailScreen.kt` 678）没有被索引列出，首页只是其中之一。
2. **搜索不是 SQL**：DAO 里备好了带 LIKE 的 `NoteDao.search(q)`（`AppDatabase.kt:26-27`），全工程 grep 无任何调用点；首页是在内存里过滤全表（`HomeScreen.kt:257-260`）。后果：笔记多时每次组合都拉全表；且只搜 `title` 与 `content`，搜不到 `thinking` 与导图节点文字。
3. **导入 ≠ 转写**：`importAudio` 只落一条 `TRANSCRIBING` 笔记（`HomeScreen.kt:310`），提示文案也明说「打开这条笔记就会开始转写并生成导图」（`HomeScreen.kt:316`）。若用户在详情页之外等结果，会永远等不到——触发点在 `DetailScreen.kt:473-493`。
4. **同秒导入会撞文件名**：目标文件名固定 `IMP_yyyyMMdd_HHmmss.m4a`（`HomeScreen.kt:284-285`），一秒内两次导入会覆盖同一文件，两条笔记的 `audioPath` 指向同一路径，删除其中一条会把另一条的录音一起删（删除逻辑 `HomeScreen.kt:264-269` 不判断引用计数）。
5. **删除的失败被吞**：文件删除和断点清理都包在 `try/catch (_: Exception)` 里（`HomeScreen.kt:265-269`、`271-274`），随后无条件 `db.noteDao().delete(note)`（`HomeScreen.kt:275`）→ 可能留下孤儿录音/孤儿断点文件，界面无任何反馈。`versions` 靠外键 CASCADE 清理（`Entities.kt:47-54`），前提是 Room 外键生效。
6. **导入结果不跳转**：`val id = db.noteDao().insert(...)`（`HomeScreen.kt:305`）取到的 id 之后没被使用，导入成功只弹 Snackbar（`HomeScreen.kt:316`），用户得自己在列表里找那条新笔记。
7. **时长/标题是尽力而为**：`MediaMetadataRetriever` 异常整段被吞（`HomeScreen.kt:297-303`）→ `durationMs` 可能为 0，此时卡片不显示时长（`HomeScreen.kt:220`）；取不到 `DISPLAY_NAME` 时标题兜底为「导入的音频」（`HomeScreen.kt:290-293`）。
8. **`vm.message.value = null` 写在组合里**：`LaunchedEffect` 直接改 ViewModel 的流（`HomeScreen.kt:99`），属于「UI 反写状态」的写法，`message` 不是事件流而是可空状态流，重复值会被 `StateFlow` 去重（连续两次同样的提示文案不会二次弹出）。
9. **ViewModel 归属页面作用域**：`viewModel()` 未指定 store owner（`HomeScreen.kt:83`），落在 Navigation 回退栈条目上；`notes` 用 `WhileSubscribed(5000)`（`HomeScreen.kt:260`），离开首页 5 秒后停止收集，回到首页重新拉全表。
10. **`import` 顺序小瑕疵**：`com.tingsiwei.app.llm.SegmentStore` 被插在两条 `data.db` import 之间（`HomeScreen.kt:58-61`），不影响编译，只是风格。
11. **空状态与文案硬编码**：空列表提示（`HomeScreen.kt:152-159`）、删除确认文案（`HomeScreen.kt:180`）、三个 FAB 菜单项（`HomeScreen.kt:120-139`）全部中文字面量内联，未走 `res/values/strings.xml`。
12. **长按即删除**：`onLongClick = { pendingDelete = note }`（`HomeScreen.kt:167`）是唯一的长按行为，没有多选、没有归档，误触风险靠确认框兜底（`HomeScreen.kt:176-188`）。
13. **`StatusChip` 的未知状态**：`else -> status to surfaceVariant`（`HomeScreen.kt:241`）会把原始英文枚举字面量直接显示出来，若上游新增状态而这里没跟上就会露馅。
