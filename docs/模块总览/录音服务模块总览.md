# 录音服务模块总览

## 模块职责

用 `MediaRecorder` 录一段 m4a/AAC 语音，靠进程级单例 `RecordSession` + 前台服务 `RecordService` 保证锁屏/切后台/离开页面都不中断，结束时把音频文件和一条待处理的笔记落库，并把后续转写交给 App 级任务宿主 `NoteProcessor` 接手。

## 运作流程

**从哪来**：首页路由 `record` 进 `RecordScreen`，用户点大号录音按钮（`ui/RecordScreen.kt:117-133`）→ 先查 `RECORD_AUDIO`（Android 13+ 连带申请 `POST_NOTIFICATIONS`，`ui/RecordScreen.kt:120-131`）→ `RecordViewModel.start()` 只是转发（`ui/RecordScreen.kt:207`）→ `RecordSession.start()`。

**怎么处理**：
1. `RecordSession.start()`（`record/RecordSession.kt:60-92`）在 `Dispatchers.Default` 协程里执行，先把 `isRecording` 置 true 占位防连点（`:65`），读一次设置里的转写方式（`:67`），然后 `Recorder(App.get()).start()`（`:68-69`）。
2. `Recorder.start()`（`record/Recorder.kt:32-60`）在 `filesDir/recordings/` 下按秒级时间戳建名 `REC_yyyyMMdd_HHmmss.m4a`（`:30`、`:35`），配 MediaRecorder（MIC 源 + m4a/AAC/16kHz/单声道/32kbps，`:43-48`），`prepare()` + `start()`，并用 `SystemClock.elapsedRealtime()` 起计时基准（`:56`）。
3. 起前台服务保活：`RecordService.start(App.get())`（`record/RecordSession.kt:76`）→ `startForegroundService` → `onStartCommand` 里 `startForeground(NOTIF_ID, …)`（`record/RecordService.kt:35-41`，Android 11+ 带 `FOREGROUND_SERVICE_TYPE_MICROPHONE`）。
4. 若转写方式是 `SYSTEM`，同时启动手机自带语音识别做边录边转（`record/RecordSession.kt:77` → `:156-161`）；识别结果通过 `recognizerCallback` 回写 `finalText`/`partialText`（`:45-58`）。
5. 一个 250ms 的 ticker 协程把 `Recorder.currentDurationMs()` 刷进 `durationMs` 状态流（`record/RecordSession.kt:78-84`）。
6. 暂停/继续：`RecordSession.pause()`/`resume()` 转调 `Recorder.pause()`/`resume()`（`record/Recorder.kt:62-86`，`MediaRecorder.pause()/resume()` + 用 `pauseStamp`/`pausedTotalMs` 把暂停时长从计时里扣掉），SYSTEM 模式下同时停/重启语音识别（`record/RecordSession.kt:97`、`:104`）。

**产出什么**：`RecordSession.stopAndSave()`（`record/RecordSession.kt:108-146`）→ `Recorder.stop()` 返回 `Pair(文件, 时长)`（`record/Recorder.kt:96-113`）→ 先取 `finalText` 快照（`:122`）→ `Dispatchers.IO` 里往 Room 插一条 `NoteEntity(title="录音 MM-dd HH:mm", source=RECORD, audioPath, durationMs, content=系统识别文本或 null, status=DRAFT/TRANSCRIBING)`（`:126-138`，状态分叉在 `:132`）→ **`NoteProcessor.start(id, NoteProcessor.Kind.TRANSCRIBE)` 把后续转写/生成交给 App 级宿主（`:140`，v1.5.0 起离开录音页也不中断）** → `saved.emit(noteId)`（`:141`）。

**影响谁**：`RecordScreen` 收集 `saved` 后 `onSaved(id)` 跳详情页（`ui/RecordScreen.kt:66-68`）；后续处理已归 `NoteProcessor` 宿主——详情页打开笔记时 `maybeRunPipeline()` → `NoteProcessor.maybeRun` 兜底续跑（`ui/DetailScreen.kt:101`、`:507-510`），App 启动时 `resumeStuck()` 拉起半路任务（`App.kt:22`）；首页删除笔记时先 `NoteProcessor.cancel` 停任务、再删音频文件与断点（`ui/HomeScreen.kt:277`、`:278-289`）；通知栏「完成」按钮回打本模块（见下）。

**通知栏「完成」按钮的回传链路**（一条完整闭环）：
`NotificationCompat.addAction(0, "完成", stopIntent)`（`record/RecordService.kt:68`）→ `PendingIntent.getService` 指向 `RecordService` 且 action=`com.tingsiwei.app.record.STOP`（`:54-58`）→ `onStartCommand` 判 `intent?.action == ACTION_STOP` → `RecordSession.stopAndSave()`（`:42-45`）→ `saved.emit(id)`（`record/RecordSession.kt:141`）→ 录音页 `LaunchedEffect` collect 后导航到 `detail/{noteId}`（`ui/RecordScreen.kt:66-68`）；随后 `finishSession()` 里 `RecordService.stop(App.get())` 撤通知（`record/RecordSession.kt:163-170`，`:169`）。注意 `RecordService.kt:44` 的 `stopSelf()` 与 `finishSession()` 的 `stopService()` 是双保险。

## 对外接口 / 被谁调用

- `Recorder`（实例类，一次录音一个）：`start(): File`、`pause()`、`resume()`、`stop(): Pair<File, Long>`、`cancel()`、`currentDurationMs(): Long`、`isRunning`、`isPaused`、`recordingsDir()`（`record/Recorder.kt:27-130`）。仅被 `RecordSession` 使用（`record/RecordSession.kt:68-69`、`:94-106`、`:113-114`、`:152`）。
- `RecordSession`（`object`，进程级）：状态流 `isRecording`/`isPaused`/`durationMs`/`partialText`/`finalText`/`error`/`transcribeMode`/`saved`（`record/RecordSession.kt:29-38`）；动作 `start()`/`pause()`/`resume()`/`stopAndSave()`/`cancelIfAny()`（`:60`、`:94`、`:101`、`:108`、`:148`）。调用方只有两处：`ui/RecordScreen.kt:192-211`（ViewModel 转发）与 `record/RecordService.kt:43`（通知栏「完成」）。
- `RecordService`（`Service`）：`companion` 里 `start(context)` / `stop(context)`（`record/RecordService.kt:77-83`），被 `RecordSession` 调用（`record/RecordSession.kt:76`、`:169`）。`onBind` 返回 null（`record/RecordService.kt:22`），不对外提供绑定。
- 本模块不向 `llm/`、`mindmap/` 暴露任何接口；它给下游的**契约**是三样：磁盘上的 m4a 文件路径 + `NoteEntity.audioPath`、一条状态为 `DRAFT`/`TRANSCRIBING` 的笔记、一次 `NoteProcessor.start(id, Kind.TRANSCRIBE)` 启动信号（`record/RecordSession.kt:140`）。

## 关键数据结构

**编码参数**（`record/Recorder.kt:43-48`，与索引 README 一致）：

| 项 | 值 | 证据 |
| --- | --- | --- |
| 容器 | `MPEG_4` → 扩展名 `.m4a` | `record/Recorder.kt:44`、`:35` |
| 编码器 | `AAC` | `record/Recorder.kt:45` |
| 采样率 | 16000 Hz | `record/Recorder.kt:46` |
| 声道 | 1（单声道） | `record/Recorder.kt:48` |
| 码率 | 32000 bps（约 14MB/小时） | `record/Recorder.kt:47`、注释 `:13` |
| 音源 | `AudioSource.MIC` | `record/Recorder.kt:43` |

- 计时三元组：`startStamp` / `pausedTotalMs` / `pauseStamp`，全部基于 `SystemClock.elapsedRealtime()`（单调时钟，不受改系统时间影响），`currentDurationMs() = now - startStamp - pausedTotalMs - (paused ? now - pauseStamp : 0)`（`record/Recorder.kt:23-25`、`:88-93`）。
- `Recorder.stop()` 的返回契约：`Pair<File, Long>` = 录音文件 + 暂停扣减后的时长（`record/Recorder.kt:96-113`）。
- `RecordSession` 状态：7 个 `MutableStateFlow`（`isRecording`/`isPaused`/`durationMs`/`partialText`/`finalText`/`error`/`transcribeMode`，`record/RecordSession.kt:29-35`）+ 1 个 `MutableSharedFlow<Long>(extraBufferCapacity = 1)`（`saved`，`:38`）；私有 `scope = CoroutineScope(SupervisorJob() + Dispatchers.Default)`（`:40`）。
- 保存落库的状态分叉：`status = if (content != null) NoteStatus.DRAFT else NoteStatus.TRANSCRIBING`（`record/RecordSession.kt:132`）——SYSTEM 识别出文字直接 `DRAFT` 进生成，否则 `TRANSCRIBING` 等离线转写；两种情况随后都 `NoteProcessor.start(id, Kind.TRANSCRIBE)`（`:140`），由宿主内部分支处理（`pipeline/NoteProcessor.kt:111-114`）。
- 文件契约：录音目录 `context.filesDir/recordings/`（`record/Recorder.kt:30`），文件名前缀 `REC_`；导入音频复用同一目录但前缀 `IMP_`（`ui/HomeScreen.kt:297-299`）。
- 通知契约：`CHANNEL_ID = "record_channel"`、`NOTIF_ID = 1001`、`ACTION_STOP = "com.tingsiwei.app.record.STOP"`，通道 `IMPORTANCE_LOW` + `setShowBadge(false)`（`record/RecordService.kt:27-32`、`:73-75`）；通知带 `setUsesChronometer(true)` 自走计时、`setOngoing(true)`、`setOnlyAlertOnce(true)`（`:63-66`）。
- 服务返回 `START_NOT_STICKY`（`record/RecordService.kt:46`）：进程被杀后系统不自动重建服务。

## 已知坑与约束

- **录音服务的职责在 v1.5.0 缩小了一半**：此前「保存后转写」靠详情页打开时触发，本模块的落库状态直接决定用户要不要手动干预；现在保存即 `NoteProcessor.start`（`record/RecordSession.kt:140`），本模块只当「状态机产出方」，转写与生成的编排全部在笔记处理宿主模块（见该总览的「已知坑」第 1 条：转写完自动接生成是耗时感知入口）。
- **暂停可能"假成功"**：`Recorder.pause()` 在机型不支持 `MediaRecorder.pause()` 时只 `catch` 后 `return`，**不置 `paused`**（`record/Recorder.kt:65-70`），但 `RecordSession.pause()` 无条件把 `isPaused.value = true` 并停掉语音识别（`record/RecordSession.kt:94-99`）→ 界面显示"已暂停"、计时照走、录音照录。`resume()` 同构（`record/Recorder.kt:76-86` 与 `record/RecordSession.kt:101-106`）。
- **注释与实际下限不符**：`record/Recorder.kt:14` 写"支持暂停/继续（Android 7.0+）"，但工程 `minSdk = 26`（Android 8.0，`app/build.gradle.kts:17`），API 层面无需判版本；能否暂停只取决于机型实现。
- **stop 失败即整段丢失**：`Recorder.stop()` 里 `MediaRecorder.stop()` 抛异常（录音过短等）会先 `outFile?.delete()` 再上抛（`record/Recorder.kt:101-110`）；`RecordSession` 只置 `error` 并 `finishSession()`，**不建笔记**（`record/RecordSession.kt:113-119`）→ 文件已删、库里无记录，用户拿不到任何东西。
- **通知栏「完成」只在进程活着时有效**：`stopAndSave()` 首行 `if (!isRecording.value) return`（`record/RecordSession.kt:109`）、`recorder` 也为 null，所以进程被系统回收后点通知什么也不会发生（服务 `START_NOT_STICKY`，`record/RecordService.kt:46`，无恢复逻辑）。
- **`saved` 事件会丢**：`saved` 是 `MutableSharedFlow`（replay=0，`record/RecordSession.kt:38`），唯一订阅者是录音页（`ui/RecordScreen.kt:66-68`）。从通知栏点「完成」而当前不在录音页时，笔记正常入库且转写任务已交给宿主（`:140`），只是没人接这个 id、不会自动跳详情。
- **录音途中改设置不生效**：`transcribeMode` 只在 `start()` 里读一次（`record/RecordSession.kt:67`）；`RecordViewModel.init` 另读一次（`ui/RecordScreen.kt:201-205`），但正在录的那一段始终按启动时的模式走。
- **文件名精确到秒**：`REC_yyyyMMdd_HHmmss.m4a`（`record/Recorder.kt:35`）同一秒内两次 `start()` 会重名，旧文件被覆盖（`MediaRecorder` 直接往该路径写）。
- **无录音长度/大小上限、无音频焦点处理**：没有 `setMaxDuration`/`setMaxFileSize`（`record/Recorder.kt:43-49` 只配编码参数），也没有 `AudioManager`/`AudioFocusRequest`；来电等打断完全靠机型行为。
- **权限要求**（缺一即崩或录不到音）：运行时 `RECORD_AUDIO`（`ui/RecordScreen.kt:120-131` 才申请；若外部直接调 `RecordSession.start()` 会走到 `MediaRecorder.prepare()` 抛异常，被 `record/RecordSession.kt:85-90` 兜成 error 文案）；清单侧 `FOREGROUND_SERVICE` + `FOREGROUND_SERVICE_MICROPHONE`（`AndroidManifest.xml:6-7`）；Android 13+ 未授 `POST_NOTIFICATIONS` 时通知不可见，因而失去「完成」入口，但前台服务本身仍能保活。Android 11+ 的 `startForeground` 必须带 microphone type（`record/RecordService.kt:37-39`）。
- **单例即进程**：`RecordSession` 是 `object`，状态不跨进程、不落盘；`App.get()` 依赖 `android:name=".App"`（`AndroidManifest.xml:19`），否则创建即 NPE。
- **SYSTEM 模式的尾句会丢**：`stopAndSave()` 先 `sysRecognizer?.stop()` 再 `rec.stop()`（`record/RecordSession.kt:111-114`），正在识别而未回调 `onResults` 的最后一句不会进来（详见「系统识别模块总览」）。
- **磁盘只增不减**：录音文件只有删除笔记时才删（`ui/HomeScreen.kt:278-283`），取消录音才 `Recorder.cancel()` 删文件（`record/Recorder.kt:116-130`）；没有容量水位或过期清理，按 14MB/小时长期累积。
- **边录边转与录音同时占麦**：`Recorder`（`record/RecordSession.kt:68-69`）与 `SpeechRecognizer`（`:77`）并行工作，Android 10+ 的第二路录音策略由厂商决定，实测行为存在机型差异（本模块只负责按代码顺序发起，见「系统识别模块总览」的对应条目）。
- **保存后的写库与任务启动共享一个协程**：`stopAndSave` 里 insert、`NoteProcessor.start`、`saved.emit` 都在同一个 `Dispatchers.IO` 协程（`record/RecordSession.kt:124-145`），insert 抛异常时任务不会启动（`try` 包住全段，`:142-144`）——反过来也意味着崩溃发生在 insert 之后、start 之前会留下一条 `TRANSCRIBING` 笔记，靠 App 下次启动的 `resumeStuck()` 拉起（`App.kt:22`）。
