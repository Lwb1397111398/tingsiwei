# 录音服务模块总览

## 模块职责

用 `MediaRecorder` 录一段 m4a/AAC 语音，靠进程级单例 `RecordSession` + 前台服务 `RecordService` 保证锁屏/切后台/离开页面都不中断，结束时把音频文件和一条待转写的笔记落库。

## 运作流程

**从哪来**：首页路由 `record` 进 `RecordScreen`，用户点大号录音按钮（`ui/RecordScreen.kt:117-133`）→ 先查 `RECORD_AUDIO`（Android 13+ 连带申请 `POST_NOTIFICATIONS`，`ui/RecordScreen.kt:120-131`）→ `RecordViewModel.start()` 只是转发（`ui/RecordScreen.kt:207`）→ `RecordSession.start()`。

**怎么处理**：
1. `RecordSession.start()`（`record/RecordSession.kt:59-91`）在 `Dispatchers.Default` 协程里执行，先把 `isRecording` 置 true 占位防连点（`:64`），读一次设置里的转写方式（`:66`），然后 `Recorder(App.get()).start()`。
2. `Recorder.start()`（`record/Recorder.kt:32-60`）在 `filesDir/recordings/` 下按秒级时间戳建名 `REC_yyyyMMdd_HHmmss.m4a`（`:30`、`:35`），配 MediaRecorder（MIC 源 + m4a/AAC/16kHz/单声道/32kbps，`:43-48`），`prepare()` + `start()`，并用 `SystemClock.elapsedRealtime()` 起计时基准（`:56`）。
3. 起前台服务保活：`RecordService.start(App.get())`（`record/RecordSession.kt:75`）→ `startForegroundService` → `onStartCommand` 里 `startForeground(NOTIF_ID, …)`（`record/RecordService.kt:35-41`，Android 11+ 带 `FOREGROUND_SERVICE_TYPE_MICROPHONE`）。
4. 若转写方式是 `SYSTEM`，同时启动手机自带语音识别做边录边转（`record/RecordSession.kt:76` → `:153-158`）；识别结果通过 `recognizerCallback` 回写 `finalText`/`partialText`（`:44-57`）。
5. 一个 250ms 的 ticker 协程把 `Recorder.currentDurationMs()` 刷进 `durationMs` 状态流（`record/RecordSession.kt:77-83`）。
6. 暂停/继续：`RecordSession.pause()`/`resume()` 转调 `Recorder.pause()`/`resume()`（`record/Recorder.kt:62-86`，`MediaRecorder.pause()/resume()` + 用 `pauseStamp`/`pausedTotalMs` 把暂停时长从计时里扣掉），SYSTEM 模式下同时停/重启语音识别（`record/RecordSession.kt:96`、`:103`）。

**产出什么**：`RecordSession.stopAndSave()`（`record/RecordSession.kt:107-143`）→ `Recorder.stop()` 返回 `Pair(文件, 时长)`（`record/Recorder.kt:96-113`）→ 先取 `finalText` 快照（`:121`）→ `Dispatchers.IO` 里往 Room 插一条 `NoteEntity(title="录音 MM-dd HH:mm", source=RECORD, audioPath, durationMs, content=系统识别文本或 null, status=DRAFT/TRANSCRIBING)`（`:123-138`）→ `saved.emit(noteId)`。

**影响谁**：`RecordScreen` 收集 `saved` 后 `onSaved(id)` 跳详情页（`ui/RecordScreen.kt:66-68`）；详情页 `DetailViewModel.maybeRunPipeline()` 见到 `status=TRANSCRIBING && content 为空 && audioPath != null` 就自动跑离线转写（`ui/DetailScreen.kt:479`、`:511-537`）；`status=DRAFT` 则直接进生成；首页删除笔记时连带删掉音频文件（`ui/HomeScreen.kt:264-269`）；通知栏「完成」按钮回打本模块（见下）。

**通知栏「完成」按钮的回传链路**（一条完整闭环）：
`NotificationCompat.addAction(0, "完成", stopIntent)`（`record/RecordService.kt:68`）→ `PendingIntent.getService` 指向 `RecordService` 且 action=`com.tingsiwei.app.record.STOP`（`:54-58`）→ `onStartCommand` 判 `intent?.action == ACTION_STOP` → `RecordSession.stopAndSave()`（`:42-45`）→ `saved.emit(id)`（`record/RecordSession.kt:138`）→ 录音页 `LaunchedEffect` collect 后导航到 `detail/{noteId}`（`ui/RecordScreen.kt:66-68`）；随后 `finishSession()` 里 `RecordService.stop(App.get())` 撤通知（`record/RecordSession.kt:160-167`）。注意 `RecordService.kt:44` 的 `stopSelf()` 与 `finishSession()` 的 `stopService()` 是双保险。

## 对外接口 / 被谁调用

- `Recorder`（实例类，一次录音一个）：`start(): File`、`pause()`、`resume()`、`stop(): Pair<File, Long>`、`cancel()`、`currentDurationMs(): Long`、`isRunning`、`isPaused`、`recordingsDir()`（`record/Recorder.kt:27-130`）。仅被 `RecordSession` 使用（`record/RecordSession.kt:67-68`、`:93-105`、`:112-113`、`:149`）。
- `RecordSession`（`object`，进程级）：状态流 `isRecording`/`isPaused`/`durationMs`/`partialText`/`finalText`/`error`/`transcribeMode`/`saved`（`record/RecordSession.kt:28-37`）；动作 `start()`/`pause()`/`resume()`/`stopAndSave()`/`cancelIfAny()`（`:59`、`:93`、`:100`、`:107`、`:145`）。调用方只有两处：`ui/RecordScreen.kt:192-211`（ViewModel 转发）与 `record/RecordService.kt:43`（通知栏「完成」）。
- `RecordService`（`Service`）：`companion` 里 `start(context)` / `stop(context)`（`record/RecordService.kt:77-83`），被 `RecordSession` 调用（`record/RecordSession.kt:75`、`:166`）。`onBind` 返回 null（`record/RecordService.kt:22`），不对外提供绑定。
- 本模块不向 `llm/`、`mindmap/` 暴露任何接口；它给下游的**唯一契约**是磁盘上的 m4a 文件路径 + `NoteEntity.audioPath`。

## 关键数据结构

**编码参数**（`record/Recorder.kt:43-48`，与索引 README 第 17 行一致）：

| 项 | 值 | 证据 |
| --- | --- | --- |
| 容器 | `MPEG_4` → 扩展名 `.m4a` | `record/Recorder.kt:44`、`:35` |
| 编码器 | `AAC` | `record/Recorder.kt:45` |
| 采样率 | 16000 Hz | `record/Recorder.kt:46` |
| 声道 | 1（单声道） | `record/Recorder.kt:48` |
| 码率 | 32000 bps（约 14MB/小时） | `record/Recorder.kt:47`、注释 `:13` |
| 音源 | `AudioSource.MIC` | `record/Recorder.kt:43` |

- 计时三元组：`startStamp` / `pausedTotalMs` / `pauseStamp`，全部基于 `SystemClock.elapsedRealtime()`（单调时钟，不受改系统时间影响），`currentDurationMs() = now - startStamp - pausedTotalMs - (paused ? now - pauseStamp : 0)`（`record/Recorder.kt:23-25`、`:88-93`）。
- `Recorder.stop()` 的返回契约：`Pair<File, Long>` = 录音文件 + 暂停扣减后的时长（`record/Recorder.kt:96-113`）。
- `RecordSession` 状态：8 个 `MutableStateFlow` + 1 个 `MutableSharedFlow<Long>(extraBufferCapacity = 1)`（`record/RecordSession.kt:28-37`）；私有 `scope = CoroutineScope(SupervisorJob() + Dispatchers.Default)`（`:39`）。
- 文件契约：录音目录 `context.filesDir/recordings/`（`record/Recorder.kt:30`），文件名前缀 `REC_`；导入音频复用同一目录但前缀 `IMP_`（`ui/HomeScreen.kt:283-285`）。
- 通知契约：`CHANNEL_ID = "record_channel"`、`NOTIF_ID = 1001`、`ACTION_STOP = "com.tingsiwei.app.record.STOP"`，通道 `IMPORTANCE_LOW` + `setShowBadge(false)`（`record/RecordService.kt:27-32`、`:73-75`）；通知带 `setUsesChronometer(true)` 自走计时、`setOngoing(true)`、`setOnlyAlertOnce(true)`（`:63-66`）。
- 服务返回 `START_NOT_STICKY`（`record/RecordService.kt:46`）：进程被杀后系统不自动重建服务。

## 已知坑与约束

- **索引归属缺失**：README 索引第 17 行「录音」只点了 `Recorder.kt` 一个文件，实际本模块还有 `record/RecordSession.kt`（168 行，进程级会话状态机与落库）和 `record/RecordService.kt`（85 行，前台服务与通知），本文档予以补上。README 第 21 行的「系统识别」宿主逻辑其实也在 `RecordSession.kt`（`:44-57`、`:76`、`:103`、`:153-158`）。
- **暂停可能"假成功"**：`Recorder.pause()` 在机型不支持 `MediaRecorder.pause()` 时只 `catch` 后 `return`，**不置 `paused`**（`record/Recorder.kt:65-70`），但 `RecordSession.pause()` 无条件把 `isPaused.value = true` 并停掉语音识别（`record/RecordSession.kt:93-98`）→ 界面显示"已暂停"、计时照走、录音照录。`resume()` 同构（`record/Recorder.kt:76-86` 与 `record/RecordSession.kt:100-105`）。
- **注释与实际下限不符**：`record/Recorder.kt:14` 写"支持暂停/继续（Android 7.0+）"，但工程 `minSdk = 26`（Android 8.0，`app/build.gradle.kts:15`），API 层面无需判版本；能否暂停只取决于机型实现。
- **stop 失败即整段丢失**：`Recorder.stop()` 里 `MediaRecorder.stop()` 抛异常（录音过短等）会先 `outFile?.delete()` 再上抛（`record/Recorder.kt:101-110`）；`RecordSession` 只置 `error` 并 `finishSession()`，**不建笔记**（`record/RecordSession.kt:112-118`）→ 文件已删、库里无记录，用户拿不到任何东西。
- **通知栏「完成」只在进程活着时有效**：`stopAndSave()` 首行 `if (!isRecording.value) return`（`record/RecordSession.kt:108`）、`recorder` 也为 null，所以进程被系统回收后点通知什么也不会发生（服务 `START_NOT_STICKY`，`record/RecordService.kt:46`，无恢复逻辑）。
- **`saved` 事件会丢**：`saved` 是 `MutableSharedFlow`（replay=0，`record/RecordSession.kt:37`），唯一订阅者是录音页（`ui/RecordScreen.kt:66-68`）。从通知栏点「完成」而当前不在录音页时，笔记正常入库但没人接这个 id，不会自动跳详情。
- **录音途中改设置不生效**：`transcribeMode` 只在 `start()` 里读一次（`record/RecordSession.kt:66`）；`RecordViewModel.init` 另读一次（`ui/RecordScreen.kt:203`），但正在录的那一段始终按启动时的模式走。
- **文件名精确到秒**：`REC_yyyyMMdd_HHmmss.m4a`（`record/Recorder.kt:35`）同一秒内两次 `start()` 会重名，旧文件被覆盖（`MediaRecorder` 直接往该路径写）。
- **无录音长度/大小上限、无音频焦点处理**：没有 `setMaxDuration`/`setMaxFileSize`（`record/Recorder.kt:43-49` 只配编码参数），也没有 `AudioManager`/`AudioFocusRequest`；来电等打断完全靠机型行为。
- **权限要求**（缺一即崩或录不到音）：运行时 `RECORD_AUDIO`（`ui/RecordScreen.kt:120-131` 才申请；若外部直接调 `RecordSession.start()` 会走到 `MediaRecorder.prepare()` 抛异常，被 `record/RecordSession.kt:84-89` 兜成 error 文案）；清单侧 `FOREGROUND_SERVICE` + `FOREGROUND_SERVICE_MICROPHONE`（`AndroidManifest.xml:6-7`）；Android 13+ 未授 `POST_NOTIFICATIONS` 时通知不可见，因而失去「完成」入口，但前台服务本身仍能保活。Android 11+ 的 `startForeground` 必须带 microphone type（`record/RecordService.kt:37-39`）。
- **单例即进程**：`RecordSession` 是 `object`，状态不跨进程、不落盘；`App.get()` 依赖 `android:name=".App"`（`AndroidManifest.xml:11`），否则创建即 NPE。
- **SYSTEM 模式的尾句会丢**：`stopAndSave()` 先 `sysRecognizer?.stop()` 再 `rec.stop()`（`record/RecordSession.kt:110-113`），正在识别而未回调 `onResults` 的最后一句不会进来（详见「系统识别模块总览」）。
- **磁盘只增不减**：录音文件只有删除笔记时才删（`ui/HomeScreen.kt:264-269`），取消录音才 `Recorder.cancel()` 删文件（`record/Recorder.kt:116-130`）；没有容量水位或过期清理，按 14MB/小时长期累积。
- **边录边转与录音同时占麦**：`Recorder`（`record/RecordSession.kt:67-68`）与 `SpeechRecognizer`（`:76`）并行工作，Android 10+ 的第二路录音策略由厂商决定，实测行为存在机型差异（本模块只负责按代码顺序发起，见「系统识别模块总览」的对应条目）。
