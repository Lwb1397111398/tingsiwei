# 分类与总导图模块总览

## 模块职责

让用户把笔记归入自建分类（名字由用户定：课程、当事人、项目都行），分类内按事件时间排序；并把一个分类下所有已生成的导图**拼接**成一幅按时间排好分支的「分类总导图」（纯本地、零 AI 调用、内容零丢失），可选「AI 优化整合」把多篇大纲融合去重成一篇固化笔记。2026-11-07 新增。

## 运作流程

**分类从哪来**：用户在分类管理页（`ui/CategoryManageScreen.kt`，路由 `categorymanage`）或任意分类选择器里输入名字 → `CategoryDao.insert`（`sortOrder` = 当前最大值 +1，新分类排末尾）。

**笔记怎么归入**（三个入口 + 一个补改入口）：
1. 录音：首页当前筛选的分类经导航参数（`record?categoryId=`，-1 表示不归类）传进录音页 → 顶部「将归入：×」chip 可改（弹 `CategoryPickerSheet`）→ `RecordSession.stopAndSave(categoryId)` 落库。
2. 导入音频：`HomeViewModel.importAudio` 内部读 `filter.value`（>0 才带），导入即归入；snackbar 提示「已归入「×」」。
3. 文字录入：与录音同构（`textinput?categoryId=` + 保存时带上）。
4. 事后改：首页长按笔记 → 菜单「归类到…」→ `CategoryPickerSheet` → `HomeViewModel.moveTo` → `NoteDao.setCategory`（**不动 updatedAt**，避免「全部」视图排序跳动）；详情页顶部也有同款分类标签。

**首页怎么展示**：`CategoryBar`（`ui/HomeScreen.kt`）横向 chip 条——「全部」+ 各分类（`CategoryWithCount`：成员数，SQL 排除 MERGED）+「未分类」+「管理」入口；筛选状态 `HomeViewModel.filter`（null=全部、`FILTER_UNCATEGORIZED=-1`=未分类、>0=分类 id），驱动列表查询、搜索范围、顶栏副标题、新建入口继承。卡片上有分类色点徽标（`CategoryUi.color(id)`：8 色按 id 取模，不存库）。选中具体分类时列表顶部固定「分类总导图」入口卡（`CategoryMapCard`）。

**总导图怎么拼**（`mindmap/CategoryMerger.kt`）：`NoteDao.observeReadyWithMapInCategory`（status=READY 且有 mapJson，`createdAt` 正序）→ 每篇 `TreeText.fromMapData` 还原缩进树 → 包一层「M月d日 · 标题」分支（换行压空格、标题截 30 字）→ 全部挂到以分类名为根的单根 forest → 复用现成 `TreeText.toMapData` 产出 mind-elixir JSON。在 `ui/CategoryMapScreen.kt`（路由 `categorymap/{categoryId}`）用 `MindMapPanel` 只读渲染；订阅式现拼——分类里有笔记生成完成会自动重拼，新课录完自动进图。

**AI 优化整合**（`llm/CategoryMergeFlow.kt`，只在用户点按钮时触发）：各篇大纲按时间正序拼成「### 日期 标题 + TAB 缩进大纲」→ 整体超窗口 55% 时逐篇砍深度（3 层→2 层→1 层，`pruneDepth`）→ `Prompts.mergeCategorySystem`（融合去重、保术语数字、按知识逻辑重组）走 `LlmClient.chat` 流式调用 → `LlmOutputParser.parse` → `TreeText.toMapData` → 落库为 `source=MERGED` 的笔记（标题「{分类名}·总导图」）；已有 MERGED 笔记则覆盖（覆盖前存版本快照，`pruneTo` 封顶 20 份与 Generator 同规矩），完成后跳详情页。

**分类删除**（`CategoryManageScreen` 删除确认后）：`db.withTransaction` 三步——`deleteMergedInCategory`（MERGED 总导图随分类删）→ `detachNotesInCategory`（普通笔记 categoryId 置 null 回「未分类」）→ `categoryDao().delete`。**笔记与录音文件绝不删**。

## 对外接口 / 被谁调用

- `CategoryPickerSheet(current, onDismiss, onPick)`：`RecordScreen`、`TextInputScreen`、`DetailScreen.CategoryTag`、`HomeScreen`（长按归类）四处调用；自足读 `categoryDao().observeAll()` 与新建。
- `CategoryMerger.merge(notes, categoryName): Result?`：`CategoryMapScreen` 调用；`CategoryMergeFlow.buildInput` 也用 `branchTopic`。
- `CategoryMergeFlow(db, settings).run(categoryId, onStage): Long`：仅 `CategoryMapScreen` 的按钮调用，返回笔记 id 供跳详情；失败抛 `LlmException`（中文 message 直接展示）。
- 数据侧接口（`NoteDao`/`CategoryDao` 新方法）见数据层总览；`FILTER_UNCATEGORIZED=-1` 哨兵定义在 `HomeViewModel.companion`，`AppNav` 路由参数也用 -1 表示「不归类」。

## 依赖的上游模块

- 数据层（三张表 + DAO）；导图格式引擎（`TreeText`/`TreeNote`/`toMapData`）；LLM 输出解析（`LlmOutputParser`）；LLM 客户端（`LlmClient`/`Prompts`/`LlmPolicy.Tokens`）；导图画布（`MindMapPanel` 只读复用）；主题令牌（`Spacing`/`Motion`）。
- 被首页 / 录音页 / 文字录入页 / 详情页 / 入口与导航（路由）反向依赖。

## 关键数据结构

- `CategoryEntity`（Room 表 `categories`）：id / name / sortOrder / createdAt——见数据层总览。
- `CategoryWithCount`：分类条投影（noteCount 排除 MERGED）。
- `NoteEntity.categoryId: Long?`（null=未分类）；`NoteSource.MERGED`。
- `HomeViewModel.filter: MutableStateFlow<Long?>`：null=全部、-1=未分类、>0=分类 id（哨兵 `FILTER_UNCATEGORIZED`）。
- `CategoryMerger.Result(mapJson, virtualRoot, noteCount)`：virtualRoot 恒 false（根恒为分类名，单篇分类也包一层保结构一致）。

## 已知坑与约束

1. **MERGED 笔记是分类的附属品**：删除分类会连带删它（用户已在删除确认框里被告知）；它不出现在分类成员数统计里；长按不给「归类到…」。但它会出现在「全部」与所属分类的列表里（有自己的来源徽标）。
2. **总导图是动态视图，不是快照**：打开现拼，笔记变化自动更新；因此它没有「编辑」入口（只读）——要编辑请用 AI 优化整合产出的 MERGED 笔记（或打开单篇笔记编辑）。
3. **AI 整合超预算降级会丢层级**：超窗口 55% 时逐篇砍到 2 层/1 层（保留主干），深层细节不会进入整合版——这是设计取舍（保「能整合」而非「全量塞入」）；拼接视图无此损失。
4. **渲染上限**：分类内 >50 篇时总导图页顶部提示建议用 AI 整合版（mind-elixir 单画布节点数过千会卡）；首版不做分页/虚拟化。
5. **分类色不存库**：按 id 取模 8 色，id 由自增主键决定，删除分类后新建的会复用旧色号——视觉上无害（同名不同 id 才是身份）。
6. **改归类不动 updatedAt**（`setCategory` 只改 categoryId）：设计如此——归类不算编辑内容，「全部」视图的最近编辑排序不跳动。
7. 单测覆盖：`CategoryMergeTest`（拼接分支/乱序防御/空分类/单篇结构/标题清洗/pruneDepth/buildInput 降级/mergeTitle）。**未覆盖**：CategoryMapScreen/ManageScreen 的 UI 层、AI 整合的端到端（需真实 LLM）、删分类事务（Room 依赖 instrumentation）。
