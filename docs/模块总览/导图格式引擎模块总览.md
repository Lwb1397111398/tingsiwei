# 导图格式引擎模块总览

## 模块职责

把「一行一个节点、TAB 缩进」的树文本与 mind-elixir 画布 JSON 双向互转，并在有多个顶层主题时自动包一层虚拟根（`TreeText.kt:23`）。

## 运作流程

**从哪来**

- LLM 输出：`LlmOutputParser` 解析出的 `mapText`（`LlmOutputParser.kt:15` 的 `Parsed.mapText`）→ `TreeText.parse`（`Generator.kt:56`、`Generator.kt:120`、`LongTextPipeline.kt:274`）。
- 用户粘贴的缩进树文本：`TextInputScreen.kt:126`。
- 画布回传 / 库里存的 mind-elixir JSON：`TreeText.fromMapData`（`Generator.kt:111` 把它还原成文本喂回 LLM；`Exporter.kt:29` 导出 Markdown；`DetailScreen.kt:412` 版本列表预览首行）。

**怎么处理**

1. `parse`：逐行扫描，取行首空白算 depth，用「(depth, node)」栈决定挂载位置（`TreeText.kt:31-47`）。TAB 优先：只要行首空白里有 TAB 就按 TAB 个数计层，否则按每 4 个空格算一层（`TreeText.kt:36-40`）；空行、剥 markdown 后为空的行直接跳过（`TreeText.kt:33`、`TreeText.kt:42`）。
2. `toMapData`：森林 → 单根 → 递归 `nodeToJson` 生成 `nodeData`，外层固定补 `direction:2`（SIDE）、空 `arrows`、空 `summaries`（`TreeText.kt:91-96`）。森林长度 > 1 时 `virtualRoot=true`，虚拟根的 topic 用笔记标题，标题空白时用 `"思维导图"`（`TreeText.kt:85-87`）。
3. `fromMapData`：只取 `nodeData` 递归还原（`TreeText.kt:101-107` → `nodeFromJson:133-139`），`virtualRoot=true` 时丢掉虚拟根、直接输出它的 children，从而还原成多顶层主题文本。
4. `serialize`：深度优先，一层一个 TAB，节点文字内部换行替换成空格并 trim（`TreeText.kt:68-76`）。

**产出什么**

- `List<TreeNote>`（森林）、mind-elixir 数据 JSON 字符串、`virtualRoot` 布尔（`TreeText.kt:83` 的 `Pair<String, Boolean>`）。
- JSON 串与 `virtualRoot` 一起写进 Room 的 `notes.mapJson` / `notes.virtualRoot`（`Generator.kt:70-79`、`TextInputScreen.kt:136-147`；字段定义 `Entities.kt:36-41`）。

**影响谁**

- 导图画布：JSON 经 `appInit` / `appSetData` 注入 WebView（`MindMapPanel.kt:55-56`），其中根节点 id 必须是 `me-root`（`TreeText.kt:126`），画布的「是否根节点」判定和「无选中时兜底加子节点」都依赖它（`index.html:73`、`index.html:165`）。
- LLM 提示词：本模块的格式约定与 `Prompts.generateSystem` 里给模型的格式说明必须一致（`Prompts.kt:14-30`）。
- 导出：Markdown 的「思维导图」小节由本模块的文本再转成 `-` 列表（`Exporter.kt:18-37`）。

## 关键数据结构

- `TreeNote`：`topic: String` + `children: MutableList<TreeNote>`（默认空，`TreeText.kt:16`）。森林 = `List<TreeNote>`，即「多顶层主题」的中间表示。
- mind-elixir 节点对象：`{ id, topic, children? }`，无子节点时不写 `children` 键（`TreeText.kt:125-131`）。
- 根节点 id 固定 `"me-root"`，其余 id 为 `"n${System.nanoTime()}-$idCounter"`（`TreeText.kt:120-123`）。
- 顶层数据：`{ nodeData, direction: JsonPrimitive(2), arrows: [], summaries: [] }`（`TreeText.kt:91-96`）；`2` 即 mind-elixir 的 `SIDE`（画布 opts 同为 `ME.SIDE`，`index.html:113`；bundle 常量 `z.SIDE=2`，`MindElixirFull.iife.js:16`）。注意画布 `init` 会用数据里的 `direction` 覆盖 opts（`MindElixirFull.iife.js:16`）。
- `toMapData` 返回值 `Pair<mapJson, virtualRoot>`，两个值必须成对存取：库里 `notes.mapJson` + `notes.virtualRoot`（`Entities.kt:36-41`）、`versions.mapJson` + `versions.virtualRoot`（`Entities.kt:61-63`），否则 `fromMapData` 会多/少一层。
- `Json { ignoreUnknownKeys = true; encodeDefaults = false }`（`TreeText.kt:25`）：`fromMapData` 因此能吞掉画布回传的 `theme/arrows/summaries/compact/meta` 等额外字段（这些字段由画布 `getData()` 带出，见 `MindElixirFull.iife.js:11` 的 `si`）。

## 已知坑与约束

**缩进与容错**

1. **空格缩进按「每 4 个一层」向下取整**（`TreeText.kt:39`）：LLM 若改用 2 空格或 3 空格缩进，全部算 depth 0，整棵树被压平成并列顶层主题，还会连锁触发虚拟根。只有纯 TAB 是安全的（`Prompts.kt:22-26` 也正是这么要求模型的）。
2. **混合缩进会丢层级**（`TreeText.kt:36-38`）：只要行首空白含 TAB，就只数 TAB、完全忽略同行的空格，`"    \tX"` 与 `"\tX"` 同级。
3. **层级跳跃不补中间层**（`TreeText.kt:44-46`）：`0 → 3` 的缩进会直接挂到上一个浅节点下，单测明确把这当作期望行为（`TreeTextTest.kt:46-47`）。
4. **首行带缩进、前置空白都不报错**：栈空即当顶层根（`TreeText.kt:44-45`），所以「少了一行总主题」这类脏输入是静默吞掉的，不会有任何提示。
5. `cleanTopic` 的 markdown 清洗有副作用（`TreeText.kt:52-65`）：`^#{1,6}\s*` 的 `\s*` 允许无空格，所以 `#热议话题` 会被剥成 `热议话题`（`TreeText.kt:55`）；行首 `*` 一律 `trimStart('*')`，`*注：……` 会掉星号（`TreeText.kt:63`）。反例安全的是 `-5度以下的低温`——列表符正则要求 `-` 后必须有空白（`TreeText.kt:54`，测试 `TreeTextTest.kt:95-99`）。
6. **`round trip` 不保真**：`serialize` 统一输出 TAB 并 `trim()` 节点文字、内部换行换成空格（`TreeText.kt:71`），所以空格缩进 / 带换行的节点文本一进一出必然变化，别拿它做「原样回写」。

**异常与容错边界**

7. `toMapData` 对空森林抛 `IllegalArgumentException("空导图")`（`TreeText.kt:84`），不是 `LlmException`。现有调用方都先自查 `parse(...).isEmpty()`（`Generator.kt:57`、`Generator.kt:121`、`TextInputScreen.kt:127`），所以这条基本不触发；新增调用方要自己兜。
8. `fromMapData` 对**坏 JSON 直接抛** `SerializationException`（`TreeText.kt:102`）。调用方待遇不一：`DetailScreen.kt:411-413` 用 `runCatching` 包住；`Generator.kt:111` 在 `try` 内（表现为「修改失败」，`Generator.kt:133-143`）；**`Exporter.kt:29` 没有任何保护**——库里的 `mapJson` 一旦被写坏，点「分享」会当场崩。
9. `fromMapData` 在缺少 `nodeData` 时返回空串（`TreeText.kt:103`），`mapJsonToTreeJson` 返回 `"{}"`（`TreeText.kt:112`），两者兜底值不一致。
10. 节点 `topic` 缺失时按 `""` 还原（`TreeText.kt:134`），`serialize` 会把空串连同行首 TAB 一起写出去（`TreeText.kt:70-72`），即输出里会出现「空白但有缩进」的行。

**并发与 ID**

11. `idCounter` 是 `object` 级可变全局状态且无同步（`TreeText.kt:118-123`）：跨线程同时 `toMapData` 理论上可撞 id（`nanoTime` 相同 + 计数相同），id 重复会让画布 `findEle` 命中错节点（`MindElixirFull.iife.js:11`）。现状下调用点都在单线程协程/主线程，属潜在风险。
12. 根 id 硬编码 `me-root`（`TreeText.kt:126`）：与画布 CSS/JS 强耦合（`index.html:73`、`index.html:165`、bundle 内 `me-root` 选择器），改这个字符串等于同时改三个模块。
13. 虚拟根只是浅包装：`forest.toMutableList()` 复用同一批 `TreeNote` 实例（`TreeText.kt:87`），改森林会连带改到已生成的 JSON 之前的源数据。

**单测覆盖情况（共 9 例，`TreeTextTest.kt:10-100`）**

- `parse` 单根缩进树（:12）、多个顶层主题（:23）、空格缩进+空行+markdown 列表符（:30）、剥标题符与加粗（:86）、`-5度` 不被误剥（:95）
- `toMapData` 单根不加虚拟根（:50）、多根包虚拟根且可逆（:59）、单根 round trip（:72）、`serialize` 节点内换行替换为空格（:80）
- **未覆盖**：混合缩进（坑 2）、层级跳跃、首行缩进、2 空格压平（坑 1）、空森林抛错（坑 7）、坏 JSON（坑 8）、`mapJsonToTreeJson`（无任何测试且无调用方）。
- 交叉核对：`TreeTextTest` 9 例与 `LlmOutputParserTest` 5 例**在同一文件** `TreeTextTest.kt`（第 10 行、第 102 行），按文件名去找会误判成缺失；索引 README 已在「构建说明」一节写明这一点（2026-09-20 补总览时定稿）。「98 例」总数与仓库实测一致（各文件 `@Test` 计数 27+17+9+13+18+14=98）。
