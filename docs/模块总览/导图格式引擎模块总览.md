# 导图格式引擎模块总览

## 模块职责

把「一行一个节点、TAB 缩进」的树文本与 mind-elixir 画布 JSON 双向互转，并在有多个顶层主题时自动包一层虚拟根（`TreeText.kt:23`）。这个 TAB 格式同时是 LLM 的输出格式、用户粘贴的输入格式、AI 改写的回传格式——一份格式贯通"AI 看得懂、用户也能手改"（`TreeText.kt:19-22` 注释）。（v1.5.0 起**不再是**「全工程唯一业务枢纽」：转写/生成/改写的执行编排已挪到 App 级 `pipeline/NoteProcessor`，见「笔记处理宿主模块总览.md」。）

## 运作流程

**从哪来**：四类输入共用这一套函数（调用点 grep 实证）——

1. **LLM 回包**（导图文本部分）：`Generator.generate` 拿到 `LlmOutputParser` 解析出的 `mapText` 后 `TreeText.parse` 判空/校验（`Generator.kt:55`、`211`、`214`、`295`、`298`；`LongTextPipeline.kt:365`、`371`、`390`），有结构才 `toMapData` 写库（`Generator.kt:69`、`132`）。
2. **用户粘贴**：文字录入页直接 `TreeText.parse` 粘贴内容（`ui/TextInputScreen.kt:126`），能出树就本地转导图、跳过 LLM 直达 `READY`（`:136` `toMapData`）。
3. **AI 改写**：库里 `mapJson` 先 `fromMapData` 反解回 TAB 文本再 `parse` 成活树（`Generator.kt:109`；`ReviseFlow.kt:83`、`103`），全量兜底提示词里放的是 `serialize(forest)`（`ReviseFlow.kt:95`）——**改写链路只在 TAB 文本上动刀，JSON 只在落库前最后一步才出现**。
4. **导出与版本预览**：`Exporter` 把库里 JSON 反解成 TAB 文本写进 Markdown（`export/Exporter.kt:29-30`）；详情页版本抽屉用 `fromMapData(...).lines().firstOrNull()` 做快照首行预览（`ui/DetailScreen.kt:424`）。

**怎么处理**（三个方向各自独立，没有共同中间件）：

- **文本 → 树**（`parse`，`TreeText.kt:28-49`）：逐行扫描，一个 `ArrayDeque` 栈保存 `(depth, node)`（`:31`）。缩进深度**TAB 优先**：该行含 TAB 就数 TAB，纯空格按每 4 个折一层（`:36-40`）；行内容先 `cleanTopic` 剥 markdown 记号（`:41`）——剥列表符 `- • · *`（须后跟空白，`:54`，「-5度」这类负号开头文字不受影响，用例 `TreeTextTest.kt:96-99` 锁住）、剥标题符 `#`（`:55`）、剥成对 `**粗体**`/`*斜体*`（`:57-61`）、开头未闭合星号也剥（`:62-63`）。空行与剥空行跳过（`:33`、`42`）。入栈前弹掉所有 `depth >= 当前` 的层（`:44`）：栈空即新根（多棵树 forest，`:45`），否则挂到栈顶节点的 children。
- **树 → 文本**（`serialize`，`TreeText.kt:68-76`）：递归先序，节点内部换行替换成空格（`:71`，防止一行被拆成两行破坏缩进）。
- **树 → 画布 JSON**（`toMapData`，`TreeText.kt:83-98`）：`forest.size > 1` 时包虚拟根，标题传笔记标题、空白兜底「思维导图」（`:85-87`）；产出 `{nodeData, direction:2, arrows:[], summaries:[]}`（`:91-96`，`direction:2` 即 mind-elixir 的 SIDE 右侧展开布局，与画布侧约定一致，见「导图画布模块总览.md」）；返回 `Pair(mapJson, virtualRoot)`——**是否包过虚拟根这个事实必须随 JSON 一起落库**（`notes.virtualRoot` 列），否则反解时不知道根节点该不该展开。
- **画布 JSON → 文本**（`fromMapData`，`TreeText.kt:101-107`）：读 `nodeData`，`virtualRoot=true` 时丢掉虚拟根、把 children 当 forest（`:105`），再 `serialize`。缺 `nodeData` 返回空串（`:103`），上层表现为 `parse` 出空树 → `Generator.kt:110` 报「当前导图数据异常，请先生成一次」。
- **节点 JSON 互转内部**（`nodeToJson`/`nodeFromJson`，`TreeText.kt:125-139`）：根节点 id 固定 `"me-root"`（`:126`，与画布 `index.html` 兜底选择器 `#map me-root me-tpc` 成对），非根 id 由 `newId()` 生成 `"n{System.nanoTime()}-{自增}"`（`:118-123`）——**每次 `toMapData` 全树 id 重发**，不沿用旧 id。

**产出什么**：`TreeNote` 活树（内存）、mind-elixir JSON（落库 `notes.mapJson` + `virtualRoot` 布尔列）、TAB 文本（提示词/导出/预览）。

**影响谁**：`Generator`/`LongTextPipeline`/`ReviseFlow`（生成与改写）、`Exporter`（导出）、`TextInputScreen`（粘贴直建）、`DetailScreen`（版本预览）、`MapDiffText`/`MapEditApplier`（改写的编号渲染与指令应用都按 `TreeNote` 树操作，见「生成流水线模块总览.md」）。

## 依赖的上游模块

- **`kotlinx.serialization`**（`:3-11`）：只用来构建/解析 mind-elixir JSON 的 `JsonObject`，无其他工程内依赖——`TreeText` 不认识 Room、网络、UI。
- 被依赖方的格式约定互锁：`Prompts.kt:14`（「一行一个节点，用 TAB 缩进表示层级」）与 `LlmOutputParser` 的标签约定共同保证进来的文本能被 `parse` 吃下。
- 与画布侧的约定：根节点 id `me-root`、`direction:2`——画布 `assets/mindmap/index.html` 按这两个约定渲染与兜底（见「导图画布模块总览.md」）。

## 已知坑与约束

1. **TAB 与空格混用的行按 TAB 计数、空格不算深度**：`indentStr.contains('\t')` 分支只数 TAB（`:36-37`），同行尾随空格不补层级。模型输出绝大多数纯 TAB，空格分支（每 4 个一层，`:38-39`）只在**完全没 TAB** 时生效——混排缩进会被拉平，这是容错不是 bug（用例只锁纯空格 `TreeTextTest.kt:32-49`）。
2. **`toMapData` 每次重发全树 id，不沿用旧 id**：库里旧 `mapJson` 的 id 与新写库的 id 无一相同（`:120-126` 每次现造）。现状安全的前提是**没有任何一方跨"生成"持久引用 id**——画布编辑在两次生成之间靠 `localJson` 连续（防回环见「导图画布模块总览.md」）；版本快照各存各的 JSON，`restoreVersion` 整行覆盖，不需要 id 对齐。若将来引入"改指定 id 的节点"类增量协议，必须先解决这条。
3. **`virtualRoot` 布尔必须与 `mapJson` 同生同灭**：反解 `fromMapData` 只认这个布尔决定展开与否（`:105`）；Room 迁移/手工改库丢了这个列，多根导图会连根带标题一起显示成单树。
4. **`cleanTopic` 的星号清理会吃掉合法以 `*` 开头的节点文字**（`:54`、`62-63`）：剥成对与开头未闭合星号是为容忍模型 markdown 化输出，代价是「*」号开头的合法内容（如数学乘号写法）被改写。列表符 `-` 须后跟空白才剥（`:54` 正则 `\s+`），负号文字安全（用例 `TreeTextTest.kt:96-99`）。
5. **空 forest 的下游行为不一致是上游把关的结果**：`toMapData` 对空树直接 `require` 抛错（`:84`），但生产路径上调用方都先 `parse` 判空拦截（`Generator.kt:56` 报「AI 返回的导图是空的」）——别绕过判空直喂 `toMapData`，那会抛 `IllegalArgumentException` 而不是友好文案。
6. **节点文字里的换行在 `serialize` 时被替换成空格**（`:71`）：单向有损。库里 JSON 里 `topic` 带 `\n` 时，反解再序列化不回同一字符串（round trip 用例锁的是无换行的标准树 `TreeTextTest.kt:73-79`）。
7. **`mapJsonToTreeJson` 是休眠接口**（`:110-114`，零调用点）：与「导图画布 PNG 导出链路休眠」（README 已知缺陷 #2）同类——留着没接线，删或接之前先看 README。
