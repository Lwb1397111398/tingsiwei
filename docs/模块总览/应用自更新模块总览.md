# 应用自更新模块总览

## 模块职责

让手机 App 自己发现并完成版本升级：检查 GitHub 私有仓库 `Lwb1397111398/tingsiwei` 的 `latest` Release → 版本比对 → 下载 APK → 唤起系统安装器覆盖安装；云端（GitHub Actions）在每次推 main 后自动构建签名包并发布，用户不再需要连电脑传 APK。

## 运作流程

**从哪来（云端出包）**：本地 `git push origin main` → GitHub 触发 `.github/workflows/build-release.yml`：①`actions/checkout@v4` 带 `fetch-depth: 0`（versionCode 依赖全量提交数，shallow clone 会数错）；②`setup-java@v4` 装 Temurin 17；③从 4 个 Actions Secrets（`TSW_KEYSTORE_B64`/`TSW_STORE_PASSWORD`/`TSW_KEY_ALIAS`/`TSW_KEY_PASSWORD`，2026-10-05 由本机 `tingsiwei-release.jks` + `keystore.properties` 写入，密钥不进 git）base64 还原出 `tingsiwei-release.jks` 与 `keystore.properties`；④`./gradlew assembleRelease --no-daemon`；⑤`git rev-list --count HEAD` 算出 versionCode（本次入库后首个 CI 包 = 提交总数 N），versionName 为 `1.5.N`；⑥把 `app/build/outputs/apk/release/app-release.apk` 复制为固定资产名 `Tingsiwei-latest.apk`，用 `gh release` 上传/覆盖到**固定 tag `latest`** 的 Release，并在发布说明第一行写入机器可读元数据注释 `<!-- tingsiwei-update versionCode=N versionName=1.5.N -->`（GitHub 页面渲染不可见），随后 5 条提交标题作为人读的更新内容。

**怎么处理（App 端检查）**：`UpdateViewModel`（`ui/UpdateViewModel.kt`，由 `AppNav` 顶层持有唯一实例，`AppNav.kt:23-24`）两条触发路径——启动静默检查（`autoCheckIfNeeded()`：`update_auto_check` 开 且 距 `update_last_checked_ms` ≥24h 才联网，失败保持安静）和设置页「检查更新」按钮（`checkNow()`，结果回显在状态行）。联网逻辑全在纯 JVM 的 `data/update/UpdateChecker.kt`：GET `https://api.github.com/repos/Lwb1397111398/tingsiwei/releases/latest`，必带 `User-Agent: tingsiwei-app`（GitHub 强制，缺了 403）。**仓库 2026-10-05 已转公开，匿名即可查询与下载（当次实测 `releases/latest` 匿名 200、资产匿名可下）**；令牌降级为可选项，仅用于突破匿名限流或仓库转回私有时兜底。解析发布说明第一行注释取 versionCode/versionName，assets 里第一个 `.apk` 的 `browser_download_url`+`size` 作下载地址；**远端 versionCode > `BuildConfig.VERSION_CODE` 才算有更新**，否则回「已是最新版本」。

**下载**：`UpdateChecker.downloadApk()`（`UpdateChecker.kt:80`）HttpURLConnection 流式 64KB 缓冲，先写 `cacheDir/updates/update-<versionCode>.apk.part`，收尾校验字节数与 Content-Length 一致后 rename 正式名（中断不留半截包冒充完整包）；目标文件已存在且长度==远端 size 时直接复用、零联网；进度按整数百分比回调进 `UpdateViewModel.progress` 驱动弹窗进度条。

**安装**：`data/update/UpdateInstaller.kt` 复用导出功能的 FileProvider（authority `com.tingsiwei.app.fileprovider`，`AndroidManifest.xml:45-53`；`file_paths.xml:5` 新开放缓存 `updates/` 子目录）把下载好的 APK 转成 `content://` URI，`ACTION_INSTALL_PACKAGE` + `FLAG_GRANT_READ_URI_PERMISSION` 唤起系统安装器；缺「安装未知应用」授权时先用 `ACTION_MANAGE_UNKNOWN_APP_SOURCES`+`package:` URI 跳系统开关页，用户开完回 App 再点一次「安装更新」。清单已声明 `REQUEST_INSTALL_PACKAGES`（`AndroidManifest.xml:10`）。

**闭环与版本纪律**：`versionCode = git rev-list --count HEAD`（`app/build.gradle.kts:5-10`），本机与 CI 对同一提交算同一个号、每推一次 +1；debug 构建也锁 `tingsiwei-release.jks`（`build.gradle.kts:59-60`，文件缺失时回落默认 debug 钥匙）→ 本机包与 CI 包签名指纹一致（证书 SHA-256 `90cc0728...c206`），覆盖安装不卸载、用户数据保留。

**产出什么**：手机上一条「检查→弹窗→下载→安装」的升级通道 + GitHub 上一个永远指向最新版的 `latest` Release。影响谁：入口与导航模块（弹窗挂载）、设置页（应用更新卡）、数据层（4 个新 DataStore 键）、构建脚本（版本号与签名规则）。

## 已知坑与约束

1. **公开仓库零配置（2026-10-05 转公开）**：匿名 `releases/latest` 已实测 200、资产匿名可下载；设置页令牌输入框保留为**可选**（限流或仓库转回私有时用）。匿名限流 60 次/时、带令牌 5000 次/时，静默检查 24h 节流（`AUTO_CHECK_INTERVAL_MS`）远够用；设置页手点不受节流限制。令牌明文存 DataStore（与 `llm_key` 同水位），仅本机可读。
2. **签名一致性是覆盖安装的前提**：本机 release/debug（有钥匙时）与 CI 都用 `tingsiwei-release.jks`；**若用户手机上装的是更早的默认 debug 签名包（v1.5.0 之前的本机构建），覆盖安装会因签名冲突失败，需先卸载重装一次**。钥匙丢失=永远无法给已装用户发可覆盖的更新包。**仓库已公开——jks 与口令绝不能进 git**（参照实现学伴把 debug 钥匙提交进了仓库，那是私有 debug 钥匙的做法，本项目的 release 钥匙不适用）：CI 仍从 Actions Secrets 还原（2026-10-05 翻公开前已做全历史扫描，无任何凭据痕迹）。本工作流仅 `push main` / 手动触发两种事件，不执行外部 PR，Secrets 不会被第三方构建读取。
3. **CI 三坑已修**（学伴项目实测踩过，此处照防）：`gradlew` 权限位 `git update-index --chmod=+x`（现为 100755）；`gradle.properties` 删掉了 `org.gradle.java.home` 机器路径（CI 判 invalid），本机与 CI 都走各自 `JAVA_HOME`；阿里云镜像海外 502——`settings.gradle.kts` 按 `System.getenv("CI")` 分流，且条件内联（pluginManagement 先于脚本体执行，引用文件级 val 会 Unresolved）。
4. **版本号语义变了**：versionCode 从手工（曾 6）改为提交数；同一提交在本机与 CI 构建号相同，**未推 main 的本地提交不算发布**，检查更新永远以 GitHub `latest` Release 为准。`fetch-depth: 0` 被删掉会导致 CI 数错版本——workflow 里两处 `git rev-list --count HEAD`（App 比对与 Release 元数据）必须同源于全量历史。
5. **GitHub 网络不稳**（本机实测）：`api.github.com` 通常可用，`github.com` 间歇性连不上；推送遇阻可用备用 IP 强制解析或 Contents API 单文件兜底（方法记录在 app-self-update 技能与学伴仓库 M7 总览）。
6. **下载文件在 cacheDir**：系统清理缓存会删掉已下载的 APK——无数据损失，重下即可（同版本完整文件不联网复用）；`.part` 半截文件不会被当成完整包（rename 前校验长度）。
7. **相同 versionCode 允许重装、更低被系统拒**：E2E 假发布时假服务器的 versionCode 要 ≥ 已装版本；`update_api_base` 指向宿主机假服务器时，模拟器地址是 `10.0.2.2`。
8. **弹窗与导航解耦**：`UpdateDialog` 挂在 `NavHost` 外层（`AppNav.kt:57`），因此任何页面（含录音页）都可能被更新弹窗打断；`downloading` 时「后台继续」可收起弹窗，但下载协程随 ViewModel 存活直到完成。
