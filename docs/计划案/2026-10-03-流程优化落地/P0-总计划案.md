## 1. 背景与目标

上一轮流程检查确认了四个流程漏洞（会话收尾无提交闸、混装提交自我复制、文档写了不入库、成本变化不申报），并给出三条规则提案，老板已批准。本计划把「流程优化」从提案变成三样可交付的东西：

1. **文档欠账清偿**：14 份过期模块总览对照当前代码（v1.5.0，commit `024692a`）补记，并补建 1 份此前漏建的总览（`pipeline/NoteProcessor.kt` 笔记处理宿主）。
2. **规则固化**：三条提案 + 老板本次指定的「计划-评分-验证」工作流，共 4 条写入 Agent Manager vault（唯一数据源 `C:\Agent\AImanager\vault\`）。
3. **闸门工具化**：把「完成前三查」做成一键脚本 `check_session_close.py`，从"靠自觉"变成"跑工具"。

**明确不做**：不改任何应用功能代码（`app/src/` 零改动）；不动 `.zcode`、`.agents` 下的配置产物（只改 vault，渲染同步由 Agent Manager 负责）；不重构任何既有工具（**含 check_modules.py**）——如执行中发现确需改动既有工具，单独提案说明理由，且必须保证体检口径不变。

## 3. 评分协议（所有计划案与产出通用）

- **独立评审**：评分由未参与起草的 AI 子代理执行（主会话起草、子代理评分，避免自己给自己打分）。
- **权重表**：
  - 计划案：目标范围清晰 20（含"不做什么"）/ 拆分合理与顺序有据 15 / 每个小计划有交付物与验收标准 20 / 评分质检协议可执行 20 / 验证矩阵覆盖老板要求（小功能验证、跨板块回归、总验收、推送条件）20 / 风险与资源 5。
  - 文档产出：准确性 40（可验证陈述与代码一致，评审随机抽 ≥3 处 file:line 或符号引用核对）/ 完整性 25（8 字段齐全、运作流程按真实数据流落到实体、覆盖 v1.2–v1.5 改动）/ 解释风格 15（无「某种/相关/一些/适当/等等」占位，小白能懂）/ 结构一致 10（8 字段格式与其他总览一致、README 索引行相符）/ 更新记录 10（最后更新=今日+改动摘要）。
  - 工具产出：正确性 40（正例反例测试全过）/ 健壮性 20（异常输入不崩、退出码语义清晰）/ 可用性 15（人话输出、--help）/ 与既有工具协同 15（check_modules 复用而非重写）/ 代码风格 10。
  - 规则段落（vault）：与 vault 既有条文不冲突 30 / 落点文件位置恰当 20 / 表述可执行无歧义 30 / 四条规则之间无重复 20。
- **通过线**：≥90 分且无「准确性类」未修复问题——该附加条件**仅适用于文档产出**；计划案、工具、规则段落按各自权重表以 ≥90 且无 P1 问题为通过线（P1＝事实错误、引用不存在的文件/机制、或导致无法按计划执行的问题）。低于 90：评审必须给出逐条建议，起草方按建议修改后重评，循环直至 ≥90。
- **收敛保护**：每轮修改必须逐条回应评审意见；同一产出 5 轮仍 <90 时停下向老板如实汇报卡点，不得降低标准放水。

## 5. 执行策略

- P-A1/A2/A3 由 3 个并行子代理起草（各自只写分配到的文档），主会话逐条落实评审意见或回传给原起草代理修改；P-B 由主会话亲自改（涉及老板提示词源，不用子代理）。
- 文档写法约束：行号只标"本次核对过的"位置，优先用「符号名+文件」定位，降低漂移；复核后确认代码未变、内容仍准确的，在「最后更新」如实写"2026-10-03 复核无误"而非虚构改动。
- 计划案与本验证矩阵存档于 `docs/计划案/2026-10-03-流程优化落地/`，随仓库提交，过程可审计。

## 6. 风险与对策

1. **行号漂移**（WIP 刚入库，行号是新写的，但后续改动会漂）→ 定位以符号为主；评审抽查。
2. **评分循环不收敛** → 每轮逐条回应；5 轮上限后升级汇报。
3. **vault 同步机制不明** → 只改 vault；若发现需要手动触发的同步入口（engine/或控制台），如实报告，不代改配置产物。
4. **体检工具误报**（check_modules 按 mtime 判过期，可能存在内容其实准确的模块）→ 不改 mtime 作弊；逐份复核后如确认无误，在更新记录里写明"复核无误"，让 mtime 与内容一致。
5. **资源盘点**：起草子代理 3 个（P-A1/A2/A3 各一，并行）；评分官复用同一评审会话续评以保持标准一致。预计每产出 1–2 轮评分可达标，单轮评审预估约 6 分钟（依据上一轮评审实际耗时的观察，未逐轮记录）；任一产出超 3 轮未达标即收紧（缩小该文档范围、拆分重评），5 轮上限触发 §3 收敛保护升级汇报。
