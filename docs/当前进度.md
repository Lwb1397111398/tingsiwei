## 2026-10-24 · 在线朗读通用化改造（修「出不来语音」）——当前卡点：老板的中转站没有语音模型

**目标**：老板反馈「联网在线朗读设置还是有问题，出不来语音」，要求：①先跑通；②填 URL+KEY 后可点「检索模型」搜可用语音模型，不局限于某一种。

**根因（已查明）**：旧代码把 TTS 模型写死为硅基流动专用（`FunAudioLLM/CosyVoice2-0.5B` + 音色强制 `模型:音色` 前缀）。老板实际填的是 OpenAI 兼容中转站（csid.cc）——App 内实测该渠道 26 个模型**全是聊天/生图/视频类，一个语音模型都没有**，请求必被拒后静默回落系统语音。

- 改动：`tts/CloudTts.kt` 重写（模型走配置；`buildVoice` 音色请求期拼装，兼容短名/旧前缀/OpenAI 式；**两级格式回退**：流式 PCM 被 400/404/415/422 拒或返回文本时自动改发极简 WAV 请求，`tts/CloudTtsAudio.kt`（新文件）解析 RIFF+线性重采样回 24k；200 但返回 JSON/HTML 不再当音频喂喇叭；`fetchModels`/`filterTtsModels`/`voicePresetsFor`；tag `CloudTts` 排查日志）；`TtsPlayer.speak` 加 `fallback` 参数（设置页试听失败只报原因不静默回落）；`SettingsRepository` 增 `tts_cloud_model` 键（四件套）；`SettingsScreen` 朗读卡重构（模型框+「检索模型」+点选 chips+音色按模型自适应预置+「已填 Key 但引擎没切过来」提醒）；`DetailScreen` 传 model。
- 修了一个真 bug：`fetchTtsModels` 在主线程发网络请求（`NetworkOnMainThreadException`），已 `withContext(Dispatchers.IO)`。
- 模块总览已同步：TTS朗读/设置页/数据层。

**已验证**：`testDebugUnitTest` 197 例全过（CloudTtsTest 扩到 21 例）、`assembleDebug` 成功。**模拟器全链路实测**：①模拟 OpenAI 兼容服务（10.0.2.2）上流式 PCM 边下边播成功（48000 字节）；②渠道拒收流式参数时自动 WAV 回退成功（44100Hz→24k 重采样数值正确）；③「检索模型」在真实中转站 csid.cc 上拉到 26 个模型并正确筛选/列全部；④模型↔音色预置联动正确；⑤对无 TTS 渠道试听会弹准确错误（HTTP 404）而非无声。**真机听感 UNMEASURED，待老板验收。**

**老板需要知道的关键结论**：现在的中转站（csid.cc）做不了在线朗读（没有语音模型）。要用在线朗读，两条路：①设置页把「语音服务地址」改回默认硅基流动（`api.siliconflow.cn/v1`），去 siliconflow.cn 免费注册领 Key 填入，点「检索模型」选 CosyVoice2 即可；②找一个有 TTS 模型的中转站，同样填好点「检索模型」点选可用模型。模型和音色都已不锁定某一家。

## 2026-10-24 · 离线朗读句间隔优化（5 秒缓冲领先量）

**目标**：老板反馈离线 kokoro 朗读两句之间空档长，提出「播前一句时预合成后面几句」。方案评估：逐句循环本就背靠背合成、不等上一句播完，卡脖子是播放缓冲只有约 0.34 秒把领先量压死——放大缓冲即等价实现预取，无需重构成预取队列（native 引擎单例也不能并行合成）。

- 改动：`TtsPlayer.kt` 离线路径 AudioTrack 缓冲 `maxOf(minBuf*4, 16384)` → `maxOf(minBuf*4, sampleRate*2*5)`（约 240KB），加注释；循环注释同步改（调速最多延后约 5 秒生效）。
- 模块总览已同步：TTS朗读（运作流程 speakLocal 段、坑 2 重写、入口行数、最后更新）。

**已验证**：`testDebugUnitTest` 184 例全过、`assembleDebug` 成功。**句间听感改善 UNMEASURED**——待老板真机用「离线朗读」读多句笔记试听。

**未完成/下一步（如需继续）**：
1. 真机试听：若句间仍有空档或句中开始断，说明设备合成慢于实时，按序尝试 `SherpaTts` 的 `numThreads` 2→4 → 实验调 `maxNumSentences` → 建议改用在线引擎。
2. 全文第一句的冷启动延迟（首趟推理）无预取可救，属模型固有。
